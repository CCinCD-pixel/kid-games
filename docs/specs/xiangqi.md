## 0. 一屏速览
- **是什么**：标准中国象棋的完整产品。孩子是星港"棋院"的见习棋手**小步步**：**棋盒**里先玩一分钟（无字）→ 在**学堂**学（9 章 33 课，会的先用**摸底**跳过）→ 在**对弈**里先下**小局**（从精选残局出发，2–4 分钟）、再下整盘，挑战 6 位"机关人"（滑轮、木牛、流马、司南、浑天、璇玑）→ **星图**里做杀棋题 → 周末把 iPad 平放**和爸爸面对面下一盘**（可设家规）。
- **一次会话 12–15 分钟**：1 节课（每段 ≤4.4 分钟）或 1 个小局（2–4 分钟）+ 3 道杀棋题 → 收尾卡；整盘棋按机关人 5–25 分钟，随时存。每个环节结束回大厅，不自动开始下一项。
- **v1 = 4–6 周内容**：33 课 / 3 个小战场 / 一步杀 40 + 困毙 8 + 双捉 6 + 两步杀 24（全部独立穷举复核）/ 每日池 8 141 题 / **28 个小局** / 6 位校准过的机器人 + 轻松档 + 让子 / 教练防漏着 / 面对面 + 家规 / 复盘 / 281 句旁白。课程 + 题 ≈ 3 小时新内容，天梯整盘 ≈ 3–5 小时对局；每周 3 次 ≈ 8–12 周不重复。
- **手感**：点或拖都能走（手机有触点预览）；棋子是"车削木玩具"；将军有朱砂印章；动画期间输入锁死。
- **引擎**：共享 `engines/board`（`board-engine.md`），由独立任务「engines/board build」先做，本作与棋手学院（`/chess/`）随后各做自己的 `games/<id>/**`。

## 1. 定位、立意、目标能力、课标锚点、证据等级
**定位与玩家幻想**：爸爸家有一副实体象棋，孩子常和他下；这一作把"那副棋"搬进星港。孩子是棋院里最年轻的见习棋手，小军师（领航员）陪他认棋、摆阵、破杀；院里住着六位老式"机关人"（木牛流马、司南、浑天仪……），他一个个挑战过去，每赢一位，棋院墙上的机关模型多一个零件。不幼稚：真的规则与术语，步子比市面入门课更小更清楚。
**立意（给爸爸看）**：① 一副真的棋、一家人的棋（面对面、让子、家规、悔棋需对方同意、自动存档、"摆到真棋盘"）；② 走前先看一眼（教练逐级放手、L24 专课、复盘）；③ 赢要赢得明白（机器人从不嘲讽；输了先看自己的好棋；无生命/计时/Game Over）；④ 一点文化不灌输（木牛流马、司南、浑天仪是孩子可追问爸爸的词）。
**能力目标（家长页）**：规则与走法 → ①；子力算账（40 以内加减）→ ①；走前检查（"刹车"）→ ②；模式识别（杀型、双捉）→ ③；多步规划 → ①。**家长页只显示 3 项**：① 课程进度；② 对弈（赢过的最高机关人、近 10 盘胜 / 和 / 负、教练提醒后改走比例、小局进度）；③ 一步杀首次做对率（近 30 题）。
**课标锚点**：象棋不在课标内；可挂数学一上「位置」、一下「100 以内加减」（子力算账）、推理意识；棋子字多为常见字，点读词可点。
**证据等级（如实写进家长页）**：总体 **C**（棋类训练的迁移效应缺主动对照，Sala & Gobet 2016/2017）；"教学型残局比整盘更适合 6 岁"为**设计判断（无引文）**；步子顺序与机器人 / 让子阶梯：D（设计判断，用模拟量化）。家长页写"好玩、有文化价值、适合亲子"，不写"益智"。**教练准确率**由与评估器同族的搜索复核（99.1 / 97.5 / 96.5 / 93.2 / 93.7 %）+ 评审用深度 4 复核（90–94 %）支撑；发布前爸爸手标 40 个局面核对一次（§9.3）。

### 2.4 面对面（和爸爸下）与家规
- iPad 平放，两人隔桌对坐。**黑方棋子字形旋转 180°**（只转棋子自己，字形层单独烘焙，光源保持左上，不是整张位图倒转）；**f2f 永不翻转棋盘**。两套控制簇各靠近自己：红簇在底部 dock / 右面板下半，黑簇**整体旋转 180°**在页眉（🏠 右侧，竖屏）/ 面板上半（横屏）；轮到谁，该侧外框亮金边 + 簇上亮灯，不用倒计时。

## 3. 核心循环与规则（引擎 `engines/board/games/xiangqi/rules.ts`，原型 `rules.mjs`）

### 3.1 会话循环
Hall →（小局 / 整盘 / 一课）→ 收尾卡（星、"今天学了什么"、"讲给爸爸听"一句；按钮：下一项 / 回大厅 / 再来一次）。对局中随时"存 / 退出"，下次"接着下"（恢复时若轮到机器人，**自动发起思考**）。**无硬时长、无锁**；连续玩 30 分钟后小军师只轻轻说一次 `s.stop`。

### 3.2 棋盘与坐标
9 列 × 10 行交叉点，红在下，红先；"楚河汉界"在行 4 与行 5 之间。`sq = r*9 + c`（r 自上 0..9）；坐标 `a1…i10`（红帅 e1，黑将 e10）；竖线号红方用一至九、黑方 1–9。开局 FEN `rnbakabnr/9/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/9/RNBAKABNR w`（大写红）。**执黑对机器人时视图旋转 180°**（自己的子在下，河字与字形保持正向，竖线号重编）。

### 3.3 走法与限制（每条限制都有教学、动画与"为什么"提示 `xq.w.<reason>`，reason 集合 = `rules.whyIllegal` 的返回集）
| 棋子 | 走法 | 限制（点到时的 reason） |
|---|---|---|
| 帅/将 | 横竖一格 | 不出九宫（`palace`）；**不能与对方将帅同线中间无子——「见面」**（`face`）；不能走进被攻击的点（`self`：「走这里，帅会被将军」） |
| 仕/士 | 斜走一格 | 只在九宫 5 点（`palace`） |
| 相/象 | 走"田" | **象眼**被塞不能走（`eye`）；不能过河（`river`） |
| 马 | 走"日" | **马腿**（先直走的那一格）有子不能走（`horse`：「马腿被别住了」） |
| 车 | 横竖直走 | 不能越子（`block`） |
| 炮 | 不吃子同车 | 吃子要隔恰好一个子（`screen` / `two`） |
| 兵/卒 | 向前一格；过河后可左右一格 | 不后退（`back`）、没过河不能横走（`side`）；其余几何错 = `shape`；自己的子 `own`；非己方回合 `turn`；被将军没解 `escape` |
自陷（走完己方帅被将军 / 见面）直接从合法着法中剔除；没有"吃王"，将死即终局。`whyIllegal` 与合法性互为充要（4 757 万个 (from,to) 判定 0 不一致，15 个 reason 都出现过）。
**反馈语言（图标，不只靠语音）**：腿 = 脚印图标出现在被堵的那一格、眼 = 眼睛图标在"田"字中心、炮架 = 「山」图标压在架子上（对应课名"隔山打牛"）、见面 = 两将之间一条金色**见面线**（被挡则变暗，试图打开则朱砂闪烁 + bump）。被点到非法点时显示 400 ms（课 L07 / L09 / L11 / L14 里选中棋子时淡显）。

### 3.4 将军、应将、将死、困毙
将军 = 走完对方帅 / 将被攻击（含见面）；**应将三法**：走开、挡住（炮可垫在炮与帅之间或拿走炮架；马用堵马腿）、吃掉。将死 = 将军且无合法着法。**困毙 = 没被将军但无合法着法 → 被困方负**（引擎状态 `stalemate-loss`；家规可改和；画面 = 九宫浮出琥珀锁；L20 专课且有国际象棋对照卡）。

### 3.5 重复、长将、限着、认输与裁定
`Game.status()` 顺序（`board-engine §3`）：局面终局（将死 / 困毙 / 无进攻子力）→ 三次重复 → 限着。
| 情形 | v1 判定 |
|---|---|
| **三次重复** | 同一局面（棋子位置 + 走子方）第 3 次出现 → 看窗口判长将或和棋；起始局面（含让子）参与计数 |
| **长将判负** | **窗口** = 当前局面最近 3 次出现中最早一次起的全部着法；窗口内**某一方每一步都将军、另一方不是** → 将军方负；双方都每步将军（互相长将，实测一例）或都不是，或窗口里插了一步安静着 → 和。循环前的引入步不在窗口内；与"第三次出现落在谁走"无关。长捉 / 一将一捉 v1 一律和（家长页写明） |
| **预警** | 当前局面第 2 次出现且走子方在窗口内每步将军 → `g.perp.warn`（不禁止，允许悔棋）；**提交前提醒**：这步会被判长将负时弹 [换个走法 / 就这样走]（`Game.wouldEndBadly`）。机器人在候选集里**排除**这类着法（不会主动走成自己长将判负） |
| **自然限着** | 连续 120 步（60 回合）无吃子 → 和（兵动不重置；家规可改不限） |
| **无进攻子力** | 双方都没有车 / 马 / 炮 / 兵 → 和 |
| **机器人认输** | R1：总步数 ≥36 且子力落后 ≥12 分（孩子口径，车 9 炮马 4 仕相 2 兵 1 / 2）；R2：≥40 且 ≥15；R3：≥50 且 ≥20；R4+ 不认输；己方被将军时不认输。认输 = 孩子的**胜**（机器人躬身 + `g.resign.win`，进结果卡，计解锁） |
| **疲惫裁定** | 对 R1–R3，限着即将和棋（119 步）而孩子子力领先 ≥9 → 判孩子胜（「它累了，这盘算你赢」`g.tired`）；对 R4+ 和棋就是和棋（`g.draw.ok`「和棋，没输，再来一盘」，并邀请去玩小局） |
**测试**：`rule-vectors.mjs` 15 条向量（真实互相长将、引入步、窗口内安静着、第三次落在将军方走、让子起始局面、悔棋跨越判决、家规）+ hash 增量 = 重算（4.7 万局面 0 碰撞）+ 2 万序列长将模糊（295 局到第 3 次，与暴力参考 0 不一致）；原 43 条规则向量保留。

### 3.6 输入与落子
点—点与拖两种；规则与参数见 `board-engine §5`（4 级规则、锁、看门狗、触点预览）。松手在非法点 → 棋子飞回 + `xq.w.*`（同原因 30 秒内不重复）。被将军时不能应将的子不亮点（点它说 `escape`）。**机器人思考或动画期间输入锁**：点击忽略、不排队（专测）。悔棋：对机器人 = 撤回孩子最近一步与机器人回应，思考中则取消（`epoch++`）；终局后也可悔；悔过的胜局不给"不悔棋"徽章。**机器人走完后**：点"上一步"标记 = 重放它的走法（160 ms 幽灵）并脉动一次它新造成的威胁（被攻击的子）；R2–R4 可在赛前开「危险点提示」（复用课里的琥珀斜纹）。

### 3.7 课程步骤规则
步型（`k`）：`tap` `stars`（par = BFS 最少着数）`capture` `quiz`（点选 / 是否 / 赚平亏 / 安全 / 将死还能逃）`setup` `escape` `make`（**走一步，将军 / 将死**：引擎算接受集）`trade`（**吃一个看赚亏**：孩子执行吃子，被保护则幽灵回吃，分数筹码 +4 / −9 飞进托盘）`sweep`（**小眼睛**：按下琥珀斜纹铺 1 秒，再把子走到星星，落点被攻击则幽灵吃掉并悔回）`demo`（幽灵手）`card`（对照卡）`bank` / `bank2`（题组，≤6 题一段，每题存检查点）`battle` `play`。走错：不出现"错"字、不扣星；没用的着 → 再看一眼，连续 2 / 3 次 H1 / H2；quiz 答偏 → 幽灵手演示 + 孪生题。**星级**：`stars/capture/sweep` 着数 = par 且无 H3 → ★★★，≤par+2 → ★★；`quiz` **首次对且孪生也对** → ★★★，用 H1 → ★★；课星 = 步星平均向上取整；连续 2 道首试没对，下一道降一档。

### 3.8 小战场（B1–B3，课末可选步）
红方有若干子，黑卒 3–4 个从底部出发，**每回合红走一步后黑卒全部前进一步**；卒到红底线红败；吃光红胜。精确求解：B1 车炮 par 6（可走 7 步，余量 1）、B2 马象 6（7，1）、B3 兵马炮 **6（8，2；卒改从第 9 横线出发）**；开局随机一步仍能赢 100 / 75 / 100 %。星：par → ★★★，par+1 → ★★，赢 → ★；validator：余量 ≥1。败了演示卒冲到底，重来；连败 2 盘少 1 个卒。

### 3.9 让子（`handicapFen(kind, giver)`）
平下 · 让先（不去子，受让者执红先走）· 让左马（让子方自己左手边的马：红 b1，黑 h10）· 让双马 · 让一车（红 a1，黑 i10）· 让一炮（仅面对面）。让子方永远是机器人（对弈）或爸爸（面对面）。效果见 §4.3。

### 3.10 边界情况（必须实现并测试）
存档重放遇非法着法 → 截断并提示；思考时切后台 → `visibilitychange` 重置预算起点、回前台再落子；动画期间连点只处理第一次；旋转设备 → `finishAnimations()` 后重排，选中保留；终局后点棋盘无反应；面对面请求未答复前冻结棋盘（可撤回）；Worker 创建失败 → 主线程小搜索（≤R3）；课程中途退出 → 从该步 id 重来（题组从该题续）。

### 3.11 小局（默认的"快棋"；修复"一盘 15–25 分钟"）
**是什么**：从精选残局 / 中局出发，孩子执红先走，机器人执黑守，**将死或困毙（黑无路可走）即胜**。28 个局面（`xiaoju.v1.json`，生成器 + 模拟筛选 + 设计师目检）8 个主题：单车擒将 3 · 双车围宫 3 · 车炮联攻 4 · 马炮联攻 3 · 车兵取胜 4 · 双炮破防 3 · 多子取胜 4 · 见面杀势 4；3 档（★ 5 / ★★ 18 / ★★★ 4，按 k15 对 R3 的严格胜率 ≥85 / 65–85 / <65 分）。无让子、悔棋无限、教练默认关（可开）。
**数字（hold-out，新种子；28 局面 × 40 盘 / 格；resign 关）**：孩子模型 k2 对 R1…R6 **严格胜 95 / 87 / 86 / 85 / 80 / 79 %**，步数中位 13–17、p90 41–99；真新手 k15 严格胜 89 / 75 / 75 / 72 / 65 / 66 %，中位 17–24；和棋率（含未结束）k2 5–20 %、k15 11–34 %。逐局面门槛：k2 对 R3 严格胜 ≥60 %（实测最低 72）、k15 对 R3 ≥30 %（最低 35）、胜局步数中位 ≤50（最大 47）、开局无一步杀。
**软上限**：60 步（30 个孩子着）未分胜负 → 卡片「这个小局走了很久」[再试一次 / 换个小局 / 继续]，**不判和、不计输赢**。**奖励与解锁**：胜 = 该局 ★；无悔 ★★；无悔且 ≤20 步 ★★★；**R_{k+1} 解锁 = 整盘胜 R_k 一盘，或 3 个不同小局胜 R_k**（两者都计入战绩 w）。Hall 的快捷条默认 **「来个小局」**，整盘在对弈门里。
**验证 V9**：以上逐局面门槛 + 总体 k2 严格胜 ≥75 %；报告写 Wilson 区间；`XQ_FULL` 工具。

### 4.2 题库（引擎生成 + 独立库**穷举**复核；原型 `puzzles.mjs` `select.mjs` `gen-extra.mjs` `pool.mjs` `lazy.mjs`）

## 5. 提示、教练、失败处理、复盘、星与收藏（无黑暗模式）

### 5.1 提示阶梯（H0–H3；`core/hints.ts`；灯泡键位置固定：竖屏 dock 左起第二个，横屏键组第二个）
H0（≥30 秒无触摸，计算 / 拖动中不计）灯泡呼吸；H1 方向（点灯泡 1 次：最近星闪光 / 无关项变暗 / 主题一句 `xq.h.1.*` / 对局里按最佳着类型说一句）；H2 部分示范（箭头 / 去掉一个干扰项 / 起点脉动；`trade` 里把亏的吃子变暗；`sweep` 里让斜纹常亮）；H3 完整示范（幽灵手走完整路线，复位后做**镜像孪生**；对局里只给一步箭头）。提示永远不卡进度；用过 H2/H3 的题不计首次做对率；对局里提示无限、免费。

### 5.2 教练防漏着（`core/coach.ts`，原型 `coach.mjs` `coach-sim.mjs`）
只在两种情形提醒（设孩子拟走 m）：① **`hang`**：走完后对方能静态净赢 ≥2 分且比最安全着法多亏 ≥2；② **`allowMate`**：走完后对方有一步杀**或一步困毙判负**（v1.1 修正：评审测得孩子被困毙判负占 7–13 % 而教练从不提醒），且存在不会被一步杀的着法。每盘上限按机关人（§4.3），用完静默；被提醒着法 <10 %。**界面**：目标点虚线圈 + 箭头"哪个黑子会吃哪个子"（`CoachRow.victim/attacker`），气泡按 `movedIsVictim` 分两句（`c.hang`「这个子会被吃」/ `c.hang2`「那个子还在被攻击」/ `c.stale`「你会没路可走」）；[再想想]（棋子飞回）[就这样走]。**判定表在轮到孩子时（机器人动画开始时）由 Worker 对所有合法着法预算**，松手查表，没算好就不提醒。
**实测（k2 对 R2–R6，每级 100 盘）**：被判"该提醒"占比 6.7 / 6.4 / 5.3 / 5.7 / 5.4 %；hang : allowMate ≈ 16 : 1（allowMate 8 / 10 / 10 / 22 / 23 次，含困毙）；准确率（深度 2 复核，确实亏 ≥150 厘兵）99.1 / 97.5 / 96.5 / 93.2 / 93.7 %；漏报抽样 8–10 %（更深战术，留给复盘与课程）；判定表 p95 3.5 ms。**教练不替孩子下棋。** 评审提的"过河兵计 1.5 分"**不采纳**：过河兵确实值 2 分，上限与 <10 % 占比已控制打扰。
**对话预算（防唠叨）**：`g.your`「轮到你了」只在第一次与闲置 >20 秒后说；`g.think` 永不出声（只有伙伴 `thinking` 与点点）；机器人走子无旁白；每 6 步最多一句伙伴话；**默默的成功**：孩子吃到安全的白棋、或"再想想"后改走时，播一次 `f.ok3`（≤2 次 / 盘）。

### 5.3 失败处理与复盘
无生命、倒计时、Game Over；一键悔棋 / 重来。输：小军师先说**自己的好棋**再给一个可改进处；机器人从不庆祝 / 嘲讽，不放胜利音。**复盘"精彩时刻"**（Worker，≤1.5 s）：`mate` 80（正）· `fork` 70 · `win` 50 · `missMate` 70（负）· `hang` 55 · `missFree` 45，选取 最高正面 → 最高负面 → 第二正面，≤3 条（每盘平均 2.8–2.9 条，检测 ≤0.15 ms）；播放器：棋谱条、0.8 s / 步回放、"炮二平五"、"从这里重新下"。**星与收藏**：课星 ★1–3；章满星 → 棋院印；赢一位 → 头像进陈列架 + 机关模型加零件；**禁用**：连胜 / 每日签到 / 倒计时 / 稀有度 / 商店 / 广告；"错 / 笨 / 失败"字样（术语「双车错」白名单）；红色当"错误色"。

### 8.4 存档（**版本冲突已解决**：kit `createStore<XqSave>('xiangqi', { version: 2, defaults, migrate })` → `kg:v1:xiangqi`，<40 KB）
**事实**：已合入 main 的旧版（33c149c）就是 `createStore('xiangqi', { version: 1 })`，信封 `{v:1, data:{ mode, level, human, initialFen, moves, flipped, autoRotate, puzzleId?, solved }}`。新 store 若也用 `version: 1`，kit 看到 `env.v === opts.version` 会**原样返回旧数据且永不调用 migrate**，新代码一读 `save.lessons[...]` 就抛错——所以用 **`version: 2`**。
```ts
interface XqSave {
  version: 2; notice: 'none' | 'legacy' | 'seen';                       // 一次性卡「旧棋局放不进来了，已留好备份」
  intro: { box: boolean; river: boolean; palace: boolean };
  placement: { done: boolean; known: Record<string, boolean> };         // 章号 → 已会
  lessons: Record<string, { stars: 0|1|2|3; stepId: string; puzzleIx?: number; done: boolean; known?: boolean }>;
  battles: Record<'B1'|'B2'|'B3', { won: boolean; stars: number }>;
  robots: Record<string, { unlocked: boolean; w: number; d: number; l: number; xjWon: string[]; badges: ('r'|'b'|'clean')[]; loseStreak: number; helpTier: 0|1|2|3|4; easy: boolean; wall: number }>;
  xj: Record<string, { wins: number; best: 0|1|2|3 }>;
  puzzles: { done: string[]; firstTry: string[]; daily: { date: string; ids: string[]; got: number }; recent30: boolean[]; tier: 1|2|3 };   // done / firstTry FIFO ≤800
  game?: { mode: 'robot'|'f2f'|'xj'; robot?: string; xjId?: string; startFen: string; moves: string[]; side: 0|1; handicap: string; seed: number; coach: boolean; easy: boolean; rules: HouseRules; undo: number; hints: number; coachShown: number; coachAccepted: number; startedAt: number };
  history: { t: number; robot: string; mode: 'full'|'xj'; result: 'w'|'d'|'l'; plies: number; undo: number; coachShown: number; coachAccepted: number }[];   // 环形 ≤30（家长页"近 10 盘"）
  settings: { coords: boolean; coachOn: Record<string, boolean>; handedness: 'right'|'left'; houseRules: HouseRules; dangerHatch: boolean };
  stats: { sessions: number; f2fGames: number; legacySolved: number }; newContent: string[];
}
type HouseRules = { stalemate: 'loss'|'draw'; perpetual: 'loss'|'warn'|'off'; limit: 120|0; undo: 'free'|3 };
```
`migrate(old, from)`（kit 只调一次，须直接返回当前形状）：`from === 1` → 在 migrate 里**自己**把旧信封原文写进 `kg:v1:legacy-xiangqi`（`try/catch`，已存在不覆盖；**kit 的 `LEGACY_KEYS` 里没有 xiangqi，不会替我们留快照**）→ 返回 `defaults()`，其中 `stats.legacySolved = old.solved?.length ?? 0`，若旧存档有走过的着法则 `notice='legacy'`；其它版本 / 异常 → `defaults()`。**决定：旧版在局存档丢弃（带说明卡 + 备份），不转换**——旧版用另一套库与规则（困毙 / 长将未必同判），旧残局编号对不上新题库，且旧版已被爸爸否决。`load` 后再过 `isValidXqSave` 形状校验，不合格 → `defaults()`；`env.v > 2`（旧缓存页）由 kit 保持原样并用默认值。恢复：`game.moves` 从 `startFen` 逐着重放并校验，遇非法着法截断；**轮到机器人时自动发起思考**；课进度存 `stepId`；`setHubProgress`「已学 12/33 课 · 小局 5/28」与 `newContent`（NEW 标记）。导入导出走 kit 家长页 `exportProgress`（`kg:` 前缀含 legacy 快照）。
**测试**：vitest 用**真实旧信封**（照旧版 `defaultSave()` 造一份：`mode:'local', level:'learner', human:'w', initialFen:'rnbakabnr/…/RNBAKABNR w - - 0 1', moves:[], …`，另一份带着法与 `solved`）+ 损坏信封（非 JSON、`v` 为字符串、`data` 为 null、v2 但缺字段）各一项；Playwright 先种旧信封再开页，断言说明卡、`legacy-xiangqi` 快照存在、新存档可用；再加"存档恢复在机器人回合"。
