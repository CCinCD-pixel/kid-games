## 1. 定位、玩家幻想、立意、能力目标、课标锚点、证据等级

### 1.1 一句话
**星晶消消乐**：开着星晶号从星港出发，一站一站消星晶、开货箱、救宇航员，飞到冥王星再回家——一款按商业三消标准做的、每一关都经过仿真验证的休息区游戏。

`game.json` 副标题（幻想动作，不写能力）：**收集星晶，开飞船去冥王星**。

### 1.2 玩家幻想
小步步是**星晶号**的船长。星晶号是一艘小飞船，靠星港矿区出产的"星晶"充能。每一站是一个真实的太阳系目的地（星港码头 → 月球·静海 → 火星·峡谷 → 小行星带 → 木星·大红斑 → 土星环 → 海王星·暗云 → 冥王星·冰原 → 回家·星港庆典），那里有当地的麻烦：月面盖满星尘、火星峡谷堆着货箱、小行星带的晶石被冻住、木星风暴里有等救援的宇航员、海王星的暗物质会蔓延。每到一站，星晶号装上一个新模块（主推进器、着陆腿、机械臂……），航线图上的飞船看得见地变完整。伙伴机器人领航员坐在副驾驶。

### 1.3 立意
**"看清再动手：消掉以后，会掉下来什么？"**

三消的乐趣本来就在"因果链"：一次交换 → 消除 → 重力 → 补充 → 新的连锁。旧版用随机关卡和单一目标把这条链藏起来了。新版把它摆到台面上：
- 道具要**做出来**（看出 L/T/方块/四连/五连的形状），**用对地方**（横火箭清横排、无人机自己找目标），**合起来用**（组合技）。
- 障碍逼他**按顺序想**：救援舱下面先清、冰壳要让同色晶石来找它、暗物质每步都要碰、角落留给道具。
- 多目标逼他**挑轻重**：先做差得多的那个。
- 每站一道星图谜题：不补充新晶石、限步数，是纯粹的"往前想 2–4 步"。
- 失败只说"还差这些"，并给一句对应的策略提示；没有生命值、没有计时、没有付费续命。

### 1.4 能力目标（可观测；家长页最多 3 个指标，见 §8.11）

| # | 能力 | 游戏里看得见的行为 | 记录 |

### 1.6 证据等级（家长页照抄）
**D 级（价值判断）**。三消游戏对一般认知能力的迁移证据很弱或为零（通用电子游戏训练效应的元分析结论为小或零，见研究报告 development.md 的 Sala 等综述）。本游戏是**休息区**，主要价值是愉快、可控的放松；我们刻意加入的"往前想一步、按顺序做、挑轻重"只声称**在游戏内**可观察到进步，不宣称提升智力。知识卡的内容是普通科普事实，不是课程。

### 2.2 全局布局常量
- 视口：`--kit-vw/--kit-vh` 与 `html[data-orientation]`（kit shell）。安全区 `env(safe-area-inset-*)`，主屏 App 实测顶部约 24 px、底部约 20 px（以真机为准，代码不写死）。

- 棋盘格子边长 `cell = min(96, floor(availW / cols), floor(availH / rows))`，取整到偶数（DPR 2 下精灵对齐像素）。
- 字体：数字 Baloo 2（`--xg-font-num`）；标题/喊话 站酷快乐体（`--xg-font-title`）；卡片文字 霞鹜文楷 26 px/1.8（`--xg-font-read`）；界面 PingFang。字幕 24 px，≤15 字。

### 2.5 输入
- **拖动交换**：手指按在格子上，移动 ≥ `0.28 × cell`（且 ≥18 px）时按主方向确定邻格，立即执行交换（不等抬手）。只认第一个指针（kit `PrimaryPointer`）。
- **点选交换**：点一下选中（放大 1.12 + 发光环），再点相邻格交换；点同一格取消；点不相邻的格改选它。
- **道具**：点一下已选中的道具 = 发射（第一次点只选中，第二次点发射；或者直接拖向邻格 = 交换发射）。这样"点选交换"和"点道具"不冲突。
- **工具瞄准**：点工具按钮 → 进入瞄准态（棋盘其余部分压暗 30%，可作用的格子高亮）→ 点格子生效；再点同一个工具按钮或棋盘外取消。离子炮瞄准态多两个 64 px 方向键（横/竖，默认横）。牵引臂需要点两个相邻格。
- 结算动画期间锁输入（但暂停键、🏠 永远可点）。命中区：格子本身（iPad 全屏时 cell ≥76 px，满足 ≥48；分屏窄窗口下 cell <48 时提示"请放大窗口"）。

## 3. 核心循环与规则

> 本节与 `emoji-match-tools/core.mjs` 逐条对应（函数名写在括号里）。两者冲突时以 `core.mjs` + 金样例为准，并回改本节。

### 3.1 循环
- **一步**（10–40 秒）：看盘 → 交换或点道具 → 消除 → 重力 → 补充 → 连锁 → 目标计数跳动 → 下一步。
- **一关**（1–3 分钟）：9–29 步，1–3 个目标，过关拿 1–3 星；失败马上可以再来，没有任何代价。
- **一站**（10 关 + 1 谜题，约 25–40 分钟，跨 2–3 次游玩）：章首教新元素，中间练，第 5 关难、第 6 关喘息，第 7 关组合技或复习，第 10 关小 Boss；到站装模块、看知识卡、停一下。
- **元循环**：星晶号 9 个模块 → 回家；星星点亮星座；谜题点亮徽章；工具按里程碑发放。

### 3.2 棋盘模型（`parseLevel`、`newGame`）
- 尺寸 W×H，5 ≤ W,H ≤ 9；格子下标 `i = r*W + c`，第 0 行在上。
- 每个格子：`mask`（是否存在；`-` 是空洞，不画、不能放东西）+ 以下层：

| 层 | 值 | 说明 |
|---|---|---|
| `kind` | EMPTY / PIECE / RH / RV / BOMB / PROP / ORB / CRATE / POD / GOO | 格子上的东西 |
| `color` | 0–5 或 −1 | 只有 PIECE 有颜色；道具无色 |
| `hp` | 1–3 | CRATE 的层数；GOO 恒为 1 |
| `ice` | 0–2 | 冰壳层数，只会出现在 PIECE 上 |
| `dust` | 0–2 | 星尘层数，在格子"地板"上，和上面是什么无关；**不会出现在货箱下面**（校验） |
| `spawner` | bool | 上方是棋盘外或空洞的格子自动成为补充口 |
| `exit` | bool | `exits` 列出的列，该列最下面的格子是救援舱出口 |
| `uid` | int | 每个可移动物体的稳定编号（移植时新增，给动画对位用；不影响规则） |

- 分类：**可交换**（movable）= 无冰的 PIECE + 5 种道具；**会下落**（falls）= 可交换的 + POD；**实心**（solid，挡住下落、自己不动）= CRATE、GOO、带冰的 PIECE。POD 不可交换、不斜滑，只会竖直下落。
- 关卡文本格式（单字符一格）：`.` 随机晶石，`-` 空洞，`_` 空格（只用于谜题），`r o y g b p` 指定颜色，`R O Y G B P` 指定颜色且带 1 层冰，`i`/`I` 随机颜色带 1/2 层冰，`1 2 3` 货箱，`@` 救援舱，`x` 暗物质，`> ^ * + &` 预置的横火箭、竖火箭、星爆弹、无人机、星核。星尘另给一层同尺寸的 `0/1/2` 文本（`dust`）；介绍卡脚本还可以给 `ice` 层（同格式，给指定颜色的晶石加 1–2 层冰，主线关卡不用）。

### 3.3 开局（`initialFill`）
1. 随机格按行优先依次取色：候选 = 本关颜色里不会与**左边两格**、**上边两格**组成三连，也不会与**左、上、左上**组成 2×2 的颜色；用 `rInit` 等概率选。
2. 填完后若全盘存在任何消除组，或没有一个合法步，整盘重来（最多 400 次，超过就报错；原型 90 关 × 1000 个种子最多重来 2 次，校验 V8 门槛 ≤10）。
3. `fixedBoard: true` 的关（教学关、谜题）用种子 `em:<id>:board` 生成开局，所以每次尝试开局完全一样；补充仍随尝试种子变化（谜题不补充）。

### 3.4 合法操作（`listMoves`、`swapValid`、`applyMove`）

| 操作 | 条件 | 花步 | 效果 |
|---|---|---|---|
| 交换两个晶石 | 正交相邻、都可交换、颜色不同、交换后**任一被交换格**处在消除组里（三连或 2×2） | 1 | 进入结算；否则晶石弹回、不花步（"再试试"） |
| 交换道具 + 晶石 | 正交相邻 | 1 | 两者换位，道具在**新位置**发射；若道具是星核，目标色 = 那颗晶石的颜色 |
| 交换道具 + 道具 | 正交相邻 | 1 | 两个都移除，在**手指拖到的那一格**（b）放出组合技（§3.7） |
| 点道具 | 道具已被选中时再点一次 | 1 | 在原地发射；星核点发 = 消掉盘上**最多的颜色**（并列取本关颜色顺序靠前的） |
| 工具 | 见 §3.14 | 0 | — |

- 交换方向：`a` = 手指起点，`b` = 落点。道具生成优先放在 `b`（§3.5）。
- 救援舱、冰住的晶石、货箱、暗物质都不能被交换。
- 只有一个指针有效；结算期间不接受新操作。

### 3.5 消除组与道具生成（`findGroups`、`creationCell`）
1. 找出所有**横向连续 ≥3**、**纵向连续 ≥3** 的同色 PIECE（带冰的也算），以及所有**同色 2×2 方块**。
2. 共享格子的形状合并成一个**组**（并查集）。不同颜色的组永不相交。
3. 每组决定道具（按优先级，取第一个满足的）：

| 优先级 | 条件 | 生成 | 名称 |
|---|---|---|---|
| 1 | 组内有一条 ≥5 的直线 | `ORB` | 星核 |
| 2 | 组内有一个格子同时属于一条横线和一条竖线（L、T、十字） | `BOMB` | 星爆弹 |
| 3 | 组内最长直线 = 4 | 横 4 → `RH`，竖 4 → `RV` | 火箭（**横着连就横着飞**） |
| 4 | 组内含 2×2 方块 | `PROP` | 无人机 |
| 5 | 其他（普通三连） | — | — |

4. 生成位置：玩家这一步的第 0 轮，若组里包含 `b`（且 `b` 无冰）就放 `b`，否则若包含 `a` 就放 `a`（道具+晶石交换时只看那颗晶石换到的新位置）；否则按类型：星爆弹放在横竖交点（第一个无冰的）；火箭/星核放在最长那条线上**最低、再最左**的无冰格；无人机放在第一个方块里最低再最左的无冰格。连锁轮次（第 ≥1 轮）一律按类型规则。找不到无冰格就不生成。
5. 道具在本轮所有命中处理**之后**才放上去（即使那一格这一轮又被别的爆炸扫到，道具照样出现）。

### 3.6 一步的结算顺序（`resolve`；每一轮叫一个 step）
```
step = 0
loop:
  groups = findGroups()
  queue  = (step == 0 ? 本步的发射/组合技 : [])
  if groups 为空 且 queue 为空: break
  creations = 每组的 (格子, 道具类型)          # §3.5
  for 每组: 组内每格受 1 次"消除命中"          # §3.6 表
  for 每组: 组外 4 邻的 CRATE/GOO 受 1 次"侧击"，同一轮每个货箱/暗物质最多 1 次侧击；冰壳从不受侧击
  while queue 非空: 取队首发射 → 覆盖的每格受 1 次"爆炸命中"；被扫到的道具立即入队尾（连环引爆，先进先出）
  放置 creations（该格此时为空才放）
  settle()                                      # §3.9：下落、补充、斜滑、救援舱到站
  step += 1;  if step > 60: break               # 安全阀，从未触发（V9 模糊测试）
步后：goo 蔓延（§3.10）→ 死局洗牌（§3.10）→ 判胜负（§3.11）
```
**命中表**（`hitCell`；最上面的一层吃掉这次命中）

| 格子上是 | 一次命中的效果 | 星尘 |
|---|---|---|
| 货箱 hp=n | hp−1；到 0 消失（计"货箱"） | 不受影响（货箱下不会有星尘） |
| 暗物质 | 消失（计"暗物质"；本步记为"碰到过暗物质"） | 不受影响 |
| 带冰晶石 | 冰 −1；到 0 晶石获得自由（计"冰壳"），**晶石留在原地** | 不受影响 |
| 无冰晶石 | 晶石消失（计入该颜色收集） | −1 层 |
| 道具 | 道具发射（入队），格子变空 | −1 层 |
| 救援舱 | 无效果（不可摧毁） | −1 层 |
| 空格 | — | −1 层 |

- 一格在同一轮可以被多次命中（不同的爆炸各算一次）；同一次爆炸只命中一格一次。
- **侧击**只来自普通消除（不来自爆炸），只伤货箱和暗物质。
- **能量**（`energy` 目标）：每消掉 1 颗晶石 +1，每掉 1 层障碍（货箱层、冰层、暗物质、星尘层）+1，每发射 1 个道具 +3。

| 发射物 | 覆盖格子 | 备注 |
|---|---|---|
| `RH` 横火箭 | 所在整行 | 视觉：两枚半火箭向左右飞 |
| `RV` 竖火箭 | 所在整列 | |

### 3.8 无人机找目标（`propTarget`）
按关卡 `objectives` 的**列出顺序**，取第一个"还没完成且有候选格"的目标：

| 目标 | 候选格 |
|---|---|
| crate | 所有货箱 |
| ice | 所有带冰晶石 |
| goo | 所有暗物质 |
| dust | 有星尘且上面是无冰晶石的格 |
| collect c | 颜色 c 的无冰晶石 |
| pod | 每个救援舱**正下方**的无冰晶石 |
| energy | （无，落到下一条） |

若都没有：任意无冰晶石。候选集合按下标升序，用 `rProp` 等概率选一个；同一轮已被选过的格不再选（PP 的 3 架飞不同的格）。

### 3.9 重力、补充、斜滑、救援舱（`settle`）
反复执行直到一轮里什么都没动：
1. **竖直下落**：逐列、自下而上，每个空格从正上方同一段（遇到空洞或棋盘顶为止）里最近的东西拉下来——如果那东西"会下落"；如果是实心的就停。（列内的空格在上方同一段内都空时，留给第 2 步补充。）
2. **补充**：（谜题与机器人评估时关闭）逐列自左向右、每列自上而下，空着的补充口生成新东西：若该列在 `pods.cols` 里，且 `场上救援舱 < max`、`已放出 < total`、`距上次放出 ≥ gap 步`，就放救援舱；否则放一颗随机晶石（`rFill` 在本关颜色里等概率）。有动就回到 1。
3. **斜滑**（只在 1、2 都不再动时）：自下而上、自左向右找第一个"被遮挡的空格"（向上走遇到的第一个非空物是实心的；若先走到空洞或棋盘顶则不算被遮挡——那一段有自己的补充口，谜题里则保持空着）；先看左上、再看右上，若是可交换的东西就斜滑进来（救援舱不斜滑）。每次只滑一个，然后回到 1。
4. **到站**：所有停在出口格上的救援舱移出（计"救援舱"），有动就回到 1。

因为救援舱只竖直下落、不能交换、不能斜滑，它永远待在进入的那一列：**所有放救援舱的列下面都必须有出口**（校验 V3）。

### 3.10 步后规则
1. **暗物质蔓延**（`spreadGoo`）：若盘上有暗物质，且本步没有任何暗物质被命中，则从"与暗物质正交相邻的无冰晶石"中（下标升序）用 `rGoo` 选 1 个变成暗物质。谜题也蔓延；机器人评估时不蔓延。
2. **死局洗牌**（`shuffle`，谜题不洗）：若没有合法步（道具在场就一定有步），把所有无冰晶石的颜色用 `rShuf` 洗牌，直到"没有现成的消除且至少有一个合法步"（≤60 次）；还不行就逐格重新取色（≤60 次）；再不行就把一颗晶石变成横火箭（伙伴："送你一个火箭"）。冰壳、道具、救援舱、障碍都不动。
3. **判定**：所有目标剩余为 0 → 过关（先判过关：最后一步刚好完成也算过关）；否则步数用完 → 差一点。

### 3.12 星级
- 1★：过关。2★：过关时剩余步数 ≥ `stars[0]`。3★：剩余步数 ≥ `stars[1]`。两条线由 `tune.mjs` 从孩子代理机器人的通关分布取 50 / 85 分位（`levels.json` 每关都有）。星级在"星晶号加速"之前结算。
- 解锁只需要 1★；最好成绩保留；结果页不出现"重玩拿满分"类文案（仓库 TONE_RULES 检查）。

### 3.13 过关演出："星晶号加速"（纯演出，不影响星级）
1. 喊话"目标完成！"（900 ms）。
2. 盘上剩余的道具从上到下依次发射（每个间隔 120 ms）。
3. 每一步剩余步数变成一枚小火箭从步数泡飞出，落到一颗随机（`rBonus`）晶石上并按横/竖交替发射（间隔 90 ms，最多 15 枚；多出的步数直接合并成最后一次大闪光）。
4. 任何时候点屏幕 = 快进到结果页。

### 3.14 工具（`applyBooster`；不花步，结算期间不可用）

| 工具 | 名字 | 操作 | 效果 | 不能用在 |
|---|---|---|---|---|
| `drill` | 激光钻 | 点一格 | 对该格 1 次命中（§3.6 表） | 救援舱、空洞、空格 |
| `tractor` | 牵引臂 | 点两个相邻格 | 纯交换（不需要成消除；道具交换时**不发射**），之后照常结算消除 | 不可交换的东西 |
| `ion` | 离子炮 | 点一格 + 选横/竖 | 该行或该列每格 1 次命中（等于一次无源火箭） | — |

### 3.15 起飞加成（`placeAssist`）
- 同一关**连续**失败 2 次 → 下一次开局预置 1 个火箭；连续失败 4 次 → 火箭 + 星爆弹；6 次及以上 → 火箭 + 星爆弹 + 星核。过关后连败计数清零。
- 放置：在开局盘面的无冰晶石格里用 `em:<id>:<attemptSeed>:assist` 选格（避开出口所在列的最下两格），替换掉那颗晶石。火箭方向：随机横/竖。
- 关卡卡上明确显示"领航员帮你装好了：[火箭图标]"，并播 em.assist.n。不是隐藏的动态难度。

### 3.16 星图谜题（puzzle）
- 固定开局（`grid` 全部指定颜色），**不补充**（`refill:false`），所有随机流用种子 0（`em:<id>:0`），所以每次完全一样。
- 步数上限 = `par`（1–4）。步数用完未完成：不出失败页，盘面保持，伙伴说 em.puzzle.retry，[撤销][重来] 在手边。
- 撤销不限次（存每步之前的完整状态快照）。
- 提示灯泡：H1 圈出第一步的起点格；H2 幽灵手演示第一步；H3 播放完整标准解（`solution`），然后回到开局让他自己走一遍。用过 H3 的解出记为"有帮助"（徽章仍点亮，家长页可见）。
- 暗物质在谜题里照样蔓延（p7 的考点）。

### 3.17 自由星海
8×8、5 色（rygbp）、无目标、无步数、补充开启；道具和组合技照常；能量环每满 300 播一次"能量满格"庆祝（粒子 + jingle-steel），然后清零继续。右下"结束" → 小结卡（最大连锁、做出的道具数、组合技数）。连续玩满 10 分钟，下一次小结或静止 5 秒时出一次气泡 em.free.break（不打断、不锁）。

### 3.18 随机性与种子
- 全部用 `@kit/rng`（mulberry32 + FNV-1a，与原型逐位一致）。根种子：`em:<levelId>:<attemptSeed>`；分流：`fork('refill' | 'init' | 'prop' | 'goo' | 'shuffle')`，另有 `em:<id>:board`（固定开局）、`…:assist`、`…:bonus`。
- `attemptSeed` = 存档里的全局自增 `attemptSeq`（每次开一局 +1），所以重试的补充不同；一局的全部操作（含工具）记成 `resume.ops[]`，**同种子 + 同操作 = 同结果**，用于断点续玩（§8.7）和复现 bug。
- 禁止 `Math.random()`（视觉粒子除外，粒子不影响状态）。

### 3.19 边界情况清单（每条在 `core.test.ts` 或 V9 模糊测试里有覆盖）
1. 同色交换 → 非法，不花步。2. 交换后只在别处出现消除不可能（盘面原本稳定，消除必含交换格）。3. 冰住的晶石参与匹配：它破冰但不消失，组里其他格照常消失（金样例 G6）。4. 生成格有冰 → 换下一个候选格。5. 一步同时形成两个不同颜色的组 → 各自生成道具。6. 道具在同一轮被炸到 → 先进先出依次发射，每个道具只发射一次。7. 星核点发时盘上没有无冰晶石 → 无效果（仍花步）。8. 无人机没有任何候选 → 只炸原地十字。9. 无人机带的火箭/星爆弹在目标格发射，覆盖范围以目标格为准。10. 组合技位置是落点 b。11. 连锁 >60 轮 → 停止本步结算（安全阀；V9 模糊测试 2 万步从未触发）。12. 救援舱停在出口上方的冰壳上 → 等冰破了再落。13. 救援舱在出口格时立即到站，即使正在连锁中。14. 最后一步同时完成目标并用完步数 → 过关。15. 暗物质被侧击或炸到都算"碰到"；工具命中也算。16. 洗牌后仍无合法步 → 送火箭（必有合法步：点火箭）。17. 关卡开局保证 ≥1 合法步、0 个现成消除（V8）。18. 旋转屏幕发生在动画中 → 状态早已算完，只重排画面（§8.5）。19. 切到后台 → 动画暂停，回来继续；音频由 kit 挂起/恢复。20. 结算中点 🏠 → 自动存档（`resume` 已含本步），下次回来从这一步之后继续。

生成方式：`puzzles.mjs --gen K` 按规格（尺寸、颜色、障碍数、par）随机出盘，穷举求解，**接受条件**：最短解 = par、首步可赢的 1–2 个、合法首步 ≥6（p9 ≥8）、par ≥3 时每条解都要做出或发射道具；候选再由人挑选并冻结进 `PUZZLES`。**拒绝**：有更短解、首步可赢 >2、开局有现成消除或无步。随机流种子与关卡 id 绑定（`em:p4:0`），所以谜题的 id 不能改（改了要重跑求解器）。

## 6. 美术（商业品质，无图片生成器）

### 6.1 风格总则
- **外壳**（航线图、站点地图、到站过场、机库）：设计系统的**剪纸夜空**风格（`data-xg-theme="night"`），纸片层叠 + 月光描边 + 柔和投影；按钮、卡片、结果页全用设计系统组件（`.xg-btn`、`.xg-chip`、`showResult`、`nodeMap`、`replayButton`、`setHintReady`、`ghostTap/ghostDrag`、伙伴 `mount`）。
- **棋盘**（操作区）：深色玻璃面板上的**亮面切割宝石**——对标 Royal Match / Candy Crush 的饱满、高光、立体感，但用我们自己的太空造型。棋盘内部**没有装饰性动画**（只有道具的待机微动和提示），保证看得清。
- 全部图形**代码绘制**：SVG 字符串（`src/view/art/*.ts`）→ 运行时栅格化成精灵图集（`atlas.ts`，§8.5）；背景场景是 SVG 源码，构建时用 Playwright 栅格化成 WebP（`site/emoji-match/tools/build-scenes.mjs`，与设计系统 `_pw/raster.mjs` 相同做法），提交进 `public/emoji-match/bg/`。**零第三方图片**，无 emoji 字形。

### 7.2 连锁音阶

### 8.3 引擎 API 与动画记录
```ts
parseLevel(def: LevelData | PuzzleData | IntroData): Level
newGame(level: Level, seed: number | string, opts?: { record?: boolean }): GameState      // record → 产生 StepRecord
listMoves(st, withTaps = true): Move[]          // Move = { t: 'swap'; a; b } | { t: 'tap'; a }
applyMove(st, mv): { ok: boolean; won: boolean; steps: number; record?: MoveRecord }
applyBooster(st, use): 同上（不加 movesUsed）
placeAssist(st, tier: 1 | 2 | 3, seed: string): number[]
remaining(st, o): number; isWon(st): boolean; starsFor(level, movesLeft): 1 | 2 | 3
bestMove(st): Move | null                          // = G 机器人的选择（并列取下标最小，不用随机）
cloneState(st, evalMode = false): GameState

interface MoveRecord { move: Move | BoosterUse; steps: StepRecord[]; post: { gooSpread?: number; shuffle?: { uid: number; to: number }[]; gift?: number } }
interface StepRecord {
  step: number;
  matches: { color: number; cells: number[]; make?: { cell: number; kind: Kind } }[];
  blasts: { kind: BlastKind; at: number; cells: number[];            // cells 按命中顺序（火箭由近到远、星爆弹由内到外）
            flights?: { from: number; to: number; carry?: Kind }[];  // 无人机
            converts?: { cell: number; kind: Kind }[] }[];           // 星核组合
  hits: { cell: number; what: 'piece' | 'crate' | 'ice' | 'dust' | 'goo' | 'special' | 'side'; color?: number; left?: number; by: number /* blast 序号，-1 = 消除 */ }[];
  created: { cell: number; kind: Kind; uid: number }[];
  settle: { falls: { uid: number; from: number; to: number; diag: boolean }[]; spawns: { uid: number; cell: number; kind: Kind; color: number; dropRows: number }[]; delivered: { uid: number; cell: number }[] };
}
```
- 引擎先**一次性**算完整步（含全部连锁，原型实测 <0.1 ms/步，A13 预计 <1 ms），视图再按 `StepRecord` 播放；动画期间状态已经是最终态（这让旋转、后台、断点续玩都简单）。
- `uid`：每个晶石/道具/救援舱一个，随交换、下落、斜滑移动；新生成的拿新 uid。精灵池按 uid 对位。
- 记录开销：`record:false`（机器人、校验）时 `record.ts` 的钩子是空函数。

### 8.4 状态机
**顶层（`app.ts`）**：`BOOT → GATE(S0) → [首次] FIRST_RUN(1-01) | ROUTE(S1) ⇄ MAP(S2) → CARD(S3) → [INTRO(S3a)] → PLAY(S4) → RESULT(S6/S7) → MAP | CARD(下一关) …`；`ARRIVAL(S8)` 插在第 10 关首胜之后；`HANGAR(S9)`、`FREE(S10)`、`PUZZLE(S11)`、`PARENT(S12)` 从 S1/S2 进出。路由用 `history.pushState` + 页内屏幕切换（不刷新页面），iOS 左滑返回 = 上一屏。

**PLAY 内部**：
```
READY ──(拖动/点选成功)──────────────▶ ANIMATING ──(动画完)──┬─▶ READY
  │ ▲                                  ▲                        ├─▶ BONUS ─▶ WIN（S6）
  │ └──(取消/点同格)── SELECTED ───────┘                        └─▶ OUT ─▶ FAIL（S7）
  ├──(点工具)──▶ AIM ──(点格子)──▶ ANIMATING
  │             └──(再点工具/点棋盘外)──▶ READY
  └──(暂停键/切后台)──▶ PAUSED ──(继续)──▶ 之前的状态
```
- READY 下启动提示计时（§5.1）；任何触摸重置。
- ANIMATING 期间输入锁定；BONUS 期间点屏幕快进。
- 每次进入 READY 都把 `resume` 写进存档（§8.7）。

### 8.5 渲染方式
- **一个棋盘 `<canvas>`**（CSS 尺寸 = 面板外框，像素 = ×DPR，DPR 封顶 2），绘制顺序：面板与格子（预渲染到一张离屏 canvas，只在 layout 变化时重画）→ 星尘层 → 出口 → 物体（按 uid 精灵）→ 冰壳 → 选中/提示光环 → 棋盘粒子/冲击波/火箭。
- **精灵图集**：每种精灵（6 晶石 + 5 道具 + 舱 + 3×3 货箱态 + 2 冰 + 2 尘 + 4 暗物质帧 + 道具待机帧，共约 40 个）按 `cell×DPR` 栅格化一次（`new Image()` 加载 `data:image/svg+xml` → drawImage 到离屏 canvas），图集 ≈ 40×(152²×4 B) ≈ 3.7 MB。cell 变化（旋转）时重建（<60 ms，在下一帧前完成；重建期间沿用旧图集缩放绘制）。
- **按需动画**：只有在时间轴、粒子、待机微动或提示存在时才跑 rAF；棋盘静止 + 无道具时零 rAF（GAME_AUTHORING §7）。道具待机微动用 8 fps 的低频节拍（每 125 ms 一帧），不是 60 fps。
- **收集飞行与喊话**：全屏 `fly` canvas（pointer-events:none）画飞向目标卡的精灵；喊话、目标卡、步数泡是 DOM。纸屑用 kit `particles` 的 `confetti()`。
- **旋转**：`onLayout` → 重算 layout → 重建图集（若 cell 变了）→ 精灵坐标都是"格子下标 → 像素"实时换算，所以动画中途旋转也不会错位。
- **后台**：`onPause` 暂停时间轴时钟；`onResume` 继续。

### 8.6 输入实现
- `PrimaryPointer`（kit）只跟踪第一个指针；`touch-action: none` 在棋盘上。
- 拖动阈值 `max(18 px, 0.28 cell)`；方向取 |dx| 与 |dy| 较大的轴。
- 点选：`onTap`（kit，无 300 ms 延迟），10 px 容差。
- 道具：第一次点 = 选中（SELECTED），第二次点同一格 = 发射；从道具拖向邻格 = 交换发射。
- 工具瞄准时用同一套命中测试；牵引臂两次点击之间显示连线预览。
- 命中测试把棋盘外 12 px 的边缘也算进最近的格子（`hitSlop`），方便边缘格。
