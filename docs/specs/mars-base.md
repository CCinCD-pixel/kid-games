### 0.3 术语

- **区（zone）**：基地上的一个地点，对应一座建筑，如 `vault`。
- **章（chapter）**：一个区里的一串节点。数学区的章 5–11 个节点：每个节点是一个约 5 分钟的 6 题任务，一章约 30–50 分钟，相当于谜题游戏一章 8–12 关的体量（这是对 §3.0"每章 8–12 关"的明确豁免）。
- **节点 / 站（node）**：最小的进度单位，如 `vault.K1.4`（"零的位置"）。完成即得 1★，解锁下一节点。
- **任务（mission）**：一次游玩的学习单元 = 3 道热身 + 1 个节点的 6 道主题 + 建造过场 + 收尾卡。约 6–9 分钟。
- **题（item）**：一道订单。**题族（family）**：一个生成器，如 `add.carry1`。
- **档（level）L1–L6**：难度阶梯，由"数的范围"和"表征"共同决定（§3.6）。
- **表征（rep）**：C 实物（必须动手搭）、P 图示（有图，直接用键盘答）、A 符号（只有算式，答错后才出图）。
- **先答后验**：默认先用键盘作答，交付后才用实物验证。
- **孪生题（twin）**：同结构、换数字的一道题，用在 H3 之后。
- **热身（warm-up）**：任务开头 3 题，来自间隔复习、认证复核、跳站探针。
- **掌握（mastered）**：技能标签最近 10 次首试 ≥80% 且最后 3 题没用提示（§3.7）。掌握与解锁无关。

## 1. 定位、玩家幻想、立意、能力目标、课标锚点、证据等级

### 1.1 一句话

> 他是火星「祝融基地」的总工程师：矿车运来火星晶，他按订单装棒、装箱、称重、排发射时刻；订单交对了，基地就长出新建筑。

### 1.2 玩家幻想

- 身份是**总工程师**，不是"小朋友答题"。领航员（伙伴机器人）是他的副手，会出错，需要他验收。
- 世界是真实航天的延伸：天问一号、祝融号 2021 年着陆乌托邦平原；火星一天 24 小时 39 分；火星有两颗小卫星。这些只出现在知识卡和场景细节里，不打断操作。
- 看得见的成长：基地从一块着陆坪长成 9 座建筑的小城，每座 3 档外观。**基地从不倒退**，造好的东西永远不会被拿走。
- 和爸爸有关：火箭赛道可以和爸爸同屏对战；"出题给爸爸"里由他开订单、验收爸爸的答案。

### 1.3 立意

**数是工程师的工具：先估一估，再算一算，最后验一验。**

- 估：轨道站插旗、赛道上只标整十，每一次落点都是一次估计。
- 算：用策略算（凑整十、补偿、想加算减、拆开阵列），不是逐个数。散晶槽一次只放得下 9 颗，结构上逼他打包。
- 验：答错时用实物和数轴把后果演出来；领航员的货单会写错，要他找出来；爸爸的答案要他验收。
- 犯错是工程数据，不是失败。界面不出现"错"字；伙伴从不难过。

## 3. 核心循环与规则

### 3.1 会话、任务、单元

- **游戏会话 `sessionIndex`**：页面打开一次算一次；如果距上次活动不到 20 分钟（刷新、切 App 回来），沿用上一个会话号。所有"间隔复习""认证复核"都按会话号算，不按日历。
- **任务结构**（普通节点）：
  1. 3 道热身（§3.9 选题），进度点空心。
  2. 6 道主题，来自当前节点。
  3. 孪生题：只在 H3 之后插入，紧跟在下一题之后，一个任务最多 2 道。
  4. 建造过场（S3）：本节点首次完成时，所在区建筑加一个部件或升档（§5.4）。
  5. 收尾卡 + 对话卡（S4）→ 回基地地图。**不自动开下一个任务。**
- **特殊节点**：
  - 校准节点（`orbit.O1.0 / O1.4 / O2.6`）：12 面旗，无热身，约 4 分钟。
  - Boss 节点：8 道主题，混合本章 3–4 个题族，无新元素。
  - 喘息节点：4 道开放订单（自己定数、自己搭），没有对错，只有"交付"。
- **长任务**：一个任务的主动操作时间超过 15 分钟时，在当前题交付后领航员问一次"这批货先交了吧？"（两个等大按钮：先交 / 继续）。选"先交"→ 已做的题保存，节点未完成，下次从下一题继续。只问一次，不强制。
- 火箭赛道一局 ≤7 分钟，谜题舱一次 3 题 ≤6 分钟，都是独立入口，不计入任务。

### 3.2 一道题的状态机

```
PRESENT ──(选模式)──► ANSWER_FIRST ──✓──► VERIFY#1
                └───► BUILD_FIRST  ──✓──► VERIFY#1
VERIFY#n: 对 ──► DELIVER ──► NEXT
          错 & n=1 ──► CONSEQUENCE ──► RETRY(强制 BUILD_FIRST) ──✓──► VERIFY#2
          错 & n=2 ──► HINT_H2（自动，预填一半）──✓──► VERIFY#3
          错 & n=3 ──► HINT_H3（幽灵手完整示范，答案出现）──✓──► DELIVER(无分) ──► 插入孪生题
任何状态 ──(提示键/30 s 无触摸)──► 提示阶梯下一级（§5.1），完成后回到原状态
任何状态 ──(返回键/切后台)──► SUSPEND（存档：任务 seed、题序号、操作日志）
```

- **首试正确** = 在 VERIFY#1 答对，且这道题没打开过任何提示。只有首试正确计入掌握与档位。
- **模式选择**：满足任一条就是 BUILD_FIRST，否则 ANSWER_FIRST：
  1. 节点带"新元素"，且是该节点前 2 道主题；
  2. 当前档位 L1，或表征被临时降到 C（§3.6）；
  3. 同一技能标签的上一题首试错了；
  4. 本题被标成"讲给爸爸听"（每个节点最多 1 道，第 5 题）：要求用实物搭出思路，交付后弹出对话卡。
- **空交付**：键盘值为空时点 ✓ → 显示框轻摇（`onSubmit` 返回 false），不算作答。
- **DELIVER**：订单箱封口 → 弧线飞向本区建筑（700 ms）→ 建筑闪一下。连续首试正确时，音高沿五声音阶升一级（`chime` 阶梯，最多 8 级，答错归零）。
- **语音节奏**：答对不是每题都说话。只在：本任务第 1 次首试正确、首试连对 3 和 6、用对了策略（补偿、凑整十、想加算减、转阵列）时说一句（§7.2 `mars.ok.*`）；其余只有音效 + 领航员点头动画。

### 3.3 答案判定

| 答案类型 | 判定 | 备注 |
|---|---|---|
| 整数（键盘）| 完全相等 | 键盘不允许前导 0；最多 4 位 |
| 插旗（数→位置）| \|落点 − 目标\| ≤ 容差 → 对；≤ 2×容差 → "很接近"；更远 → 差得多 | 插旗题**不重试**（知道答案后重插没有意义）："很接近"照常交付，不算首试正确；"差得多"演示差距后进孪生题。容差见 §4.2 轨道站表 |
| 读数（位置→数）| \|答 − 真值\| ≤ 容差 | 同上 |
| 钱（元/角两栏）| 换算成角后相等 | 只有 S1.6"几元几角"要求角 <10；答成"0 元 15 角"→ 提示"15 角能换成几元几角？"，不算错也不算首试正确 |
| 钟（读）| 时 ∈1–12、分 ∈{0,30} 或 5 的倍数，与真值相等 | 12 时只接受"12"，不接受"0" |
| 钟（拨）| 分针吸附到目标刻度；时针由齿轮联动，总是一致 | 吸附：T1 只吸附 0/30，T2 吸附 5 分刻度 |
| 比较（`compare2`）| 两步：① 在两个数中间放 >、<、=；② 点出"决定大小的那一位"（两个数里第一个不同的数位，任点其中一个数的那一位都算）。两步都对 = 对 | 不是纯选择题（猜中率 ≤1/9）。L6 的"三/四个数挑最大"同理：挑出最大的数 + 点出决定它最大的那一位 |
| 纯选择题 | 一次点击就完成作答、选项 ≤4 个的题 | 全游戏目前为 0 道；以后新增题族若是纯选择，受 V8"总体 ≤10%、每任务 ≤1 道"约束。干扰项只许用 4 类诊断（差 1、差 10、运算用反、数字颠倒）|
| 搭建 | 晶槽状态的数值 = 目标，且满足"交付规范"：散晶 ≤9、棒 ≤9、箱 ≤9（1000 例外，§3.4）| 规范由容量规则保证 |
| 找错单 | 先点出错的那一位（第一个出错的数位），再在键盘输入正确结果 | 点错位置 → 领航员"这一位是对的，再看看" |
| 开放题（预算采购、三角数阵 T4、B1.3 多种放法、喘息订单）| 按规则校验，任何满足规则的答案都对 | 不存在"唯一答案" |

### 3.4 晶体操作规则（ManipKit `PlaceValueTray`）

**部件**：矿车（散晶车 / 棒车 / 箱车）、散晶槽、压棒机、棒架、装箱机、箱位、切割机、暂存盘、发货口。

| 规则 | 内容 |
|---|---|
| 散晶槽容量 | 9 个六边形格。第 10 颗落进压棒机入口，晃动；入口有晶时，矿车再倒的晶会弹回矿车 |
| 压棒 | 压棒机只在"槽里 9 颗 + 入口 1 颗"时可点；点击 → 10 颗合成 1 根棒，进棒架 |
| 棒架容量 | 9 根。第 10 根进装箱机入口；点装箱机 → 1 箱，进箱位 |
| 箱位容量 | 9 箱。只有 `vault.K2.3`（999+1）允许第 10 箱：装箱机变成"千晶舱"动画，托盘显示 1 个千晶舱（=1000），这是托盘能表示的最大值 |
| 切割 | 把一根棒拖到切割机（或点棒再点切割机）→ 10 颗散晶落进**暂存盘**（10 格，切出后才出现）；把一箱拖到切割机 → 10 根棒进棒架（棒架满时进暂存架）|

| 撤销 / 重来 | 每个操作入日志；"撤销"倒放上一步（200 ms）；"重来"回到本题初始状态，一键，无确认 |
| 点选代替拖拽 | 点源（发光）再点目标，等价于拖拽 |
| 守恒 | 任何操作前后，托盘 + 暂存 + 发货口 + 矿车的总值不变（单元测试断言）|

### 3.6 难度档位与自适应（参数已仿真）

**档位**（每个技能标签一个，跨节点保存）：

| 档 | 数的范围 | 默认表征 | 说明 |
|---|---|---|---|
| L1 | 题族 band 1 | C 实物（必须搭）| 最大支架 |
| L2 | band 1 | P 图示 | |
| L3 | band 2 | P 图示 | |
| L4 | band 2（题族只有 2 档时用 band 2；有 3 档时用 band 3 的一半概率）| A 符号 | 答错后才出图 |
| L5 | 最高 band | A 符号 | |
| L6 | 题族的"挑战变体"（§4.1 表最后一列）| A 符号 | 只能靠连对升上来 |

**规则**（只看首试）：

1. 首试对 → 连对计数 +1；连对 3 → 升 1 档（最高 L6），计数清零。**连对计数和档位一样按标签存档、跨任务累计**（存档 `tags[tag].streak`）；不跨任务的话，一个任务只有 6 题，向上走得比向下慢，正确率会系统性偏高（仿真里"强"学习者因此从 84% 涨到 85.0%）。
2. 首试错 → 降 1 档（最低 L1），计数清零。
3. 同一标签连续 2 次首试错 → 接下来 3 题表征临时降一级（A→P→C），与档位无关。总方案"同一技能连错 2 次降一档"落在这里。
4. 新节点的起始档：该标签已有档位就沿用；新标签若先修标签已掌握从 L3 起，否则 L2。
5. **过渡**：任务结束时本节点首试 <60% → 节点不前进；下一次进这个节点是"过渡任务"：档位上限 L3，前 2 题强制动手。过渡任务结束后节点无条件完成。所以一个节点最多玩 2 次。
6. **直达**（跳站）：任务结束时档位 ≥L5 且首试 ≥5/6 → 出"直达"卡，两个等大按钮："直达后面两站" / "按顺序走"，领航员把两个都读出来，不暗示。选直达 → 后面 2 个节点标为"跳过"（地图上显示虚线，可随时回去玩），它们的标签进入热身探针队列。
7. **连续高分**：同一区连续 2 个任务首试 ≥95% → 同样出直达卡，但只跳 1 站。

**仿真结果**（`sim.mjs`，5 类学习者 × 1000 人 × 30 次会话，统计第 3–30 次会话**主题题**的首试正确率；热身复习题按设计应更高（≥85%），不计入这个目标）：

| 学习者 | 首试正确率均值 | p10–p90 | 一个节点最多玩几次 | 第 18 次会话后剩余节点（中位/最少）|
|---|---|---|---|---|
| 强（整体超前）| 84.2% | 82.1–85.7% | 2 | 80 / 55 |
| 中 | 81.0% | 79.2–82.7% | 2 | 107 / 79 |
| 弱 | 76.3% | 73.8–78.6% | 2 | 118 / 106 |
| 已会 100 以内 | 81.8% | 80.4–83.3% | 2 | 81 / 67 |
| 0–100 已线性 | 82.2% | 80.4–83.9% | 2 | 102 / 69 |

两头都只有约 1 个百分点余量。真代码校验器（V4）超出时的调参顺序：偏高 → 先丰富 L6 挑战变体，再把直达阈值从 5/6 调到 4/6；偏低 → 先把新节点起始档从 L2 降到 L1（只对弱学习者生效的那条规则），再把过渡阈值从 60% 调到 65%。**不改 3 对升 / 1 错降。**

### 3.7 掌握与间隔复习

- 标签掌握：该标签最近 10 次首试中 ≥8 次对，且最后 3 题没用任何提示。少于 10 次不判。
- 掌握于会话 s → 在 s+1、s+3、s+6、s+10 各安排 1 道热身复习题，档位 = 当前档位 −1（最低 L3）。
- 复习题首试错 → 复习表重排为"下一次、再隔 2 次"，标签标 `shaky`；连对 2 道复习题去掉 `shaky`。
- 孩子看不到"掌握"二字。他看到的是节点星星和建筑档位；家长面板看掌握与复习。

### 3.8 认证规程

**流程**：在 S7 点一块认证牌 → 认证运行器（S2 的变体：顶栏没有提示键，进度点 4–6 个，牌子徽章在订单卡左侧）。

1. 题序固定：一档 a、二档 a、一档 b、二档 b（各子技能的一档/二档题族见 §4.4）。
2. 每题只答一次，答错时演示后果 1.5 秒，不重试，直接下一题。错满 2 题立即结束。
3. 4 题全对 → 通过。错 1 题 → 追加 2 道二档题，全对才通过。
4. **通过**：徽章点亮 + 建筑部件 + 该子技能的练习节点全部标为"跳过（可玩）"。进入**暂定期**：之后的热身里安排 4 道该子技能的二档题（所有子技能合计每次会话最多 2 道），错 ≥2 道 → 悄悄重开练习章（从第 1 节点、L3 起，地图上出现推荐环；徽章不收回，家长面板标"复习中"）。
5. **未通过**：练习章打开，领航员："我们去练习舱，把这块牌子练出来。" 练完该章 Boss 节点后（或做满 3 个练习任务后）可以再认证。
6. 认证时不显示提示键；30 秒无触摸只播放一次"慢慢来"的鼓励句，不给方法提示。

**为什么不是"4 题错 2 停"就够**（会的人：一档首试 p=.97、二档 .93；半会的人：一档 .85、二档 .60；按题序精确计算）：

| 通过规则 | 会的人通过率 | 半会的人误通过率 |
|---|---|---|
| 4 题错 ≤1 | 98.7% | 69.9% ✗ |
| 4 题全对 | 81.4% ✗ | 26.0% ✗ |
| **本规程（错 1 追 2）** | **96.3%** | 42.0% |
| **本规程 + 暂定期复核（4 道二档错 ≥2 重开）** | 93.8% 保持认证 | **19.9%** ✓ |

仿真（`sim.mjs`，各 10 万次）：不会的人（二档 p=.3）误通过 6.5%（复核后 0.6%）；有系统性误解的人（二档 p=.05）0.2%。全部满足总方案"会的 ≥90%、不会的误通过 ≤20%"。

### 3.9 推荐、解锁与热身选题

**区的开放**（地图上从"建设中"变成可进）：

| 区 | 开放条件 |
|---|---|
| 轨道站、认证站、谜题舱 | 上手完成后 |
| 火箭赛道（百赛道）| 完成第 1 个任务 |
| 千晶大仓 | C1 已认证，或完成 `cert.C1.3` |
| 生产线 | 累计完成 3 个任务 |
| 任务时刻表 | 累计完成 4 个任务 |
| 补给站 | C2 已认证，或完成 `cert.C2.4` |
| 称重台 | C2 已认证（或完成 C2 Boss），且累计完成 6 个任务 |
| 千赛道 | 完成 `vault.K1` 章 |
| 自由工厂 | 完成 `factory.P1.4` |
| 出题给爸爸 | C2 已认证或完成 `vault.K1` 章 |

**"开始任务"推荐**：对每个"有下一个可玩节点"的已开放区打分，取最高：

```
score = 2 × min(6, 距上次玩该区的会话数)       // 没玩过记 6
      + 1.5 × (该区有待做的认证或被重开的练习)
      + 1 × (该区是超前区：orbit/vault/factory/balance/clock-T2)
      − 5 × (本次会话已经玩过该区)
平分时按固定顺序：orbit, cert, vault, factory, balance, supply, clock, puzzle
```

- 第 1 次会话固定推荐 `orbit.O1.0`（校准）。第 2、3 次会话如果 C1、C2 还没认证，推荐认证站（认证是一次 4–6 题的短任务，之后再推荐一个普通任务）。
- 孩子可以无视推荐，点任何已开放的建筑（主动选择记入日志 `source:'self'`）。

**热身选题**（每个任务 3 道，按优先级填）：

1. 认证暂定期复核题（每次会话合计 ≤2 道）。
2. 到期的间隔复习（§3.7），最久未复习的优先。
3. 跳站探针：被"直达"跳过的节点的标签，各 1 道（L3）；首试错 → 该跳过节点被推荐。
4. 当前节点的先修标签，L3。
5. 以上都不足时：最近玩过的其他区的标签，L3。

约束：热身不能和本任务主题用同一个"新元素"；3 道热身来自至少 2 个不同的区（交错）。

### 3.10 各区的专属规则

**轨道站（插旗）**
- 拖旗时，手指上方 140px 处出现放大镜（直径 120，4 倍），显示手指附近的刻度和旗尖；抬手才落点，吸附到整数。
- 落点后：先播"旗落"音，再从目标处升起一道光柱（240 ms），显示落点与目标之间的距离条和数字"差 d"；容差带（半透明青绿）只在落点后显示。
- 锚点按节点撤除：0/10/…/100 → 0/50/100 → 0/100（0–1000 同理：每 100 → 0/500/1000 → 两端）。
- 校准节点：12 个目标固定（§4.2），顺序随机，不显示容差带，不说"对/错"，每面旗落下只有"卫星入轨"动画；结束时一次性展示 12 面旗和一条拟合线（"你的轨道"），领航员只说"轨道画好了"。通过标准（R² ≥ .90、斜率 .90–1.10、PAE ≤10% / ≤15%）只在后台判定。
- `orbit.O1.0` 通过 → O1.1–O1.4 标为跳过，直接开 O2；没通过 → 按顺序走，O1.4 是复测。

**火箭赛道**（参数见 §4.3）
- 对手：爸爸（同屏轮流）或领航员（练习 / 对手 / 高手）。赛道：百赛道（0–100）或千赛道（0–1000，K1 章完成后）。
- 每回合翻 2 张行动牌，选 1 张 → 键盘报落点 → 报对，火箭才起飞。
- **牌组**：百赛道有"基础牌"（默认）和"进阶牌"（C2 已认证或 C2 章完成后，在选赛道页用分段按钮切换，两套都随时可选，不自动切）。进阶牌里的乘号牌（+10×3 等）在生产线 P1.4"乘号登场"完成前显示成普通数（+30），之后显示乘号；领航员报落点时也按乘号念（"三个十，落在 57"）。
- 报错：领航员给 H1（如"先加 10，再加 7"）再报一次；第二次还错 → 数轴上把跳跃拆开演示，落点数字出现，孩子照着按一次 → 起飞。不扣分、不跳过回合。
- 落在补给格前进 10，落在陨石格后退 10（效果只触发一次，不连锁）。≥100 即到站（不要求正好）。
- 后手从第 5 格出发（抵消先手优势；仿真后手胜率 50.3%）。
- **验收领航员**：对战领航员时，领航员每次报落点后问"对吗？"，孩子点 [对] 或 [不对]。领航员按档位有一定概率故意报错（练习 30%、对手 15%、高手 5%），错误只用诊断类（差 1、差 10、不进位、大减小）。
  - 孩子点"不对"且确实错了 → 领航员改正，孩子得 1 枚"检查员章"（只计数，用于解锁知识卡 §5.5）。
  - 孩子点"不对"但其实对 → 一起用跳跃验算一遍，没有任何惩罚。
  - 孩子点"对"但其实错了 → 落地后领航员自己发现并改正（`mars.race.oops`"哎呀，我算得不对"，再显示正确落点）。
- 对战爸爸时，爸爸也用键盘报落点（同样规则）。界面不记录胜负次数，只在结果页说谁先到站。孩子输了：领航员"领航员先到站！再来一局？"，不难过。

**谜题舱**：见 §4.5。规则：一次 3 张谜题卡，任意顺序；每题可撤销、清空；填满后自动检查，或点"完成"检查；没做完离开不留记录，也不出现"今天做完没有"。

**称重台**（ManipKit `Balance`）
- 两个秤盘；横梁倾角 = clamp(3° × (右重 − 左重), −12°, 12°)，弹簧动画（stiffness 180、damping 14）。
- 砝码是带数字的圆角块；神秘箱是橙色木箱，箱面一个白圈"?"。同一题里的箱子一样重。
- 允许的操作：
  1. **两边同拿**：从一个盘拖走一个砝码（或箱子）时，另一个盘里同值的砝码（或箱子）同时高亮；放到回收口 → 两个一起消失。另一边没有同值的东西 → 拖动时横梁预演倾斜，松手弹回，领航员："两边要拿一样的。"
  2. **两边同加**（B1.4 起）：从补给盘拖一个砝码到一边 → 另一边自动出现同值的虚影，点虚影确认放下。
  3. **切砝码**：点一个砝码再点"切"→ 键盘"切出几？"输入 k（1 到 N−1）→ 变成 k 和 N−k 两块。
  4. **平分**（B2.5 起，双胞胎箱）：一边只剩 2 个箱子、另一边只剩砝码时，"平分"键亮起 → 砝码按"一人一个"分成两堆（可切割），每个箱子对应一堆。
- 目标：一边只剩 1 个神秘箱、另一边只剩砝码 → "称出来了！" → 键盘输入箱子的重量。
- 天平任何时候都不允许"偷偷"失衡：除了两边同拿、同加、切、平分，没有别的操作。

**补给站**（ManipKit `MoneyTray`）
- 钱包里是练习币；柜台上是货架（物品 + 价签）。付款：把钱拖到柜台付款区，付款区显示合计（L1–L2 显示数字）。
- 兑换机：10 个 1 角 ↔ 1 元；2 个 5 角 ↔ 1 元；5 个 1 元 ↔ 5 元；2 个 5 元 ↔ 10 元；2 个 10 元 ↔ 20 元。和晶棒同一个比喻：10 个小的换 1 个大的。
- 找零：收银员（领航员）往上数，孩子在键盘输入找回多少；动手模式下，孩子从收银抽屉里一张张拿钱，口播往上数（"7 元，8、9、10 元"）。

**任务时刻表**（ManipKit `Clock`）
- 表盘直径 360（竖屏 300）。拖分针，时针按 1/12 联动；T1 分针吸附 0/30，T2 吸附 5 分刻度。逆时针拖动允许。
- 时间轴：一条 12 格的横条（每格 1 小时），起点和终点用发射图标标出；经过几小时 = 两点之间的格子数，动手模式下孩子一格一格点亮。
- 只用"上午/下午"的口头说法，不用 24 时计时法。

校准目标（固定，顺序随机）：
- 0–100：3, 7, 12, 18, 25, 33, 42, 51, 64, 71, 86, 93
- 0–1000：6, 18, 34, 78, 122, 163, 246, 366, 486, 606, 754, 938（取自 Siegler & Opfer 2003 的 0–1000 刺激集）

通过规则：线性拟合 R² ≥ .90，斜率 .90–1.10，PAE ≤10%（0–100）/ ≤15%（0–1000）。原型 `numline.mjs`（每类 1 万次）：

| 估计者 | 0–100 通过 | 0–1000 通过 | 平均 PAE |
|---|---|---|---|
| 线性，噪声 σ=3% | 100% | 100% | 2.4% |
| 线性，σ=6% | 93% | 94% | 4.5% |
| 线性，σ=9% | 71% | 74% | 6.5% |
| 线性，σ=12% | 34% | 43% | 8.4% |
| 对数式 | 0% | 0% | 32–41% |
| 半线性半对数 | 0% | 0% | 16–21% |
| 压缩（斜率 .75）| 0.1% | 0.1% | 7.5% |

结论：实际起决定作用的是 R² 和斜率（PAE 门槛基本不会单独卡人）；对数式和混合式一个都过不了；规则对"已线性"的孩子偏严（σ=9% 时 71%），代价只是多玩几个 0–100 节点，可以接受。家长面板同时显示 PAE 和对数拟合 R²（`r2log`），并印常模：0–100 一年级 PAE 约 14–18%、二年级约 10–15%；0–1000 二年级约 19%、四年级约 12%。

### 5.1 提示阶梯

- **触发 H0**：≥30 秒无任何触摸，或孩子点提示键。以下情况不计时：键盘里有未交付的输入且最后一次按键在 10 秒内；正在拖拽；旁白正在播放。

### 5.2 失败处理

- 学习区没有生命值、没有计时、没有 Game Over。
- 答错 → 演示为什么（§3.5）→ 重试；再错 → H2；再错 → H3 + 孪生题。不跳题、不扣分。
- 同一标签连续 2 次首试错 → 接下来 3 题表征降一级（§3.6）。
- 任何状态一键"撤销""重来"。返回键随时可用：存档到题级（任务 seed + 题序号 + 操作日志），下次进入从同一题继续，题目不变。
- 建造好的建筑、拿到的星和卡，永远不会被拿走。

## 6. 美术

### 6.1 风格总则

- **两个层次**：
  - **世界层**（基地地图、建造过场、赛道背景、知识卡插图）：剪纸分层 SVG。暖色火星，纸张有厚度和投影。
  - **操作层**（S2 操作区、键盘、谜题）：干净的扁平矢量，放在暖白纸面上。**不放任何装饰动画**（Fisher 2014），只有操作反馈动画。
- 光从左上来；阴影只有向下偏移（dx=0），旋转屏幕时不会显得歪。
- 不用 emoji 做角色或主要物件。不用 CSS `filter`、SVG `<filter>`、`backdrop-filter`（A13 上贵）。纸张阴影 = 同一路径偏移 4px、填 `rgba(52,30,12,.18)`。

### 7.2 音乐

- 操作区（S2、S5 对局中、S6 解题中、S7 认证中）**没有背景音乐**。
- **基地地图、章节图、档案页**：运行时合成的环境音乐 `src/audio/ambience.ts`，不用文件：
  - 火星风：粉红噪声 → 低通 400 Hz → 增益按 0.08 Hz 正弦缓慢起伏（−32 dB 到 −26 dB）。
  - 和声垫：两个失谐 ±6 cent 的三角波，和弦 C–Am–F–G（每个和弦 8 秒，32 秒一循环），低通 1200 Hz，起音 1.5 s / 释音 2 s，−28 dB。
  - 拨弦旋律：固定种子（`createRng('mars-base:ambience')`）在 C 大调五声音阶上生成 16 小节旋律（每小节 2–3 个音，72 BPM），音色 = 正弦 + 2 倍频泛音、10 ms 起、600 ms 衰减，−24 dB。每次进地图从同一处开始，听起来是同一首曲子。
  - 接到 `getBus('music')`；kit 的 `duckMusic` 只管 `<audio>` 音乐，所以本模块自己订阅旁白：`onCue(cue≠null)` → 300 ms 降到 35%，`onCue(null)` → 600 ms 回到 100%。
  - 进入操作屏、页面隐藏（kit `pause`）时 800 ms 淡出并停止所有节点；回到地图再淡入。家长面板可关。
- 庆祝：设计系统的 `level-complete`、`chapter-complete`、`jingle-win` 乐句。

### 7.3 数字与拼句

- **数字片段** `mars.num.0` … `mars.num.1000`：每个数一段，按教材读法：305"三百零五"、360"三百六十"、110"一百一十"、200"二百"、1000"一千"、20"二十"、12"十二"。读法函数 `readZh(n)` 在 `content-src.mjs` 里，`voice/numbers.ts` 用同一算法（单测对照）。量词前的"两"：`mars.u.liang`（两根、两箱、两元）。
- **单位片段**：`mars.u.ke` 颗、`mars.u.gen` 根、`mars.u.xiang` 箱、`mars.u.yuan` 元、`mars.u.jiao` 角、`mars.u.shi` 时、`mars.u.fen` 分、`mars.u.xiaoshi` 小时、`mars.u.ban` 半。
- **名称片段**：区名 `mars.zone.*`、章名 `mars.chapter.*`、节点名 `mars.node.*`、行星 `mars.planet.*`、货物 `mars.item.*`、认证牌 `mars.badge.*`。
- **载体片段** `mars.c.*`（24 个，见 `lines.json` 里 `fragment:true` 的条目）：如 `mars.c.place`"把旗插在" + `mars.num.378`。槽位只放在自然停顿处。
- **拼句实现**（kit 的 `Narrator` 没有多片段接口，在本游戏内做，**不改 kit**）：`src/voice/compose.ts`
  ```ts
  sayComposite(parts: string[], subtitle: string, opts?: { interrupt?: boolean }): Promise<SayResult>
  ```
  1. 把字幕条（`createSubtitleBar`）的 `onCue` 包一层：`composite` 进行中时忽略片段自己的 cue，只在开始时显示一次完整 `subtitle`，结束（最后一段 `done`）时清空。
  2. 依次 `narrator.say(part)`（kit 队列本身是串行的，片段之间不加额外间隔；`interrupt` 只加在第一段）。
  3. 数字 2 后面紧跟量词时用 `mars.u.liang`（"2 根" → "两根"；"12 根"、"20 根"不变）。
  4. "再听一遍"按钮由本游戏自己管：记住最后一次是单句 id 还是 composite，再听时整句重放（kit 的 `narrator.replay()` 只会重放最后一个片段，所以不用它）。
  5. 片段缺音频时 kit 会退回系统 TTS 读片段文字，句子仍然完整。
- 抽样质检：每个拼句模板 × 20 个随机数值拼出的句子，过一遍本地 ASR（§9 V9）。

  - 节点给了 `band`：这就是本节点要教的概念，**档位不改 band**，只改表征（L1 = C 实物，L2–L3 = P 图示，L4–L6 = A 符号）；到 L6 时，6 题里最多 2 题换成该题族的 L6 挑战变体。

  - Boss 的 `items` 是"混合"：每个题族 2 题，打乱顺序，同一题族不相邻。
- 认证题序、轨道校准目标、赛道参数、谜题档位表都放在 `tuning.ts`（代码常量，有单测）。

### 8.3 状态机

**路由**（S0a–S13）：`BOOT → (onboarded ? MAP : ONBOARD) ; MAP ⇄ CHAPTER ⇄ MISSION → BUILD → WRAP → MAP ; MAP ⇄ RACE ; MAP ⇄ PUZZLE ; MAP ⇄ CERT(→ CERT_RUN → CERT_RESULT) ; MAP ⇄ ARCHIVE ; FACTORY → SANDBOX ; CERT|VAULT → TEACH ; MAP → PARENT`。路由不进浏览器历史（主屏 App 没有后退手势冲突），返回键由 kit shell 处理：在 MAP 时回大厅，其他屏幕回 MAP（任务中先存档）。

**题目**：§3.2。实现为显式枚举 + `transition(event)` 纯函数（可测），视图订阅状态。

**赛道回合**：`SETUP → DEAL → PICK → ANNOUNCE → (kid: VERIFY_ANNOUNCE ⟲ hint) | (bot: KID_JUDGES) → FLY → EFFECT → CHECK_FINISH → (next player) DEAL … → END`。对局状态存档在 `race.inProgress`，离开后可继续。

**认证**：`INTRO → ITEM(i) → (wrong: SHOW_CONSEQUENCE 1.5 s) → … → (0 错: PASS) | (1 错: EXTRA(2)) | (2 错: FAIL) → RESULT`。

### 8.4 渲染方式

- DOM + 内联 SVG。每个操作区一个 `<svg>`（viewBox 按 §2.3 的操作区尺寸），可拖动物件是 SVG `<g>`，用 `transform` 移动。
- 动画：WAAPI（kit `animate`）和 CSS transition，只动 `transform`、`opacity`。弹簧（天平）用 kit `tween` 每帧算角度。
- Canvas 2D 只用于 kit particles（交付尾迹、尘土）。不用 WebGL。
- 布局：CSS grid + `--u` 缩放变量；kit shell 的 `layout` 事件触发重新布局（换方向时：取消正在进行的拖拽，物件回原处；模型状态不变；当前题不重置）。
- 幽灵手：设计系统 `ghostTap/ghostDrag`，脚本化步骤（`engines/manip/ghost.ts`），每个提示/上手动画是一段步骤列表。
- 文字：数字全部用 `--xg-font-num`；SVG 内文字用 `<text>` + 同字体。

### 8.5 输入

- kit `PrimaryPointer`：只认第一个手指；第二指按下忽略。
- 拖拽：`makeDraggable`，命中区 ≥64（小物件用 `hitSlop` 扩到 64）；吸附半径 48；拖动时物件跟手偏上 24px（避免手指遮挡）。
- 点选代替拖拽：点源 → 发光 → 点目标；再点源取消。
- 键盘：设计系统 `mountKeypad({maxLength: 4})`；物理键盘（调试）数字键也能用。
- 双击、长按不承担唯一功能（切砝码用"点砝码 + 点切"）。
