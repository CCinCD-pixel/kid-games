## 0. 一屏速览

- **是什么**：2.5D（俯视 3/4 斜角）推箱子解谜，**商业手游品质**。孩子是星港**调度员小步步**，指挥搬运机器人**小推**把补给箱推上同色发射台；一个仓库装满，地板升降台把货沉下去，一枚货运火箭从仓库旁边升空，飞向天宫空间站、月宫基地或火星基地。
- **核心操作**：点地面 → 小推自动走过去（BFS 最短路，少拐弯）；点挨着的箱子 → 推一格；点不挨着的箱子 → 箱子四周出现可推方向的箭头，点箭头 → 自己走过去推一格；屏幕任意处滑动 = 走/推一格（熟手用）。**撤销不限次**（单位 = 一推，带"倒带"动画，长按连撤），**重来本身也能撤销**。
- **内容**：主线 7 章 54 关（52 推箱关 + 2 侦探题），每关都有手工确定的 ASCII 地图、最优推数/步数、"这关教什么"和机器校验；跳级考试 2 关；**经典仓库**（旧版 10 关，导入他的旧进度）；**大师塔** 12 层（36–51 推，3–5 箱，可选）；**随机新仓库**（逆向拉箱生成器，4 档，无限、每次都新）。
- **教什么**：先想后推（多步规划）、站位与方向（空间）、谁先谁后（顺序约束）、临时停车（子目标）、倒着想（逆向推理）、**看出推不动的箱子**（四类死局：墙角、空墙边、并排贴墙、四方块）、颜色约束配对。
- **手感**：每一步都有补间（走 110 ms/格、推 150 ms/格）、挤压回弹、尘土、发射台卡扣锁定光、按入位顺序升调的锁定音、倒带撤销、仓库装满的火箭发射；小推有待机/行走/推/撞墙/思考/庆祝 6 组参数化动画。
- **时长**（§4.9）：主线 + 认证 模型估计 2.3 h、按 6 岁实际放慢 1.5 倍 ≈ 3.5 h；全部固定内容 5.1–7.7 h；随机仓库无限。按每周 3 次 × 约 12 分钟：**主线 ≈ 6 周，全部固定内容 ≈ 13 周**。
- **引擎**：建 `engines/puzzle`（PuzzleKit，第一款用户）：网格模型、推箱规则、寻路、死局检测、预算内求解（Web Worker）、逆向拉箱生成器、关卡校验器。

## 1. 定位、玩家幻想、立意、目标能力、课标锚点、证据等级

### 1.1 定位与玩家幻想
- **定位**：站内"规划 / 空间推理"主力学习卡（7 张学习卡之一），`domains: ["planning", "spatial"]`。全站唯一的单人确定性规划谜题，和棋类（对抗）、月宫（3D 空间）、玉兔（编程）不重叠。
- **玩家幻想**：**"我是星港的调度员。每个仓库都是一道题：我先看清楚哪个箱子先走、哪里是死角，再指挥小推一推一推地装货——仓库一装满，就有一枚火箭替我把补给送上太空。"** 他喜欢的三样东西（太空、机器车辆、冒险）在这里同时出现：货运火箭 + 搬运机器人 + 一层层的"仓库关卡"。
- **基准（我们学什么，不抄什么）**：

| 产品 | 让它显得"贵"的东西 | 我们拿来做什么 |
|---|---|---|
| A Monster's Expedition / A Good Snowman Is Hard to Build（Draknek） | 撤销是**倒带**（反向播放补间，有专属音效，长按加速）；重来也能撤销；全程无字；每个动作都有重量感（先蓄力再动、落地有回弹） | 撤销 = 一推一倒带（§3.4）；重来可撤销；推箱"接触延迟 20 ms + 落地回弹"（§6.6） |
| Patrick's Parabox | 极简 HUD；每关只有一个点子；关卡名就是线索；同一区域里同时开放多关，卡住可以先去别的关，进度从不卡死 | 每关一个"这关教什么"；关名 2–4 字即点题；每章永远同时开放 2 关；提示永远可选、只发光不自动播 |
| Cosmic Express（Draknek，太空题材） | 完成时**有叙事意义的离场**（列车开走）；可爱的太空配色；关卡地图就是星图 | 仓库装满 → 升降台沉货 → 火箭升空；关卡选择是"星港货运图" |
| Mekorama | 点哪走哪的小机器人；机器人有大量小动作（晃、眨眼、摔倒爬起）让人想一直看 | 小推的 6 组参数化动画 + 眨眼/东张西望/打盹（§6.4） |
| Thinkrolls Space（Avokiddo，3–8 岁） | 每章只加一种新物件；第一关零文字靠示范；章节地图有收集感 | 新元素只在章首出现；首关幽灵手示范；章节完成解锁小推装扮 |
| Lara Croft GO / Monument Valley | 舞台式切面（diorama）、柔和光影、每个画面都像一张海报 | 仓库是悬在剪纸夜空里的切面货舱，外沿有纸片投影（§6.3） |
| 一般应用商店"推箱子"（反例） | 纯格子 + 瞬移 + 方向键 + 蜂鸣音 | 全部不要：没有方向键盘、没有瞬移、没有系统蜂鸣、没有"最少 N 步" |

**"贵"的 8 条可验收标准**（每条都对应到本规格的具体参数，DoD 逐条看）：
1. **零延迟**：点下到画面/声音变化 ≤100 ms（§8.6）；动画中的输入排队不丢（§3.2）。
2. **有重量的运动**：蓄力—接触延迟—过冲回弹三段式，箱子与小推不同步起步（§6.6 推一格）；从不瞬移。
3. **撤销是演出**：倒带动画 + 专属音 + 长按加速；重来可撤销（§3.4）。
4. **无字教学**：第 0 章 4 关只靠幽灵手、关卡结构和一句语音学会全部操作（§2.3）。
5. **有意义的完成**：锁定音按入位顺序升调成和弦，升降台沉货、火箭飞向真实目的地（§6.6）。
6. **一致的美术**：一套色板、一套形状语言（圆角 + 纸边 + 夜蓝墙 + 琥珀主角），3/4 斜角遮挡正确（§6.2–6.3）；风格板先过审（§6.7）。
7. **一关一个点子**：每关都有被校验器证明的课程意图（§4.2 关键校验列、§9.1 L 规则）。
8. **尊重时间**：没有确认弹窗、没有强制观看（首个发射序列除外）、2 关同时开放、结果卡一键下一关（§3.5、§5.5）。

### 1.2 立意
1. **先想后推**：推箱子的每一推都可能不可逆（现实里推进墙角的箱子就是出不来）。游戏让他在一个安全的地方体验"不可逆"，并学会**在动手之前看出来**——这是规划能力的核心。
2. **调度员不是搬运工**：真正的物流靠计划。关卡课程从"站对位置"一路走到"倒着想"，每一章都是一种真实的调度思路：先装最里面的、先让开挡路的、最难进的先进、颜色（货物种类）要对上。
3. **出错是工作的一部分**：撤销被设计成"倒带"而不是"失败"；死局用琥珀色的"推不动"标记 + 小推挠头，从不出现"错"；"工程师也常常撤回重来"。
4. **航天是真的**：货运火箭送的是天舟那样的补给（水、燃料、种子、零件），知识卡讲天舟货运、文昌发射场、太空里的货物为什么要绑好、装货为什么讲顺序（先用的放门口）。
5. **和爸爸讲**：每次收尾卡有一个"讲给爸爸听"问题（"收拾书包时，先放哪个？为什么？"），把"顺序"和"倒着想"带回现实。

## 3. 核心循环与规则（穷举、无歧义）

### 3.1 世界模型
- **网格**：W×H 个格（主线/认证/经典 ≤10×10，大师塔 ≤12×12，随机仓库 ≤10×9）。行 r 从上到下，列 c 从左到右；格号 `i = r·W + c`。
- **格类型**：`wall`（墙）、`floor`（地面，从小推起点泛洪可达的非墙格）、`void`（外部，不画地板，画星空）。地图字符见 §8.3；泛洪漏到地图边缘 = 数据错误（校验 G1）。
- **发射台**（pad）：在 floor 上，颜色 `k ∈ {0,1,2,3,4}`（0 = 星港琥珀，1 燃料红●，2 水蓝▲，3 种子绿■，4 零件紫◆；固定内容只用 0–3）。
- **补给箱**（crate）：在 floor 上，颜色同上。每种颜色：箱数 = 台数（G1）。同色箱子可互换。
- **入位**：箱子在**同色**发射台上 = 入位（锁定）。颜色不同 = 不入位（台上不出卡扣，箱子无 ✓ 灯）。
- **过关**：所有发射台都被同色箱子占据（等价于所有箱子入位）。
- **小推**：占一格；箱子、墙是障碍；能站在空发射台上。

### 3.2 输入 → 动作（`src/input/boardInput.ts`）
只认第一个手指（kit `PrimaryPointer`），点按判定用 kit `onTap`（≤10 px 位移、≤600 ms），滑动用 kit `onSwipe`（≥30 px）。所有命中判定在棋盘坐标里做，**命中范围 = 整格 + 6 px 外扩**（格 ≥57 px，所以实际目标 ≥57 px）。

| 输入 | 条件 | 结果 |
|---|---|---|
| 点地面/空发射台格 X | X 可达（箱子当障碍的 BFS） | 小推沿最短路走到 X（同长度时选拐弯最少的；仍并列按 上→右→下→左 优先）；X 闪一下脚印光圈 120 ms |
| 点地面格 X | 不可达 | 不移动；X 画琥珀虚线框 300 ms + 小推"疑问"表情 600 ms + `bump`（音量 0.5）；连续 3 次点不可达格 → 伙伴 `sok.tip.unreach`"那里走不到哦，箱子挡住啦"（每关最多 1 次） |
| 点箱子 B | 小推与 B 相邻，且沿"小推→B"方向推一格合法 | **推一格** |
| 点箱子 B | 小推与 B 相邻，但该方向推不动 | B 抖动 ±2°（2 次，160 ms）+ 小推撞一下（§6.6 bump）；**不**显示箭头 |
| 点箱子 B | 小推不相邻 | B 被"选中"：B 四周出现**可推方向箭头**（只显示合法的方向：站位格可达 + 前方是空地面），每个箭头是 64×64 的命中区（外扩到相邻格中心）；再次点 B 或点别处 = 取消选中 |
| 点箭头 d | B 被选中 | 小推走到 B 的反方向站位格，接着**推一格**；推完 B 保持选中、箭头按新局面刷新（所以连着点同一个箭头就能一路推下去） |
| 点墙 / 星空 | — | 无动作；轻微涟漪（琥珀，α .25，240 ms），无声 |
| 滑动（棋盘内任意处起手） | 设置"滑动走路"开（默认开） | 小推朝该方向走一格；那格是箱子则推一格（不合法 → bump） |
| 键盘 ←↑→↓ / WASD | 开发 / 外接键盘 | 同滑动 |
| 点小推自己 | — | 小推开心跳一下（彩蛋，200 ms），无其他效果 |

- **输入队列**：动画进行中收到的新动作进入**长度 1 的队列**（后来的覆盖先来的）；当前格的补间结束后执行。走路中途点了新目标：走完当前这一格后从当前位置重新寻路。
- **输入锁**：发射序列、H3 演示、倒带（撤销动画）、关卡入场动画期间锁住棋盘输入（撤销键在倒带期间仍可连按，见 §3.4）。
- **选中态的生命周期**：推箱、撤销、重来、走路开始时清除（"点箭头推"那一推完成后保留）。

### 3.3 推的规则
- 推：小推在 P，箱子在 B = P + d，目标 T = B + d。合法 ⇔ T 是 floor 且 T 上没有箱子。结果：箱子到 T，小推到 B。一次只推一个箱子，不能推两个连着的箱子，不能拉。
- **推数**（HUD 数字）= 当前历史里的推次数（撤销会减少，重来清零）。**步数不显示**（只用于内部统计和 2 星判定以外的家长数据）。
- 推完后立即（同一帧）：① 胜利判定 → 是则锁输入进入发射序列；② 否则跑死局检测（§3.6）；③ 通知 Worker 重算提示（防抖 300 ms，§5.1）。动画只是"演出"，逻辑状态在推的瞬间已经确定（修掉旧版"推离目标后仍弹胜利"的竞态）。

### 3.4 撤销与重来
- **撤销单位 = 一推**。历史栈存每一推之前的完整状态 `{player, boxes}`（小推站位 = 那一推的站位格，即 B − d）。撤销 = 恢复上一个状态，演出为**倒带**：箱子和小推同时反向滑回（120 ms，`outCubic`），带 2 个 30% 透明度的青色残影和 `sok-rewind` 音效；撤销后小推站在当时推箱的位置、面朝箱子。
- 两推之间的"纯走路"不进历史（走路随时可以再点回去，没必要撤）。所以"撤销"永远退到"上一推之前"，满足方案"撤回到上一次推箱之前"。
- **长按撤销**：按下立即撤 1 次；按住满 400 ms 起连撤，间隔从 220 ms 起每次 ×0.75、下限 80 ms（220、165、124、93、80、80…）；松手停。按住 2 s 共撤 18 次。
- **重来**：把当前状态作为一个特殊条目 `{kind:'restart', snapshot}` 压栈，然后回到开局（演出：箱子和小推淡出 150 ms → 开局状态弹入 200 ms）。**重来后再按撤销 = 一步回到重来之前的局面**（误触重来不丢进度）。没推过任何箱子时重来按钮置灰。
- 栈深上限 2000 条（超过丢最旧的，实际到不了）。
- **离开再回来**：关卡进行中离开（回地图、回大厅、切后台被杀），历史栈序列化进存档 `inProgress`（§8.7）；下次点同一关时直接恢复到离开时的局面（结果卡"再来一次"例外：从头）。

### 3.5 胜利、星级、发射序列
- 胜利：§3.1；输入立即锁住；发射序列（§6.6，首次 3.2 s 不可跳过，之后 2.4 s，点屏幕任意处可快进到结果卡）。
- **星级（按推数，方案 §3.0/§3.6）**：设本关最优推数 `opt`（求解器给出，存在关卡数据里，校验器复核）。
  - ★★★：推数 ≤ `opt`，且本关这次没有用过 H3；
  - ★★：推数 ≤ `star2 = opt + max(2, ceil(0.25·opt))`；
  - ★：过关。
  - 用过 H3 → 最多 ★★。结果卡**不写**"最少只要 N 推"、"再玩一遍拿满分"。每关记录历史最好星数和最少推数。
- 侦探题星级：3 块棋盘都第一次就对 ★★★；2 块 ★★；其他 ★。
- 结果卡的 **下一关** = 当前轨道里按顺序的下一个已开放关；本章最后一关之后如果下一章已开放就进下一章第 1 关（先播章节开场语），否则回地图，并让新开放的页签发光一次。
- 解锁只需要 ★（§5.5）。

### 3.6 死局反馈（两层）
**第一层：看得见的死局（四条保守规则，立即显示）**——`engines/puzzle/src/deadlock.ts`，与 `sokoban.mjs detect()` 逐格一致：
1. **墙角**（corner）：箱子不在同色台上，所在格两面相邻（一横一竖）是墙。
2. **墙边**（wall）：箱子不在同色台上，且所在格是该颜色的"简单死格"（从这里推，不管别的箱子怎样都到不了任何同色台；用"从同色台反向拉"的可达性预计算）而不是墙角——通常是贴着一面没有同色台的墙。
3. **并排**（pair）：一个 2×2 方块里 2 格是同一侧的墙、2 格是并排的箱子，至少一个箱子不在同色台上。
4. **四方块**（square）：其他任何四格全是墙/箱子的 2×2 方块，至少一个箱子不在同色台上。

这四条都只会把"真的没救"的局面标出来（零误报，校验 G6 在全部可达状态上验证）。表现：被判死的箱子上弹出琥珀圆底 ✕ 徽章（180 ms `outBack`）+ 箱子外一圈琥珀虚线；小推转向它做"挠头"（§6.4）；撤销键出现两圈扩散光环（直到撤销）；`try-again`（软木"咚"）。**每种类型第一次出现时**（全游戏一次），伙伴说出它的名字：`sok.dead.corner.first` / `wall.first` / `pair.first` / `square.first`；之后只出图标不说话。✕ 一直留到撤销为止；他可以继续推别的箱子（不强制撤销）。
**第二层：看不见的死局（求解器证明，延迟提醒）**：每推一次，Worker 在预算内判定当前局面是否还能完成（§5.1 同一个求解器）。若"已证明推不完"且第一层没报：
- 第 2–3 章：再推 2 下或 8 s 没动作后提醒；第 4–6 章：再推 3 下或 15 s 后；随机仓库：同第 4–6 章；大师塔、经典仓库：不主动提醒（按 💡 才说）。
- 提醒 = 伙伴气泡 `sok.stuck.1`"这样好像推不完了" + 一个按钮 **回到能推完的地方**（xg-btn--accent，带 `undo` 图标）。点它 = 连续倒带到历史里**最近一个可完成的局面**（Worker 从新到旧逐个判定，开局状态一定可完成），倒带速度同长按撤销。他也可以不理，自己撤。
- 第 0–1 章只有一个箱子，单箱死局全部落在第一层，不会出现第二层。

### 3.7 侦探题规则（S6，3-3 与 3-5）
- 每题 3 块静态棋盘，依次出现（棋盘翻牌入场 300 ms）。语音 `sok.quiz.ask`"哪些箱子再也推不到发射台了？点它们"。
- 点箱子 = 放/取一个放大镜标记（再点取消）；每块棋盘至少有 1 个死箱、至少 1 个活箱（校验 Q2）。点 **检查**：
  - 标对的死箱：琥珀 ✕ 徽章 + 类型名标签（墙角 / 墙边 / 并排 / 四方块）+ 该类型语音；
  - 漏标的死箱：同样揭晓，标签旁多一个小幽灵手（"这个也没救了"），`sok.quiz.missed`；
  - 标错的活箱：标记变成青色 ✓，并用半透明幽灵演示它还能被推动的一推（箭头 + 300 ms 滑动后复位），`sok.quiz.alive`"这个还能推，你看"；
  - 在同色台上的箱子算"已经到家"，不算死箱（A3、B3 专门考这一点）。
- 一块棋盘第一次全对 → 记"首次正确"；否则揭晓后给同一块棋盘一次重试（标记清空），第二次无论对错都揭晓并进入下一块。永不出现"错"字，揭晓语气是"侦探发现了"。
- 3 块做完 → 结果卡（星级 §3.5）。

### 3.8 认证（跳级考试）规则
- 第 0 章最后一关（0-4）过关后，地图第 1 章章首出现"跳级考试"节点，并在首次进入第 1 章页签时弹 S7 邀请（只弹一次；之后节点一直在）。
- 考试 = cert-1、cert-2 两关，正常玩，有撤销、有 H1/H2，**H3 在考试里不可用**（💡 第三次按只重复 H2）。

- 没过（中途退出或某关一直没过）→ 不扣任何东西，不说"没通过"；节点保持可再考；伙伴 `sok.cert.later`"那我们从第 1 章开始，正好热身"。

### 4.8 随机新仓库（生成器：`engines/puzzle/src/generator.ts`，原型 `random.mjs` + `gen.mjs` + `rooms_random.mjs`）
**算法（逆向拉箱 + 正向验证 + 拒收）**，`generatePuzzle(tier, seed)` 对同一种子结果逐位相同（`createRng` / mulberry32）：
1. 选房间：从该档房间表里按种子选 1 个模板（16 个手画模板，§8.3 `rooms.json`，尺寸指内部：4 小（5×5、6×4）、4 中（6×5、7×5、6×6）、4 大（7×6、8×5、7×7 十字）、4 特大（8×7、7×7、8×6；当前不用，留给以后扩容 T4 池）；`x` 柱位按 `pFurn`（0.45–0.5）随机成墙；50% 左右翻、50% 上下翻。
2. 定箱数和颜色：按档（下表）；有颜色时发射台颜色按 1,2,1,2… 分配。
3. 放发射台：在地面格里随机选 k 个（模板有 `o` 区时优先）；所有箱子先放在自己的台上（= 完成状态），小推放在随机非台格。
4. **逆向拉箱 BFS**：从完成状态（小推在每一个连通区都算一个起点）出发，做"拉"的逆操作（小推站在箱子旁、往外退一格并把箱子拉过来），记录每个状态的拉数 d（= 正向最少推数的上界，状态不超过 150 000）。
5. 选起始局面：在 d ∈ [推数下限, 推数上限] 的状态里，只留**所有箱子都不在台上**的，随机挑一个；小推起点选该状态可达区里的非台格（模板 `p` 区优先；可达区全是台 → 拒收，原型 bug 修复记录见 `gen.mjs`）。
6. 正向验证：全图预解求真正最优推数（必须落在档位区间），并得到参考解。
7. 拒收规则（任何一条不过就换种子重来，每次调用最多 60 个候选）：

| 规则 | 内容 |
|---|---|
| R0 | 生成失败：房间泛洪不封闭 / 拉不出够远的局面 / 没有"全部离台"的局面 / 小推只能站在台上 |
| R1 | 不可解，或最优推数不在档位区间 |
| R2 | 开局就有检测器死局 |
| R3 | T2 起"没有点子"：贪心机器人能解 **且** 不需要停车 **且** 不止一个箱子能先走 |
| R4 | T2 起"没有张力"：开局没有任何致命首推 |
| R5 | 走路太多：最优步数 > 3 × 推数 + 12 |
| R7 | 太乱：内部墙格 > 内部格的 30% |
| R8 | 重复：与最近 50 个已玩的规范哈希（8 种对称归一）相同，或与任何固定关相同 |
| R9 | 提示预算：全图状态数 > 50 000 |
| R10 | 有颜色时没有颜色诱饵 |

8. "这关教什么"按模板自动写（`lessonOf`）：必须停车 → "先给一个箱子找个停车位"；唯一先手 → "先送对的那一个箱子"；有颜色 → "每个箱子找同色的发射台"；有并排陷阱 → "别让两个箱子并排贴墙"；有墙角陷阱 → "小心墙角"；有墙边陷阱 → "别把箱子推到空墙边"；否则 "先想好路线再推"。（对应语音复用 `sok.hint.*` / `sok.lv.*` 里同句的录音；新句子 7 条已在 §7.3 之外另列为 `sok.rnd.*`，见附录 B 末尾。）

### 4.9 续航测算（每周 3 次 × 约 12 分钟 = 36 分钟/周）

|---|---|---|---|---|
| 主线第 0–6 章 + 认证 | 56 | 139 min | 208 min | 5.8 周 |
| 经典仓库 | 10 | 24 min | 36 min | 1.0 周 |

## 5. 提示、失败处理、星级、掌握、元进度

### 5.1 提示阶梯（`src/hints/`，Worker 端 `engines/puzzle/src/stategraph.ts` + `solver.ts`）
**求解后端（为什么提示永远是"对的下一推"）**
1. **全图预解（主路径）**：关卡一载入，Worker 从开局出发把所有推级状态（小推位置归一化为可达区里编号最小的格）**全部展开**，再从所有完成状态做反向 BFS，得到每个可达状态的"离完成还差几推" `togo`（−1 = 已经推不完）。上限：200 000 个状态或 6 s，超出即放弃本路径。实测（Node，原型 `sokoban.mjs explore`，`graphbench.mjs`）：第 0–5 章每关 ≤ 4 400 状态；第 6 章 4 箱关 7 083–40 315（最大 6-6，0.5 s）；大师塔最大 108 532（T12，1.1 s，原型 64 MB）；经典 C10 173 512（2.8 s，98 MB）。**生产实现必须用类型数组**（开放寻址哈希 + CSR 边表 + `Int16Array togo`，§8.2），目标 ≤ 40 字节/状态（C10 ≈ 7 MB）、A13 上 T12 ≤ 3 s。建图期间棋盘照常可玩。
2. **单次求解（后备）**：图还没建好、或超上限时：从当前局面做推数最优的 A*（启发 = 每个箱子到最近同色台的单箱推距之和，下界可采纳；去重键含精确小推位置），预算 200 000 节点或 1 500 ms。
3. **参考解（最后后备）**：关卡数据自带一条最优解 `lurd`（校验器复核）。载入时把这条线经过的每个局面算出规范键存起来；求解超预算时，若当前局面在参考线上就按参考线给提示，否则提示"倒回到参考线上最近的那一步"（历史栈里从新到旧找第一个在参考线上的局面；开局一定在）。

**下一推怎么选**：在当前局面的所有合法推里，取 `togo(推后) = togo(现在) − 1` 的推（最优）；并列时选小推走路最短的；再并列按箱子编号、方向 上→右→下→左。图没好时用 A* 解的第一推。

**分级**（按 💡；两次按之间至少 4 s，按钮上有冷却环；他推了一下之后，下一次按重新从 H1 开始，但本关"用过的最高级"保留给星级和掌握统计）

| 级 | 触发 | 表现 | 语音 |
|---|---|---|---|
| H0 | 30 s 没有任何触摸（动画期间不计），或本关重来 ≥3 次，或本关出现 ≥3 次死局（两层都算），或本关已玩 5 分钟 | 💡 发光（kit `setHintReady`，两圈扩散 + 灯泡摆动），**不自动给提示**；他推一下或按 💡 后熄灭 | 无（只在第 0–1 章第一次发光时 `sok.hint.glow`"卡住了可以点小灯泡"） |
| H1 方向 | 第 1 次按 | 下一推要动的那个箱子外圈蓝色光环脉动 3 次（`--xg-info-500`，1.2 s），伙伴看向它 | 按情境三选一：`sok.hint.h1`"先动这个箱子"；这一推是把箱子从台上推下来 → `sok.hint.h1.unlock`"先把它从台上推下来"；这一推让箱子离最近同色台更远（停车）→ `sok.hint.h1.park`"先把它停到旁边" |
| H2 部分示范 | 第 2 次按 | 箱子上画推的方向箭头（蓝，粗 chevron），站位格出现两个履带脚印，小推到站位格的路线画成虚线点；持续到他下一次推或 8 s | `sok.hint.h2`"站在这里，往这边推" |

- **孪生题**（方案"H3 + 孪生"）：用过 H3 的关，结果卡多一个"镜子仓库"按钮 = 本关左右镜像（`mirrorRows`，校验 G7 保证最优推数相同）。镜子仓库独立计星、不影响原关；它不用 H2/H3 通过时，原关的"掌握"按通过计。

### 5.2 失败处理
- 学习模式**没有生命、计时、Game Over、"错"字**。撤销无限、重来可撤销（§3.4）。
- 死局用琥珀色 + 形状（✕ 徽章 + 虚线）+ 小推"挠头"表现，**从不用红色**（设计系统：红色只给家长区）；看不见的死局延迟提醒并给一键回退（§3.6）。
- **演示"为什么"**：每类死局第一次出现时伙伴说出名字；侦探题揭晓时演示"还能推"的箱子怎么推（§3.7）。
- **卡关**：每章永远同时开放 2 个没通过的关（相当于可以跳 1 关）；在同一关累计 8 分钟且下一关已开放时，伙伴**只问一次**：`sok.tip.skip`"要不要先试试下一关？等会儿再回来" + [去下一关] / [接着想]。
- **连续两关用了 H3**（同一章）→ 下一关开场伙伴说 `sok.tip.slow`"这关慢慢来，推之前先看一看"，并且这一关的 H0 发光阈值降到 20 s（方案"同一技能连错 2 次，降一档"在谜题里的落地：不改题目，只加脚手架）。

### 5.3 星级

### 5.4 掌握与家长页
- **干净通关**（clean）：这次通关过程中最高只用过 H1，并且没有点过"回到能推完的地方"。
- **章节掌握度** = 本章推箱关里有过干净通关的比例；≥70% 记为"掌握"（家长页显示，孩子看不到）。
- **家长页 3 个指标**（方案 §4.6 "每个游戏最多 3 个"；旁边注明"本游戏内部基准，没有外部常模"）：
  1. **独立通关率**：每章 首次进入就干净通关的关数 / 已玩关数；
  2. **提示使用**：每关平均最高提示级、H3 次数；
  3. **自救率**：死局事件里，他自己在 3 推之内撤回（没按 💡、没点回退按钮）的比例——"看出不对、自己改"的指标。
- 日志 marks 见 §8.8。

## 6. 美术（商业品质、不用图像生成器）

### 6.1 风格一句话
**"剪纸夜空里的切面货舱"**：俯视 3/4 斜角（顶面 + 正面厚度）的扁平矢量，暖纸色地板、深夜蓝墙体、奶油色纸边高光、琥珀色主角；整块仓库像一张剪纸立体模型悬在星港夜空里，外沿投下柔和纸片阴影。操作区内**没有装饰性动画**（设计系统规则），所有动都是有意义的反馈：走、推、锁定、死局、提示、发射。全部由代码绘制，零位图素材（夜空纹理用设计系统现成的 `paper-night.webp` / `scene-*.webp`）：所有形状以 **SVG 路径数据**（`d` 字符串，按 1 格 = 100 单位的坐标系写在 `src/render/shapes.ts`）定义，运行时用 `new Path2D(d)` + `ctx.scale(s/100)` 画到 Canvas；同一份路径也用于风格板导出 SVG、地图节点和机库大图（DOM `<svg>`），保证「一个图块一处定义」。参考：设计系统 `styleguide/screens.html?s=game`（纸面操作区 + 夜空外框）、原型 `research/proto/papercut.html`（剪纸层次与投影）。

### 6.3 棋盘几何与绘制（`src/render/board.ts`, `tiles.ts`）
- **投影**：每格 s×s 顶面；**墙**高 `hw = 0.32s`，顶面整体上移 hw，正面画在本格下沿往上 hw 的带里；**箱子**高 `hc = 0.20s`；**小推**高约 1.15s，脚在本格中心偏下 0.38s。画家算法：**逐行从上到下**，每行先画该行墙（顶 + 正面），再画该行的动态物体（箱子、小推、特效）；移动中的物体按 `max(起行, 终行)` 归行。这样南边（下方）的墙会正确地挡住北边物体的脚。
- **墙的自动拼接**（无图块集）：
  - 每个墙格算 4 邻掩码；顶面是 s×s 矩形，**凸角**（该角两侧邻格都不是墙）圆角 r = 0.18s，**凹角**补一个 r = 0.12s 的内圆角（用地板色在墙内侧画四分之一圆）。
  - 纸边高光只画在**外露边**（邻格不是墙的那条边）上。
  - 正面只在"下方邻格不是墙"时画；左右两端按掩码收成圆角。
  - 贴花：每个墙正面按 `hash(levelId, i) % 100` 决定：<15 通风格栅（3 条横缝）、15–22 舷窗灯（小圆 + LED 色点，静态）、22–30 章节贴花、其余素面。警示条只贴在与发射台相邻的墙正面。
- **地板**：每格两档棋盘色 + 右/下 1 px 缝 + 四角 4 个 1.5 px 螺栓（s ≥ 64 时才画螺栓）；发射台四周地板画 4 条黄黑短警示纹（0.12s 宽，α .5）。
- **外部（void）**：夜空纹理 + 每关确定性星点（`createRng('sokoban:'+id)`，密度 1/2500 px²，半径 0.6–1.4 px）+ 章节天体剪影（§6.2 表）；外沿纸片投影让仓库"浮起来"。
- **静态层缓存**：载入/转屏时把"夜空 + 地板 + 发射台底座"画到 `bg` 画布一次；墙按行预渲染到离屏画布（每行一张），动态帧只 `drawImage` 这些行图 + 画动态物体。
- **棋盘入场**（每关开始，§6.6）：地板按行从下往上弹入、墙从上落下、台亮、箱子落下、小推最后落下。

### 7.2 背景音乐
- 方案规则：**背景音乐只在菜单和庆祝时**，操作区只有反馈音效。
- 需要 1 首：**"星港夜班"**，用于货运图 / 机库 / 开场，60–90 s 无缝循环，♩≈84，五声音阶马林巴 + 柔和合成 pad + 轻刷鼓，响度 −23 LUFS（比音效低一档），kit `music.play(url, { volume: 0.45, fadeMs: 800 })`，进关卡淡出 400 ms。
- 来源（按顺序尝试，许可登记后再用）：① 设计系统管线合成（`build_sfx.py` 的音序器模式：五声音阶 4 小节 × 4 段 + pad，可控、零许可风险）；② OpenGameArt / Kenney Music 的 CC0 循环。**拿不到满意的就不放**——菜单静音也合格（DoD 不卡在 BGM 上）。
- 结果卡用设计系统 jingle（`level-complete` / `chapter-complete`），不另做。

### 8.2 PuzzleKit API（`@engines/puzzle`）

```ts
export type Dir = 0 | 1 | 2 | 3;                       // 上 下 左 右（与原型 DIRS 顺序一致）
export interface Level {
  id: string; W: number; H: number; N: number;
  wall: Uint8Array; floor: Uint8Array;                 // floor = 从小推起点泛洪
  goal: Int8Array;                                     // -1 无台；0..4 台色
  colorOf: Uint8Array;                                 // 槽 → 颜色（按颜色、位置排序）
  groups: [number, number][];                          // 同色槽区间（规范化时组内排序）
  start: { player: number; boxes: Uint16Array };
  dead: Record<number, Uint8Array>;                    // 每色简单死格
}
export interface State { player: number; boxes: Uint16Array }   // boxes 规范化（组内升序）
export interface Push { slot: number; from: number; to: number; dir: Dir; walk: number }
export function parseLevel(src: string | string[], id?: string): Level;      // 非法 → throw（G1 规则）
export function legalPushes(l: Level, s: State): { pushes: Push[]; dist: Int16Array };
export function applyPush(l: Level, s: State, p: Push): State;
export function isSolved(l: Level, boxes: Uint16Array): boolean;
export function walkPath(l: Level, s: State, to: number): number[] | null;  // 格序列（不含起点）
export function detectDeadlock(l: Level, boxes: Uint16Array): { type: 'corner' | 'wall' | 'pair' | 'square'; cells: number[] } | null;
export class StateGraph {                              // 全图预解
  static build(l: Level, o: { maxStates: number; maxMs: number; signal?: AbortSignal }): StateGraph | null;
  togo(s: State): number;                              // -1 = 推不完；-2 = 不在图里（不该发生）
  get size(): number;
}
export function solvePushOptimal(l: Level, from: State, b: { nodes: number; ms: number }): { pushes: Push[] } | { dead: true } | { unknown: true };
export function nextPush(l: Level, s: State, src: { graph?: StateGraph; reference?: string /*lurd*/ }): { push: Push; kind: 'normal' | 'unlock' | 'park' } | { rewind: true } | null;
export function mirror(rows: string[]): string[];
export function canonicalHash(rows: string[]): number;
export function generatePuzzle(tier: 1 | 2 | 3, seed: number, rooms: RoomSet, avoid: Set<number>): GeneratedLevel | null;
```
- 规范化：小推位置取可达区里格号最小的那格（与原型 `minReach` 一致），状态键 = `[player, ...boxes]` 打包成 Uint16。
- `StateGraph` 实现要求：开放寻址哈希（键 Uint16 段，容量 2 的幂，负载 ≤0.6），状态数组 `Uint16Array(cap × (1+nBoxes))`，前向边 CSR（`Int32Array`），反向 BFS 得 `Int16Array togo`；构建可被 `AbortSignal` 中断（切关时）；每 5 000 状态 `await` 一次让出（Worker 内仍能响应取消）。

### 8.3 数据格式
**地图字母**（与原型 `sokoban.mjs parse()` 完全一致）：`#` 墙；`-` 或空格 地面/外部（泛洪决定）；`@` 小推；`+` 小推在琥珀台上；`$` 琥珀箱；`.` 琥珀台；`*` 琥珀箱在台上；`A B C D` 颜色 1–4 的箱子；`a b c d` 颜色 1–4 的台；`1 2 3 4` 颜色箱在同色台上（仅内部使用）。

`content/sokoban/levels.json`（`tools/export-levels.mjs` 从原型导出；数字由校验器写入并在 CI 复核）：

```json

  "levels": [
    { "id": "2-6", "ch": 2, "track": "main", "role": "twist", "review": false,
      "name": "让一让", "teaches": "挡路的箱子先推到一边，等会儿再回来推它", "say": "sok.lv.2-6",
```

### 8.4 状态机
**应用（`router.ts`）**

```
BOOT ─▶ START_GATE ─(首次 tutorialDone=false)─▶ OPENING ─▶ PLAY(0-1)
              └─(否则)─▶ MAP
MAP ─节点─▶ PLAY | QUIZ ；─认证节点─▶ CERT_OFFER ─▶ PLAY(cert-1) ─▶ PLAY(cert-2) ─▶ MAP
MAP ─货单─▶ RANDOM_PICK ─▶ GENERATING ─▶ PLAY(rnd) ；MAP ─机库─▶ HANGAR ─▶ MAP
PLAY ─胜利─▶ LAUNCH ─▶ RESULT ─下一关─▶ PLAY ；─再来─▶ PLAY ；─镜子仓库─▶ PLAY(twin) ；─地图─▶ MAP
RESULT ─(收尾条件)─▶ WRAPUP ─▶ PLAY | 大厅
任意 ─🏠─▶ save → 大厅（kit shell.leave）
```
**一局（`session.ts` + `play.ts`）**

```
ENTER(入场动画, 输入锁) ─▶ IDLE
IDLE ─点地面─▶ WALKING ─到达─▶ IDLE
IDLE ─推─▶ PUSHING ─补间完─▶ (逻辑早已更新) ─▶ IDLE | LAUNCH
IDLE ─撤销─▶ REWINDING ─▶ IDLE         （长按：REWINDING 连续）
IDLE ─💡3─▶ DEMO(幽灵, 输入锁, 点击中止) ─▶ IDLE
任意 ─hidden─▶ PAUSED(补间瞬间完成) ─visible─▶ 原状态
叠加态：selected(箱子箭头)、deadMarks(✕ 列表)、stuckPrompt(第二层提醒)、hintGlow(H0)
```
逻辑状态（`State` + 历史栈）只在 `session.ts` 改；渲染层读快照 + 事件流（`{type:'walk'|'push'|'undo'|'restart'|'dead'|'solved', ...}`）排补间。

### 8.5 渲染方案
- **两张 `<canvas>`** 叠放在棋盘区：`bg`（夜空 + 地板 + 台底座，载入/转屏/换主题时画一次）和 `fg`（逐行：墙行图 → 箱子 → 小推 → 特效）。DPR 用设备值（2），画布尺寸 = 棋盘矩形 × 2；所有路径坐标乘 `s`。
- **只在变化时画**：有补间/粒子时 rAF 驱动；静止后停 rAF；小推待机用 12 fps `setTimeout` 只重画它所在的行带（`fg` 局部 `clearRect` + 重画该行墙与物体）；45 s 后进入"困"帧并停止定时器。页面隐藏时全部停。
- DOM：HUD、伙伴条、操作条、箭头命中区（透明按钮，供无障碍与测试选择器 `data-testid`）、提示箭头可以画在 `fg` 上。
- 结果卡、地图、机库都是 DOM（设计系统组件）。

### 9.2 机器人与模拟（完整版校验器内）
- **朴素小孩 k1 / k3**（`kid.mjs kidAttempt`）：每推按"离同色台曼哈顿距离变小"的 softmax（τ=0.45）选；不愿把已入位的箱子推下来；被检测器标 ✕ 的推会撤回（算 1 推）；看不见的死局认不出来；预算 2×opt+8 推。用途：`naiveMax` 断言（"有没有不动脑就能过的捷径"）。
- **学习者 L1**（`learnerAttempt`）：同上，但每一推以 q=0.6 的概率"想清楚"——在最优推里选。用途：预期首试通过率代理（B1、C6）、§4.2 表。
- **贪心机器人**（`greedy`）：反复把"离空台推数最少的那对 箱→台"一路推到底。用途：`greedy:'ok'/'fail'`。
- **顺序求解器**（`sequential`）：每个箱子只能连续推一段并且必须停在台上（不许停车）。用途：`seq:false`、`seqFirst:'only'`。
- **种子固定**：所有随机用 `mulberry32`，种子写死（k1 种子 11，L1 种子 13，各 400 次）；同一关同一份代码结果逐位相同（vitest 快照）。
