## 1. 立意、能力、证据

**立意**："**你的数学，养大一个会成长的伙伴。**"伙伴只对"做完"反应，不看速度和对错，不催、不因没来而难过。
- **间隔复习 / 提取练习**（B 级：Cepeda 2006；Dunlosky 2013，二手待核）：检修固定含到期复习；到期复习 ≤3 个游玩日内被服务：中等 10 / 15 分/天 94 / 95 %，弱 10 分/天 88 %，5 分/天 71–87 %。
- **认识人民币**：**v1.1** 开店（§7.2）。**内在动机**（争议：完成即得的有形奖励可能挤出内在动机，Deci 1999 待核）：奖励小而固定、无排行 / 连签 / 限时，加**测量 + 退出规则**（§2.7）。
**风险（诚实）**：养成最易滑向"为喂宠物而刷"→ 币只买外观 / 成长、不锁数学，点穿只教学；宠物抢数学时间 → 宠物舱里不能赚币；主线做完后赚币几乎全是检修（同一批 ≈30 个知识点的复习 + 拉伸），靠 X 和 v1.1 新区续航。

## 2. 经济

**2.1 原则**：①币只来自"做完一组"，数额在 `content/star-pets/economy.json`，**不随对错、速度、余额、时间、第几趟变**；②没有数学内容被币锁住（解锁、推荐、星、徽章、掌握都不读余额）；③买了的永远在，放回仓库 / 移动 / 试摆无惩罚；④币不过期、不衰减、**无每日 / 每趟 / 每分钟上限**；⑤宠物舱里不能赚币；⑥收尾卡显示数 = 入账数（E19）；价格全是 10 的倍数。

**2.2 入账（只有两个来源）**

| src | 星币 | 触发 | id（§3.2）|
|---|---|---|---|
| `mission.new` | **26** | 规划器给出的订单做完（校准、探针 + 节点、补救章、系统安排的第二遍）。26 = 原 24 + 折进来的里程碑 | `mn:<节点>:<第几遍>:<设备>` |
| `check.run` | **16** | 一趟设备检修做完（第 n 趟同额）| `ck:<设备>.<序号36>` |

**不付币**：孩子自己重玩（宠物照样反应）、一起验货、**验货单 / 徽章亮或半亮、掌握、Boss、知识卡、升档、基地升级、首次校准**（v1.0 的里程碑币 ≈727 全部取消）、币礼（改物品礼盒）。**没有"今日首趟"。**这些事件让宠物有**信息性反应**（灯泡、欢呼、才艺），不是赏金——mars-base 嵌入式验货的低压设计（§3.6）不被币污染。

**2.4 点穿保护 → 教学响应（不碰付币）**
- v1.0 的"降到保底 + 每分钟 6 币上限"整体删除。`economy.earn(src,{ref})` **没有时间 / 对错参数**（E12 单测）。信号只做三件事：①下一题切 build-first 或降一档；②这组结束后领航员一句"这几件货再核对一遍？"+ 两个等大键（核对 / 先放着）——选核对只重做被求助的 ≤3 题（带脚手架），**币已照常入账**；③家长页 +1"快的趟数"。
- **单题计时**（mars-base 现状 `activeMs` 声明了却从未累加）：`ItemTimer`（`app/engagement.ts`，纯函数）——题目亮起且可输入时开始；每个指针 / 键 / 计时事件先 `tick`；**示范演示时间扣除**；`visibilitychange` 隐藏期不计；**空闲每段最多计 45 秒**（同 `hint.idle`）；整题夹 120 秒；写进 `ItemResult.ms`。组统计 `{n,medianMs,ft,assistedShare,flagged}`（排除新元素前 2 题与被示范的题，**不足 6 题不判**）存 `kg:metrics:v1:star-pets` 最近 20 组（≈600 B）。单测：伪时钟 + 可见性。
- **判定（一条）**：`首试 <55 % 且 每题中位 < max(20 秒, 他自己"准确的组"中位的 60 %)`。基线只取他自己首试 ≥70 % 且未被判的最近 10 组（默认 30 秒）。准确又快的、慢而吃力的孩子都不会被判。
- **机器人**（`mash.mjs` 跑**真 UI 单题时间模型**：错答阶梯 3 次 + 对质演示 1 秒 + H3 幽灵手 7 秒；不预置"已被判"）：诚实强（快）/ 中 / 弱 **0 % 误判**；匆忙全靠提示的弱孩子 64 % 被判（付币不变）；H3 全按 / 快乱点 / 躲 v1.0 阈值的 12.5 秒 H3 全按 **100 % 被判**；**躲过 20 秒线**的（慢乱点：打字题仍要 ~20 秒的 H3 路；23 秒的 H3 全按 / 乱点）几乎不被判，赚 4.9–7.0 币/分 = 1.4–1.9× 诚实中等——**这就是无上限时诚实的上界**；重玩 / 验货循环 0 币/分。最坏 9.7 币/分（2.7×），9.5 小时刷完目录（诚实中等 12.5 小时）。真 UI 机器人（Playwright）是 P5 交付物；数字不对改 `economy.json`，不加上限。
- **"新内容价值递减"（替代 6 币/分上限）**：①自己重玩与验货**不付币**；②货架解锁靠**学习进度**（区做完 33 / 66 / 100 %、基地等级）而不靠币量——多赚的币只能买已解锁的；③检修只从遇到过的标签出题、过度掌握降权、永不引入新元素——刷检修换不来更快的新内容。

## 3. 账本契约（按 `sync.md` §8.4；`ledger.mjs` 是可运行参照，`vectors.json` 两边共用）

**3.1 存储**：键 `kg:v1:economy` = `{v:1, ledger:LedgerEvent[], pet:Record<键,字符串|null>, seen:string[]}`。**设备 id 与 Lamport 计数器归 `kit/clock`**（`kg:clock:v1 {dev,lc}`，安装时用墙钟**一次**播种 `lcSeed` ≤2^33，之后只靠 `max(本机,见过的)+1`；不导出；与 sync 是否开通无关）；`economy.dev` 删除。派生状态按账本修订号缓存。
**3.2 事件** `{id,d,lc,ts,kind,amount,src,ref}`：`id` 用共享 **`ID_RE=^[A-Za-z0-9:._-]{3,96}$`**（`kit/economy` 导出）；`d=^[A-Za-z0-9]{1,16}$`；`lc` 整数 0..2^40；**`ts` 仅展示，永不参与排序**；`kind ∈ earn|spend|grant`，`amount` 无符号 0..100000（`spend` 为减，0 合法）；`src≤32 ref≤48`；非法事件合并时丢弃并计数，不抛错；只增不改不删。

| 类 | id | 备注 |
|---|---|---|
| 本机普通（喂食 `feed`、庆典 `fest`）| `<d>.<lc36>` | lc 严格递增故唯一，**不含墙钟** |
| 确定性、**非**自然（订单 / 检修 / 购买）| `mn:<节点>:<第几遍>:<d>` · `ck:<d>.<序号36>` · `b:<物品>` | 游戏拥有（§3.6）；`b:<物品>` 让两台设备各买同一件**合成一条、只付一次**；同 id 异内容取较小 `(lc,d,JSON)` |
| **自然（规范事件）** `d:'n',lc:0,ts:0` | `egg:<线>` · `u:<规则>` · `g:<物品>`（免费 / 礼盒）· `retro:node:<节点>` | 内容查 `economy.json` 的表（金额只是 id 的函数）；两台设备产出**字节相同**的事件；CI 对每个内容 id 跑 |

v1.0 的 `m:` `d1:` `rf:` 不再存在（无里程碑币、首趟加成、退货）。`src/ref`：`earn`：`mission.new` `check.run`；`spend`：`buy`(`item:<id>`) `feed`(`<线>:<食物>:<成长>`) `fest`；`grant`：`egg` `unlock`(`shelf:<规则>`) `free|gift`(`item:<id>`) `retro`。
**3.3 折叠与显示**：按 **`(lc,d,id)`** 排序折叠 `b←max(0,b±amount)`；`balance` 与被原谅的透支 `forgiven` 是**事件集合的纯函数**，与到达顺序 / 重复 / 批次无关。两台设备同时花同一笔 → 透支原谅为 0（两件都留，什么都不收回）。**显示余额只在安全点变化**：远端事件先入收件箱，只在页面打开、回到房间 / 地图、购买动画结束后并入；确认面板与币计数进行中**绝不变**；本机新事件 `lc` 最大、**立刻全额可见**；购买前校验本机余额 ≥ 价；**购买以事件呈现**（币飞出与那条 `spend` 同步）。显示余额**只会因他自己花币而下降**，一次并入降幅 ≤ 该批 `spend` 之和（1,500 次检查，最大降幅 224）。
**3.4 派生状态**（纯函数）：`owned` = `spend(buy,item:X)` 或 `grant(free|gift,item:X)`；`growth(线)` = 该线 `feed` 事件 `ref` 里**存下的成长数**之和（以后调表不让既有宠物倒退，E18）；`pets` = `egg` 事件；`unlocked` = `unlock` 事件；订单 / 检修数 = `earn` 事件数。
**3.5 `pet` 映射**：`Record<键,值|null>`（null=删除），**没有墙钟 `t`**；戳 `[lc,d]` 由 sync 层盖（sync §4.1：map·L）。键：`name:<线>`（≤4 字）· `slot:<房间>:<位置>` · `wear:<线>` · `paint:<线>` · `tint` · `active` · `goal` · `gift:<物品>`（≤16 字）；≤300 条、值 ≤64 B。**同一物品出现在两个位置**：渲染取固定位置顺序**第一个**，其余空着，下次写入顺手把失败者写成 null（幂等）；未拥有 / 种类不符的条目不画也**不**清除（购买事件可能还在路上）。方案存档 → v1.1。
**3.6 奖励事务（幂等、可崩溃）**：①确定性 id；②`endMission()` 在**同一次** `saveNow()` 里 `plays++`、把 `{id,kind,amount,src,ref}` 推入 `save.eco.pending[]`、清 `save.mission`；③`economy.flush(pending)` 逐条"读盘→与内存取并集→写盘→回读校验"，**id 已在就跳过**，成功后从 `pending` 删除再存；④开机、每次 `saveNow` 后、回前台都 `flush`；⑤`runNode / runWall / startCheck` 带**忙锁**（双击只开一个运行器）；⑥`daily.runSeq` 与"清 `daily.run`"同一次写入。**写盘失败**：事件留内存并置 `unsaved`，家长页顶部横幅"这台设备没存上进度"，下次写入带上全部；购买没写成 = 币还在孩子手里（失败落在安全一侧）。**两个标签页**：写前总读盘取并集。
**3.7 导入 / 清除**：`importProgress` 对 `kg:v1:economy` **永远取并集**（文件里的 `dev/lc` 忽略），在 `kit/progress.ts` 实现并测（现状会覆盖同版本键，**必须先于星币上线**）；无"清空账本"；游戏进度重置不触及账本。
**3.8 迁移追补（v5→v6）**：首次载入对 v5 里已完成的主线节点各发一条 `retro:node:<id>`（自然、规范，**12 币**；28 节点 = 336 币），只对**本机迁移前**进度、**先于**收件箱并入；两台设备迁同一份存档只付一次，与实时 `mn:` 不同 id 但不会对同一次游玩双付；追补发了币则蛋在首次载入出现。仿真起步 144 / 336 币全绿。
**3.9 与 sync 对账（D5 关闭）**：排序 `(lc,d,id)` · `d/lc` 由 `kit/clock` 盖 · 无符号 `amount`+`kind`、无 `adjust` · id 3–96 同源 `ID_RE` · 命名空间归本规格 · 设备 id 只有 `kit/clock` 一份 · 单事件 ≈117 B（≤130 B；一年 ≈250 KB）· `pet` = map·L、`seen` = U · 云端**不得**校验金额 · `importProgress` 并集。**共用向量** `vectors.json`（id 23、lcSeed 7、自然 17、折叠 7、并集 3、安全点 2、成长、房间）：本目录 + `../sync-tools/ledger.mjs` **两个实现 120 条断言一致**；双向清单 L1–L8 共用编号。

## 10. 美术、音频、旁白（诚实重数）

**10.1 美术（全部代码绘制，星港剪纸风，无位图）**：宠物是**参数化 SVG**，共享骨架 6 个部件（身体 / 头 / 眼 / 耳或天线 / 尾或翼 / 底座），每形态 ≤36 path；**一律滚动 / 悬浮 / 跳，无走路循环**。重数：**8 个角色**（6 形态 + 2 蛋）；5 心情 × 6 = 30 个脸态（参数）；**25 套动画** = 通用 12 + 每线特色 2×2 + 孵化 2 + 进化 1 + 学习反应 2 + 才艺 4，按形态调 `transform-origin`，做成**每形态一张参数表**；服装拟合 12 个锚点；装饰 24 件（≤18 path）+ 4 张外景（≤40 path，带活景循环）+ 8 个点触关键帧。渲染 **DOM + 内联 SVG**；**静止同时动画的元素 ≤12**；reduced-motion ×0.5 且无粒子；用 `--mb-*` / `--xg-*` 令牌。
**10.2 原型门 G0（P3 开工前）**：**WebKit 对内联 SVG 内部元素的 CSS transform 动画通常不进合成层（主线程重绘）**，Chromium 4× 降速测不到。先做抛弃式页面：15 位全摆满、1 只宠物同时跑 5 个动画、进化场景含 40 个粒子，**在爸爸的 iPad 9（A13）上**读页面内置计数器。通过：拖动 / 孵化 / 进化 ≥50 fps；首绘 ≤150 ms；静置 10 秒长任务（>50 ms）≤2 个；机身 10 分钟不烫。失败预案：只给 HTML 包装层做 `transform`，内部换脸用显隐；仍不行则预渲染成 CSS 精灵图。**与风格门同一次试玩做。**
**10.3 音效与旁白**：音效全合成 ≈12（币叮、购买、嚼、裂壳、进化、摆放、拿走、蹭、两线叫声、庆典），每个 ≤400 ms，走 kit 总线；**点开始页前无声、静止无声、无提醒音**；叫声让位于领航员语音。旁白 **≈85** = 句 45（检修 6 · 引导 10 · 学习反应 10 · 孵化 / 进化 / 取名 8 · 购买 / 目标 5 · 礼盒 3 · 迎接 3）+ 点读名 40；依赖 mars-base 那条尚未跑通的 TTS 管线，**点读名可延到 v1.1**；只用 ffprobe / ASR 检查，**从不外放**。**P3 伙伴 5–6 会话**（v1.0 的 4 个不现实：mars-base 同类 41 会话、4 个构建会话后就砍了三区与配音）。
