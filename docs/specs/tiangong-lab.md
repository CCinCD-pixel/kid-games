**术语**
- **实验室**（lab）：一个科学主题，有 6 个完整的加 3 个大纲。
- **单元 A / 单元 B**（unit）：每次约 10 分钟 / 约 8 分钟的会话。
- **预测**（prediction）：POE 里的 P。不评对错，只记录。
- **探针**（probe）：带"概念标签"的预测题或委托题，用来统计"第二次遇到同类题时有没有进步"（§5.4）。
- **反直觉题**（counter）：大多数 6 岁孩子会猜错的题，单独统计正确率。
- **挑战**（challenge）：单元 B 的 5 关手作关，有星级。
- **委托**（commission）：生成器出的短题，每组 5 题。
- **格 / 份**：乌鸦瓶的刻度单位。1 份水能让细瓶的水面升 1 格。
- **斤**：曹冲实验室的质量单位。课本里用克和千克（二下），故事和集市里用斤；家长页注明 1 斤 = 500 克。
- **主坐标**：实验台舞台的 viewBox 是 720×640；故事插画按 1600×1200（4:3）设计。

## 1. 定位、玩家幻想、立意、能力目标、课标锚点、证据等级

### 1.1 玩家幻想
> 我是天宫空间站的"小小载荷专家"。空间站上有一排实验舱，每个舱门后面都是一个从古代传下来的老问题：乌鸦怎么喝到瓶底的水？铁牛沉进河底，怎么捞上来？大象太重，怎么称？
> 我先猜，把猜的锁住，再动手做实验。猜错了，就是发现了一件意外的事。做完的实验舱会接到空间站上。委托板上，乌鸦、曹冲和鼓车师傅还会不停地来找我帮忙。

"载荷专家"是真实的中国航天员岗位：2023 年神舟十六号的桂海潮是第一位载荷专家（见 §4.9 事实核对 F-01）。

### 1.2 立意（给爸爸看，不对孩子说教）
1. **科学是"先猜，再验"。** 猜错是发现，不是失败。界面上永远不出现"错"字；猜得和结果不一样，就盖一个"意外发现"章。
2. **古人的聪明 + 今天的航天。** 每个实验都从一个中国故事出发，在"天宫卡"里落到今天的空间站。
3. **把实验带回家。** 每个实验室都有一张用家里东西就能做的回家卡，由爸爸带着做。这是证据等级从 C 往上提的唯一办法（§1.5）。

### 1.4 课标与教材锚点
**以孩子手里的课本为准。** 他 2026 年秋入学，用的是 2024 年起逐册替换的新版统编教材。语文一上已核（见下）；数学册次按人教版现行目录写，二年级的册次等拿到课本再核一次（D4）。

**《义务教育科学课程标准（2022 年版）》**
- 第一学段（1–2 年级）：
  - 观察、比较物体的外部特征和材料，包括轻重、软硬、沉浮的现象；
  - 磁铁能吸引铁一类的物体；
  - 太阳东升西落，影子会变化；
  - 用简单的工具做测量和记录。
- 超前到第二、三学段的内容：
  - 公平测试（控制变量）；
  - 物体在水中的沉浮和材料、形状有关；
  - 简单电路（闭合回路、开关、串联，**并联是 4 年级以上**）；
  - 杠杆和天平；
  - 齿轮传动；
  - 月相（3 年级以后）。

**数学（人教版）**
- 一下：分类与整理（简单的统计表和统计图）；100 以内数的认识；100 以内的加减。
- 二上：100 以内的加减法（二）；表内乘法（齿数比的直觉）。
- 二下：数据收集整理（画"正"字）；万以内数的认识（千）；克和千克。
- 三上：测量（吨）。

**语文（统编版）**
- 一上（2024 新版）第八单元第 9 课《乌鸦喝水》（已核，F-02）。这个单元大约在 12 月学。他 10 月就能玩到实验室 ①，所以是"先做实验、后学课文"：课文学到时，家长卡提醒爸爸问一句"你在天宫实验室里做过这个实验，还记得沙子吗？"。
- 二上《曹冲称象》（旧版在第三单元；2025 新版的位置待孩子升二年级时核，F-08）。实验室 ③ 比课文早一年，故事页按《三国志》原文写，不照搬课文措辞。

**超前点（明示）**
- 公平测试；
- 天平规则 2（重量相同时看距离）；
- 并联；
- 3200 斤的累加（千位）；
- "同样大的水"作为密度的直觉表述。

所有超前点都有 H1–H3 提示托底，答错只会降一档，不会卡住进度。

### 1.5 证据等级（如实写进家长页）
- **总体：C**。屏幕科学游戏迁移到真实推理的证据有限，所以靠回家卡和爸爸的对话卡把它往 C+ 提。
- **"先探索、后讲解"的顺序：B**。Bonawitz 等 2011（*Cognition*，研究对象是学前儿童，约 4–5 岁）发现，大人先演示会让孩子只探索被教的那个功能。本作的解释卡只在探索之后出现。
- **天平规则序列：B+**。Siegler 的天平规则评估（被试 5–17 岁）显示，5 岁左右多是规则 1，9 岁左右多到规则 2/3。本作评分只到规则 2；规则 3、4 只观察，不评分。
- **控制变量教学：B**，但年龄是超前的。Chen & Klahr 1999（*Child Development*，2–4 年级）发现，明确讲解再配对比实验有效。本作在挑选物品对之后，用属性标签明示"哪里不一样"。
- **间隔练习：B**。Vlach & Sandhofer 2012（*Child Development*，研究对象是幼儿；被试年龄待核对）发现，科学概念分散学习的泛化更好。本作的委托按会话次数间隔复现探针。

## 3. 核心循环与规则

### 3.1 三种会话

| 会话 | 时长 | 结构 | 结束 |
|---|---|---|---|
| 单元 A「做实验」 | 约 10 分钟 | 故事 → [预测 → 锁定 → 探索 → 对照]（每个实验室 3 轮；其中一轮之后接"解释"，位置由各实验室 JSON 的 `explainAfter` 指定：乌鸦、沉浮、齿轮、电路在第 1 轮后，曹冲、天平在第 2 轮后）→ 笔记 | 收尾卡 A，加一张"讲给爸爸听"对话卡 |
| 单元 B「挑战」 | 约 8 分钟 | 5 关挑战（挑战条上的节点可以自由选，默认按顺序）→ 回家卡 → 天宫卡 | 收尾卡 B |
| 委托 | 约 5 分钟 | 一组 5 题（§3.5） | 收尾卡 C |

- 单元 A 做完，才开放单元 B 和下一个实验室的舱门。
- 单元 B 第一次做完，才开放委托。
- 之后所有会话都可以随时重复。重复单元 A 时跳过故事，可以从故事页的「再听故事」按钮进入；预测题照常锁定，但只把第一次作答计为"首次接触"，后面的作答计为"再次接触"。

### 3.2 POE 状态机（LabKit `poe.ts`，所有实验室共用）

```
Idle ─start(round)→ Ask ─pick(choice)→ Locked ─(auto 400ms)→ Explore
Explore ─[mustTry 全部完成 且 (动作数≥3 或 自首个动作起≥20s)]→ ExploreDone（出现「我发现了！」按钮，脉动）
ExploreDone ─tap「我发现了！」→ Compare ─(auto 1.6s 或 点击)→ (本轮有解释? Explain : Next)
Explain ─pick(card)─┬ 正确 → ExplainOk → Next
                    └ 不对 → Replay（重放这一轮的关键片段 ≤6s）→ Explain（重新选，另一张卡依然在）
Next → 下一轮 Ask | 本单元结束 → NoteStamp → EndCard
```

**规则**
1. **锁定不可改。** 锁定后预测卡翻面，盖章并缩到舞台角上（显示"我猜：↑"）。离开再回来，锁定的选择仍然有效，从 Explore 重新开始；舞台复位，但已完成的 mustTry 保留。
2. **mustTry 是每轮 1–2 个必须做的动作**（定义见各实验室，例如"至少放一颗石子"）。没做完之前不出现「我发现了！」。孩子可以无限探索，不催。45 秒没点「我发现了！」时，伙伴说 `tg.explore.found`（H0 级）。
3. **对照**：分屏显示「我猜」和「真的」两张小卡。
   - 一致：盖 ✓ 章，音效 `correct`；
   - 不一致：盖"意外发现"章，音效 `jingle-magic`，伙伴用 surprised 表情。**绝不出现"错"字**，也不用红色。
   - 如果这道题是反直觉题，第一次出现"意外发现"时，发一张发现卡（§5.5）。
4. **解释卡**：两张，一张对，一张是常见误解。
   - 选错：不扣分，进入 Replay，重新选。
   - 用了 H3（直接揭示）的，这道解释不计入掌握。
5. **预测从不给提示。** 猜什么都可以，这里只有 H0：30 秒没选，伙伴重读一遍问题，卡片轻轻晃一下。
6. **每次预测都写一条 `ProbeRecord`**：`{ probe, lab, item, first: boolean, choice, correct, ts, session }`。

### 3.3 实验台通用交互（LabKit `bench.ts`）
- **拖放**：从托盘按住物件，物件放大到 1.12 倍并带阴影，音效 `ui-pick`。拖到落点区（drop zone，命中半径 = 区域 + 24 单位）松手：吸附，音效 `ui-snap`。在区域外松手：240ms 飞回托盘。只认第一个手指（kit `PrimaryPointer`）。
- **点选替代**：点托盘物件选中（金色描边），再点落点区，等同于拖放。
- **撤销 / 重来**：每个状态都能撤销一步，撤销栈 ≤50 步；「重来」恢复到本轮开始的状态。模型状态每次都从动作列表重新计算，不做增量修改，所以撤销是精确的。
- **动画期间**：模型立刻更新，动画按队列播放。连续快速投放时，每个动画压缩到 ≤150ms，最终画面总和模型一致。乌鸦喝水、鸡蛋上浮这类庆祝动画播放的 1.2 秒内锁住输入，锁住时出现半透明遮罩，不让孩子以为点了没反应。
- **方向切换**：舞台 viewBox 不变，只重新计算 k，状态不丢。
- **切到后台**：kit shell 暂停，rAF 停止，计时冻结；回来时恢复。
- **静音**：所有指令都有字幕，结果都有动画，静音也能完整玩。

### 3.4 挑战（单元 B）通用规则
- 每关开始时显示目标横幅（图示 + ≤12 字）和伙伴的一句旁白。
- 有些挑战开始前有一道"小预测"，比如 crow.c4"哪个瓶子水升得多？"。它走 POE 状态机，但没有解释环节。
- 判定一律由模型完成（§4 各实验室）。达成目标时，结果面板用 kit/ui `showResult` 显示星星，星星依次弹出，音效 `star-1/2/3`。
- 没达成目标，不叫失败：用模型说明"还差多少"（比如水停在 13 格、红线在 15 格，就显示一个"还差 2 格"的标尺），然后给「再试一次」（保留当前状态）或「重来」。
- 星级阈值在 §4 的各实验室表里，全部由原型求解器算出。总规则（总方案 §3.0）：1★ 达成，2★ 达到效率标准，3★ 最优且没用 H3。**星星只影响收藏里的"满星徽章"，不卡任何进度。**

### 3.5 委托（commission）规则
- **委托板**是一块软木板，上面钉着 5 张纸卡，每张写着委托人（乌鸦、怀丙、曹冲、爷爷、鼓车师傅、领航员）和一句话。孩子按顺序做，也可以点任意一张先做；做完的卡盖章。
- **出题**：`gen(type, level, seed)`（§8.4）。
  - 种子 `tiangong:${type}:${level}:${seed}`，seed 是每个实验室各自递增的计数器，存在存档里。
  - 每个实验室保存最近 50 道题的 key，重复就 seed+1，最多跳 10 次。
- **一组 5 题的构成**（每个实验室有当前级别 ℓ ∈ 1..5）：
  1. 题型从 ℓ 可用的题型里抽（§4 各实验室的"委托题型"表）。按探针弱项加权：权重 = 1 + 2 × (1 − 该探针最近 10 次的首试正确率)。
  2. 每组至少 1 道反直觉题型或交错复习题；第 3 章以后的交错原则（总方案 §3.0）在这里体现为 20%：5 题里 1 题来自另一个已完成的实验室。
  3. 同一题型不连出 3 次。
- **自适应**：
  - 在 ℓ 级连续 3 次首试正确 → ℓ+1（最高 5）。
  - 同一探针连续 2 次没对 → ℓ−1（最低 1），并且下一题插入一道同题型的孪生题（同一题型、低一级、新种子）。
  - 一组 5 题的首试正确率连续两组 >95% → 可以跳一级。低于 60% → 降一级。
- **作答方式**：
  - 选项题：3 个大按钮 200×120（横屏 260×110），选项顺序由生成器打乱。
  - 数值题：用设计系统的数字键盘 `mountKeypad(el, { maxLength: 4, onSubmit })`（默认 maxLength 是 3，3200 需要 4 位），键 76px；`onSubmit` 返回 `false` 时键盘只轻轻晃一下（设计系统内置，不出现"错"）。elephant.sum 和 L4–L5 的 elephant.read 用键盘。
  - 搭建题：在实验台上做，判定交给模型。
- **答错**：
  - 第一次：用模型演示原因（比如把 n 颗石子放进去，水停在哪里），然后再答。第二次答对，不计首试正确。
  - 第二次还没对：给 H3，展示答案和过程，然后出一道孪生题。
- **一组结束**：收尾卡 C 显示"完成 5 个委托"和本组的计数表（正字），不显示分数。

### 3.6 边界情况（全实验室共用）

| 情况 | 处理 |
|---|---|
| 多指同时触摸 | 只认第一个指针，其余忽略（kit input） |
| 拖动中途切到后台或旋转屏幕 | 取消这次拖动，物件回到托盘，模型不变 |
| 动画中途点「撤销」 | 立刻跳到撤销后的最终画面，排队中的动画清空 |
| 预测锁定后离开，从未探索 | 存档 `round.locked=true`。回来直接进 Explore，不再问 |
| 单元 A 做到一半离开 | 存到当前轮的 Ask/Explore 起点。已完成的轮次和笔记保留 |
| 挑战做到一半离开 | 不保存关内状态，下次重新开始这一关（每关 <2 分钟）。已拿到的星星保留 |
| 委托做到一半离开 | 已完成的题计入；未完成的题，下次用同一个 seed 重新出 |
| 生成器 200 次尝试都失败 | seed+1 重试，最多 10 次。全部失败就换同实验室的另一种题型，并在日志记一条 `gen.fail`。CI 保证接受率 ≥99.5%（§9.1） |
| 存档损坏或版本更高 | kit/progress 的 envelope 解析失败 → 用默认值，并把旧数据备份到 `kg:v1:tiangong-lab:corrupt:<ts>` |
| localStorage 不可用（隐私模式） | 照常游玩，存档只放在内存里；家长页提示"本次进度不会保存" |
| 音频没解锁（没点开始页） | 旁白排队，等开始页被点。kit 的开始页一定会出现 |
| 首次打开横屏和竖屏 | 都支持，不提示旋转 |
| 孩子长时间不动（>3 分钟） | 伙伴切到 sleepy 表情（不是难过），轻轻呼吸。任何触摸都会唤醒；不弹窗，也不会自动退出 |

### 4.1 实验室 ① 乌鸦喝水 `crow`

#### 4.1.1 开场故事（剪纸，3 页）

| 页 | 画面（1600×1200，下方 18% 只放地面和水面） | 正文（纸带） |

| 2 | 院子里一个细长的陶瓶，瓶身开一个"透视窗"，能看见瓶底一点水。乌鸦站在瓶口低头，嘴够不着水，用一条虚线标出差距 | 瓶子里有水，可是水太少，它喝不着。 |
| 3 | 地上散着许多小石子。乌鸦歪头看，头顶一个剪纸问号 | 旁边有许多小石子。乌鸦有办法了吗？ |

交接旁白（伙伴）：`tg.crow.handoff`"我们实验室里也有一样的瓶子。来，帮乌鸦想办法！"

#### 4.1.2 模型 `model/crow.ts`（原型见 `models.mjs` 的 `crowLevel`）
- **单位**：体积以"份 ×100"存成整数；高度以"格"为单位。瓶子横截面积 A ∈ {1（细瓶）, 2（粗瓶）} 份/格，瓶高 H（格），水量 W（份 ×100）。
- **物件表**

| id | 名称 | 看起来多大（份） | 计入水位的体积（份） | 行为 |
|---|---|---|---|---|
| `stone_s` | 小石子 | 1 | 1 | 沉 |
| `stone_l` | 大石子 | 3 | 3 | 沉 |
| `sand` | 一勺沙 | 1 | 0.6（干沙颗粒间约 40% 是空气） | 沉，冒气泡 |
| `sponge` | 海绵 | 2 | 0.2（固体部分） | 吸水 1.6 份；拿出来时带走这 1.6 份 |
| `wood` | 小木块 | 2 | 1（ρ=0.5，排开的水重等于自身重量） | 浮 |
| `ice` | 冰块 | 2 | 1.84（ρ=0.92） | 浮；融化后变成 1.84 份水，水位**不变** |
| `pingpong` | 乒乓球 | 2 | 0.16（ρ≈0.08） | 浮 |

- **水位**：
  - 记 S = 沉物（石子、沙）的固体体积和，Sp = 海绵的固体体积和，F = 浮物排开的体积和。
  - `hA = W + S + Sp + F`，水位 `h = hA / (100·A)`。
- **石堆露出水面**：
  - 石堆的堆积密实度 φ=0.6，所以石堆高 = S/(0.6A)。
  - 如果 `3·hA < 5·S`（水位低于石堆顶），水只能填进石缝：`hA = 5W/2`，浮物搁浅，不再计入。
  - 这种情况只在沙盒里出现（例：W=4 格，8 颗大石子 → 水位停在 10 格）。出现时伙伴说 `tg.crow.pileout`，并发一张发现卡。
  - 评分题由生成器保证石堆始终在水下（§4.1.5 拒收规则 R-crow-1）。
- **溢出**：`hA > H·100·A` 时，溢出量 = 差值，W 相应减少，水位 = H。乌鸦照样能喝到水；但"正好到线"的关卡要求不能溢出。
- **乌鸦喝到水** ⇔ `hA ≥ line·100·A`。
- **参考值**（W=10 格，细瓶）：
  - 小石子 0–4 颗 → 10/11/12/13/14；
  - 一勺沙 → 10.6；
  - 海绵放进去 → 10.2，拿出来 → 8.4；
  - 冰 → 11.84，融化后仍是 11.84；
  - 木块 → 11。

- **橡皮泥船**：
  - 30 g 橡皮泥（ρ=1.6，体积 18.75 cm³），方底边长 s，船帮高 w（cm）。

  - 船体容积 `V_h = s²·w`。空船能浮 ⇔ `V_h > 30`。
  - 能装的弹珠数 `cap = ⌊(V_h − 30)/5⌋`（弹珠 5 g）。

| s \ w | 1 | 1.5 | 2 |
|---|---|---|---|
| 5 | 沉（空船也沉） | 1 | 4 |
| 6 | 1 | 4 | **8** |
| 7 | 3 | **8** | 漏 |

- **救生衣（浮具）**：物体 (m_o, V_o) 绑上 n 个浮具 (m_a, V_a)，浮起来的条件是 `(m_o + n·m_a) < (V_o + n·V_a)·1.0`。最少个数 `n = ⌊(m_o − V_o)/(V_a − m_a)⌋ + 1`；如果 m_o < V_o，n = 0。

#### 4.3.2 模型 `model/elephant.ts`
- **吃水**：船帮是竖直的，所以吃水深度 `d = d0 + M/(ρ·A_wp)`，和质量成正比，和东西的材料、体积无关。舞台上每隔 k 斤画一道刻度：`mark = M/k`。
- **等量替换**：吃水相同 ⇔ 质量相同（A_wp 抵消）。替换阶段允许的误差为 0，因为石块组合由关卡或生成器保证能正好凑出。
- **分批称**：秤的量程是 C。一批石块的总重 ≤ C 才能称；超过时指针停在最大值，显示"太重了"图标，不会弄坏秤。
  - 最少批数 = 装箱问题的最优解（原型 `minBatches`，子集 DP，n ≤ 10）。
- **吃水线显示**：差值 Δ = 装载质量 − 目标质量。
  - Δ < 0：水线在标记下方，显示"还差一点"（向下小箭头）；
  - Δ > 0：显示"多了"；
  - Δ = 0：标记线闪金光，音效 `lock-in`。
  - 船的下沉量按 `Δ/k` 格成比例显示。

#### 4.4.2 模型 `model/balance.ts`

  - 力矩 `τ = Σ w·d`。τ左 > τ右 → 左边下去（`L`）；相等 → 平（`B`）；否则右边下去（`R`）。
  - 动画：倾角 ±12°，用 `--xg-ease-spring`，约 1.0 秒停稳。
  - 预测题里梁被"支撑木"托平，点「放手」后才倾斜。沙盒里实时倾斜。
- **Siegler 题型**（单堆对单堆）：
  - `balance`：重量、距离都相同；
  - `weight`：距离相同；
  - `distance`：重量相同；
  - `conflict-*`：重量和距离都不同。
  - **评分题只用前三类**。冲突类只在沙盒里作为"意外发现"出现（`disc.balance.conflict`："远处 1 块，顶住了近处 2 块！"）。
- **规则机器人**：
  - 规则 1 只看重量；
  - 规则 2 先看重量，重量相同时再看距离；
  - 规则 4 就是力矩。
  - 在前三类题上，规则 2 和力矩的答案完全一致，这保证评分题用规则 2 就能全对。
- **杆秤**：
  - 秤钩在提纽左侧 a=1 处，秤砣质量为 m_c，放在提纽右侧 x 处。
  - 水平条件 `M·a = m_c·x`。定盘星 x0=0，画在提纽右边一点，表示"零"。
  - 小秤：m_c=1 斤，刻度 0–10 斤，每格 1 斤。大秤：m_c=5 斤，刻度 0–50 斤，每格 5 斤。
  - 秤砣吸附在整数刻度上。x ≠ M·a/m_c 时，秤杆向力矩大的一侧倾斜，倾角 = clamp(4°·|M·a − m_c·x|, 0, 10°)。

#### 4.5.2 模型 `model/gears.ts`（原型 `gearSim` / `gearRun`）
- **钉板**：整数网格，1 格 = 40 个 viewBox 单位。
- **齿轮**：S 半径 1 格、10 齿；M 半径 2 格、20 齿；L 半径 3 格、30 齿。半径按节圆算，齿顶多画 0.12 格。
- **双联齿轮**：`D_MS`（后层 M + 前层 S）和 `D_LS`（后层 L + 前层 S），同轴，角速度相同。
- **层**：钉分"矮柱"（h=0）和"高柱"（h=1，画得更高，带一圈铜环）。
  - 单个齿轮放在它那根柱子对应的层上；双联齿轮同时占 0、1 两层。
  - 柱子的销钉贯穿第 0 层到 top 层（高柱，或者装着双联齿轮的柱子，top=1；否则 top=0）。
- **咬合与碰撞**（只在同一层判定）：
  - 圆心距² = (r1+r2)² → 咬合；
  - 圆心距² < (r1+r2)² → 碰撞，这一步非法：齿轮红色描边，播 `bump`，弹回托盘；
  - 齿轮盘面盖住另一根有齿轮的销钉（d < r，且层 ≤ 那根销钉的 top）→ 同样算碰撞。
- **转动**：
  - 摇把所在的齿轮 ω=+1（顺时针为正，单位是圈/摇把圈）。
  - 咬合传递：`ω2 = −ω1·N1/N2`；同轴：ω 相等。用 BFS 传播，全部用精确有理数。
  - 一个连通块里出现矛盾 → **卡死**，整个连通块 ω=0。卡死时摇把只能转 5°，然后抖 3 下（每下 60ms），出现"卡住"图标。
  - 奇数个齿轮围成一圈必然卡死；偶数圈不会。
- **输出**：输出柱上那根轴的 ω。指针表盘显示方向和圈数，计圈器取整显示。
- **摇把操作**：
  - 拖着把手绕圈：累计角度，方向由叉积符号决定，只认第一个指针；
  - 或者按住「转」按钮：每秒 0.5 圈，顺时针。
  - 带计圈器的齿轮上画一个白色标记箭头。

#### 4.6.2 模型 `model/circuit.ts`（原型 `circuitSolve`）
- **网格**：节点 `c,r`，间距 150 个 viewBox 单位（4×3 个节点占 450×300）。每条单位边上最多放一个元件。
- **元件**：
  - 导线、闭合的开关：0 Ω。
  - 小灯泡、小电机：1 Ω。
  - 电池：理想电压源，1 V，负极 → 正极。电池上画"+"和"−"，不只靠颜色区分。
  - 断开的开关、拧下的灯泡：断路。
- **求解**：
  1. 用并查集把 0 Ω 的边合并成超节点。
  2. 电池两极落在同一个超节点里 → **短路**：所有灯熄灭，电池泛橙红色的光，出现"烫"图标和 3 颗柔和的火花；伙伴说 `tg.circuit.short`。
  3. 否则，在电池所在的连通块上做节点分析：负极电位 0、正极 1，其余节点按 KCL 列方程，用精确有理数高斯消元求解。
  4. 每个灯泡的电流 `I = V_a − V_b`。**亮 ⇔ I ≠ 0**；亮度 `P = I²`。
- **亮度显示**：光晕半径 = 18 + 42·√P（单位），不透明度 0.35 + 0.65·√P。用径向渐变，不用 blur 滤镜。
  - 1 盏灯 P=1；2 盏串联各 0.25；3 盏串联各 0.11（很暗但亮着）；2 盏并联各 1。
  - 灯泡被一根导线绕过时 I=0，熄灭，而另一盏灯从 0.25 变成 1（更亮）。
- **电机**（只在沙盒里有）：转向 = sign(I)。电池反过来，风扇就倒转。
- **电流动画**：亮着的回路上，小光点沿导线流动，速度正比于 |I|，用 `stroke-dashoffset` 实现，1.2 秒一个循环。短路时不播电流动画（避免误导），只显示电池发烫。

#### ⑧ 太阳与影子 `shadow`（3D，VoxelKit）
- **模型**：
  - 太阳赤纬 `δ = 23.44°·sin(2π(284+n)/365)`；
  - 时角 `H = 15°·(t_solar − 12)`；
  - 高度角 `sin h = sinφ·sinδ + cosφ·cosδ·cosH`；
  - 方位角 `cos A = (sinδ − sin h·sinφ)/(cos h·cosφ)`，下午取 360°−A；
  - 影长 `L = 杆高 / tan h`，影子方向 = 太阳方位角 + 180°。
  - 纬度 φ 由家长设置（默认北纬 30°），不读定位。时间用当地太阳时（不做时差和均时差修正，家长页注明）。
  - **黄金值**（φ=30°N，1 米杆，用于游戏第二版的模型测试）：10 月 5 日（n=278，δ=−5.79°）9 时高度角 34.0°、方位 122.0°、影长 1.48 m；12 时 54.2°、180°、0.72 m；15 时 34.0°、238.0°、1.48 m。6 月 21 日正午影长 0.12 m，12 月 21 日正午 1.35 m。
- **单元 A**：
  1. 早上 9 点和中午 12 点，影子哪个长？
  2. 影子在杆的哪一边？
  3. 太阳从哪边升起？
- **挑战**：在 3D 场景里摆一根杆，按要求的时刻预测影子的落点；用影子找北。
- **委托**：`shadow.length`、`shadow.dir`、`shadow.time`。答案必须唯一：两种影长相差 <15% 的题拒收。

#### ⑨ 月亮观察站 `moon`
- **模型**：
  - 朔望月 P = 29.530588853 天；参考新月 2000-01-06 18:14 UTC（JD 2451550.26）；
  - 月龄 `age = (JD − 2451550.26) mod P`；
  - 亮面比例 `k = (1 − cos(2π·age/P))/2`；age < P/2 为盈。
- **玩法**：
  - 5–6 周里记录 6–8 次观察，其中至少 2 次在早上上学路上；阴天或没看到也记一条。**不做日历格子**，不显示"今天没打卡"。
  - 每条记录：画出看到的形状（从 8 个月相里挑一个），再和模型对照。

## 5. 提示、失败处理、星级与掌握、成长与收藏

### 5.1 提示阶梯（LabKit `hint.ts`，沿用总方案 §3.0 的协议）

**触发**
- H0：≥30 秒没有任何触摸，或者孩子点了提示键。正在播动画、正在用数字键盘输入、旁白正在播放时，不计时。
- 提示键：顶栏的灯泡图标，64px。30 秒没动作时，提示键进入"ready"态，用 kit/ui 的 `setHintReady`（柔光脉动），不自动弹出内容。
- 每再点一次提示键，升一级：H1 → H2 → H3。

**每个阶段的内容**

| 阶段 | H0 | H1 方向 | H2 部分示范 | H3 完整示范 |
|---|---|---|---|---|
| 预测 | 重读问题，卡片轻晃 | — | — | — （预测不给答案） |
| 探索 | 必做物件脉动高亮 | 旁白告诉他该做什么（如 `tg.crow.p1.must`） | 幽灵手示范一次拖放 | 自动做完必做动作，孩子接着探索 |
| 解释 | 两张卡各重读一遍 | 重放这一轮的关键片段 | 伙伴指出证据（如"看水量计"） | 揭示正确的卡，播放动画；这一题标记 `usedH3` |
| 挑战 | 目标横幅脉动 | 各关的 H1（§4 各表） | 各关的 H2：代做第一步 | 完整示范，然后出一道孪生题（同题型、同级、新种子）。孪生题做完，才计入这一关的通关 |
| 委托 | 重读题面 | 换一种说法，并高亮关键数字 | 选项题去掉一个错误选项；搭建题代放第一件 | 显示答案和模型演示，然后出孪生题 |

**规则**
- 提示永远不卡住进度。
- 用过 H2 或 H3 的作答不计入掌握判定（§5.4）。
- 3★ 要求没用 H3。

### 5.2 失败处理
- **没有生命值、没有计时、没有 Game Over。** 全游戏任何地方都不出现"错"字，也不用红色表示"不对"。"还没对"用琥珀色 `--xg-try-*` 配 `try-again` 音效（木质的"咚"）。
- **预测不一致**：盖"意外发现"章（§3.2）。
- **挑战没达成目标**：用模型讲清楚"差在哪"（还差几格、多了几斤、指针反了），然后给「再试一次」或「撤销」。
- **同一个探针连续 2 次没对**：委托降一级，并插一道孪生题（§3.5）。挑战里则自动把提示键切到 ready 态。
- **连续三关都用了 H3**：伙伴建议"先去做个委托热热身？"，给两个按钮「好」「不用」。不强制。
- **委托一组的首试正确率 <60%**：下一组降一级。收尾卡不显示分数，只显示"完成 5 个委托"。

### 5.3 星级
- 只有单元 B 的挑战有星，每关 0–3★，阈值见 §4 各表。全部由求解器给出，在 `content/tiangong-lab/<lab>.json` 里写成 `stars: { 3: {...}, 2: {...} }`，CI 会和求解器的输出比对（§9.1）。
- 结果面板用 `showResult({ ribbon, stars, title, text, stats, actions, accentGame: 'lab' })`：星星的节奏、音效（`star-1..3` + `level-complete`）和 3★ 彩纸都由设计系统自带，本作不另做；从不自动跳下一关。`ribbon` 写关名（"挑战 3 · 正好到瓶口"），`stats` 写"用了 3 颗 / 最少 3 颗"这类过程数据，旁白用过程性表扬，例如 `tg.ch.best`"你找到了最省的办法！"。不说"真棒"，也不写"重玩一遍拿满分"。
- 每个实验室满 15★ 时，舱门边出现一枚"满星徽章"（只是装饰）。没有任何东西要靠星星解锁。

### 7.3 配音（narration）
- **文件**：`content/tiangong-lab/narration.yaml`，仓库格式（`content/narration/README.md`）：
  ```yaml

    - id: tg.crow.comm.count

  ```
  这份文件由 `~/kid-games-work/specs/tiangong-lab-tools/narration.mjs` 从附录 A 机械生成（已生成好：`tiangong-lab-tools/narration.yaml`，直接拷进仓库）。以后改台词，改 yaml 即可，附录 A 只作为规格存档。配音管线（docs/VOICE.md）读这份 yaml，产出 `public/audio/tiangong-lab/` 和 `audio-manifest.json`；在音频生成之前，游戏必须照样能玩（字幕 + kit 的 speechSynthesis 兜底）。
- **角色**：`narrator`（温和女声：故事、选项标签、卡片、数字）、`companion`（伙伴领航员：指令、提示、反馈）、`dad`（可选，以后逐句覆盖）。音色和后处理由配音管线决定，本作不指定引擎。
- **槽位和数字**：kit/narration 的 `{槽位}` 只填进字幕，不念。所以：
  1. 带数字的委托题，字幕里有数字（`text`），语音用不带数字的 `norm`（"看看水面和红线，最少放几颗石子？"）。数字本身画在题图上（Baloo 2 大号数字）。
  2. **点数字听读音**：题图和笔记里的数字都可以点，调用 `sayNumber(n)`（`src/app/numbers.ts`）。配音管线有全站共用的数字音频（游戏名 `numbers`：`num.0`…`num.1000` 标准读法，另有 `num.<n>.liang` 两字变体），启动时 `narrator.addManifest('/audio/numbers/audio-manifest.json')` 合并进来（文件不存在时忽略）。
     - n ≤ 1000 → `num.<n>`；n = 3200（本作唯一超过 1000 的数）→ 本作自己的 `tg.num.3200`（"三千二百"）。
     - 片段不进字幕条（`onCue` 里过滤 `num.` 和 `tg.num.` 前缀），数字旁边弹一个 1.2 秒的小气泡显示数字。
     - 音频缺失时，`narrator.say(cnReading(n))` 交给 kit 的 speechSynthesis 兜底；`cnReading` 和配音管线 `textnorm.int2cn` 同一规则（205 → 二百零五，110 → 一百一十，1000 → 一千）。
     - 生成器保证题里不会出现 1000 以上的其他数；`numbers.test.ts` 对 0–1000 和 3200 断言 `cnReading` 的结果。
- **字幕长度**：指令字幕 ≤15 字（只数汉字、字母和数字，槽位按 2 字算）。超过的 25 句已拆成"短字幕 + 完整语音"。故事正文、解释卡、天宫卡、回家卡、安全卡、发现卡、对照后的一句话（id 以 `.story.n`、`.explain.A/B`、`.pN.say`、`.tiangong`、`.home`、`.safety`、`.disc.*`、`.cN.result`、`.cN.up`、`.pileout`、`.explain.replay`、`.name` 结尾）显示在各自的卡片或纸带上，不受此限。`narration.mjs` 和 §9.1 V8 都检查这一条。
- **语气**：全部台词过一遍仓库的 TONE_RULES（`tools/check-content.mjs`：不说"宝宝真棒/真聪明"、不出现"错了/错误"、伙伴不难过、没有"快点/时间到"），当前 0 条命中。
- **多音字**：`narration.mjs` 按配音管线的格式给 102 句加了逐行 `pinyin` 锁（例如 `称不了: chēng bù liǎo`、`转: zhuàn`、`得: de`、`喝不着: hē bù zháo`、`数一数: shǔ yī shǔ`、`剥: bāo`、`拧: nǐng`），只在本作的 yaml 里，不改全站 `_lexicon.yaml`。新增台词时，先跑 `narration.mjs` 看锁有没有覆盖到。
- **行数**：共用 35 句；6 个实验室 239 句（乌鸦 44、沉浮 46、曹冲 39、天平 35、齿轮 39、电路 36）；外加 `tg.num.3200`，合计 275 段。其中 25 句带 `norm`，102 句带 `pinyin` 锁。
- 完整台词见附录 A。

### 8.4 生成器接口（`gen/index.ts`）
```ts
export interface Task { type: string; level: 1|2|3|4|5; seed: number; tries: number; q: TaskQuestion; answer: string | number;
  choices?: (string|number)[]; probe: string; minPieces?: number; detail?: unknown }
export function gen(type: TaskType, level: Level, seed: number): Task | { failed: true; reasons: Record<string, number> };
```
- 随机数一律用 `@kit/rng`：
  - 根种子 `createRng(\`tiangong:${type}:${level}:${seed}\`)`；
  - 第 i 次尝试用 `root.fork(i)`；
  - 答案配额用独立的 `createRng(\`want:${type}:${level}:${seed}\`)`，这样配额在多次重试之间保持不变；
  - `MAX_TRIES = 200`。
- 原型的 `rng.mjs` 和 `@kit/rng` 逐位一致（同一个 mulberry32 + FNV-1a，`fork(i)` 都是对 `${seed}:${i}` 取哈希），所以移植版直接用 `@kit/rng`。
- 和原型逐字段一致：vitest 对每个题型 × 级别抽 200 个种子，比较 TS 移植版和 `site/tiangong-lab/tools/proto/gen.mjs` 的 JSON 输出，必须完全相同（差分测试 `gen.diff.test.ts`）。原型文件旁边各放一个最小的 `.d.mts` 类型声明（相对路径的 `.mjs` 不能靠通配 `declare module` 解决）。

### 8.5 渲染方案与性能预算（A13，iPadOS 26 Safari 主屏 App）
- **渲染**：SVG DOM。每个舞台一个 `<svg viewBox="0 0 720 640">`，分 5 层 `<g>`：bg / equipment / items / fx / overlay。
  - 动画：用 kit/tween（rAF）和 kit `animate()`（WAAPI，只动 transform 和 opacity）。
  - 只在"脏"的时候跑 rAF：有活动 tween、水面在晃、齿轮在转、电流在流动时才跑；全部静止时，rAF 次数为 0。
  - 水面：每帧只改 1 条 path。
  - 齿轮：每帧只改各组的 `transform`，同时转的齿轮 ≤8 个。
  - 粒子：用 kit/particles，同时 ≤40 个。
  - 不用 SVG filter 和 CSS blur；光晕用径向渐变。
- **故事页**：用 `<img src={new URL('../assets/story/…svg', import.meta.url).href}>`，由浏览器栅格化一次后缓存，不进 DOM；翻到第 n 页时预解码第 n+1 页（`img.decode()`）。

| 预算项 | 上限 |
|---|---|
| 首屏 JS（实验室自己的代码，不含 kit），gzip | ≤90 KB |
| 每个实验室的懒加载块，gzip | ≤45 KB |
| 每页故事 SVG，gzip | ≤120 KB |
| 每个实验室的配音（约 45 句 × 平均 2.5s × 48kbps AAC） | ≈700 KB，进入实验室时预取本实验室的部分 |
| 帧时间：动画期间主线程脚本 + 样式 + 布局 | ≤8 ms/帧（60fps 下留出余量） |
| 舞台 SVG 节点数 | ≤900（33 件物品按需挂载，不全部常驻） |
| JS 堆 | ≤60 MB |
| WebKit 内容进程内存 | ≤250 MB（3 GB 设备） |
| 舱图静止时 CPU | rAF 次数为 0；6 颗慢闪星用 CSS animation |
| 生成器 | 每题 p99 ≤5 ms，`gears.build` ≤20 ms，都在主线程（实测最慢 L5 平均 0.4 ms） |
| 电路求解 | ≤12 个节点、≤17 条边，精确有理数，≤1 ms |

## 附录 A：配音台词表（`content/tiangong-lab/narration.yaml` 的源表）

**格式**（紧凑写法，供审阅）：`id: [角色, 文本]` 或 `id: [角色, 字幕, 念的话]`
- 角色：`n` → `narrator`（旁白），`p` → `companion`（伙伴领航员），`d` → `dad`（可选，用来覆盖）。
- 三段式的行：第二段是 ≤15 字的字幕（仓库格式的 `text`），第三段是真正念出来的话（`norm`）。两段之间用英文逗号加空格分隔，文本里不要出现英文逗号。
- `{x}` 是字幕槽位，由 `narrator.say(id, { vars })` 填进字幕，**不念**；所以带槽位的行一定是三段式，念的话里不含数字。
- 选项标签（`.a/.b/.c`）用 narrator 声音，点卡片时播放。
- 机械转换：`node ~/kid-games-work/specs/tiangong-lab-tools/narration.mjs` → `tiangong-lab-tools/narration.yaml`（已生成：275 段，语气 / 字幕长度 / 槽位 / 多音字锁检查全部通过）。直接拷成 `content/tiangong-lab/narration.yaml`。
