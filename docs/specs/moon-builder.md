## 0. 一屏速览

- **是什么**：Three.js 低多边形 3D 搭建解谜。孩子是"小步步总工程师"，在月球南极扩建基地（取名"广寒基地"，呼应嫦娥、广寒宫）。地球发来的设计图逐步变难：能转的全息模型 → 一张固定角度的图 → 只看 5 秒 → 别人站在别处拍的照片 → 两张 / 三张正投影图 → 镜子和转台 → 工程委托。每搭对一个模块，它就飞进基地，玉兔小车开进来，基地一点点长大。
- **核心操作**：点一个面放一块（按下即显示预览、松手才放），长按 0.5 秒拿走一块，↺↻ 每次转 90°（只有 4 个视角，没有自由旋转），点"对接检查"看差异叠加（缺的琥珀虚线框、多的半透明 + ✕），改，对接。
- **内容**：9 个世界 70 个机器搜索 + 校验 + 人工编排的固定关（M1–M8 各 8 关，M9 6 个委托）；432 张预生成并校验过的"施工单"（9 类 × 4 档 × 12，每个世界一类，3 升 1 降自适应，档位对孩子不可见）；自由建造（5×5，最高 4 层，可放进基地、可打印"出题给爸爸"的三视图卡）；9 张实物挑战卡；11 张月球知识卡。
- **时长**：固定关预计 ≈ 113 分钟（中位 90 秒 / 关），施工单 ≈ 650 分钟（原型估计）。按每周 3 次 × 约 12 分钟：固定主线约 5 周走完，之后施工单 + 补星 + 自由建造 + 实物卡至少再撑 6 周（§4.6）。
- **引擎**：新建 `engines/voxel`（VoxelKit，本游戏是 owner），玉兔编程复用：列高网格、任意 90° 方位 + 俯角的正交相机（另有透视跟车）、DDA 面拾取、只在变化时渲染、按颜色 InstancedMesh、blob 假阴影、多视口剪裁、WebGL 上下文丢失恢复、A13 性能预算、离屏拍照。

## 1. 定位、玩家幻想、立意、目标能力、课标锚点、证据等级

### 1.1 定位与玩家幻想
- **定位**：站内"3D 空间主力"学习卡，吸收旧"记忆方块"。在 7 张学习卡中负责 `spatial`（主）、`engineering`、`memory`。
- **玩家幻想**：我是月球基地的总工程师——我看得懂工程图、能想清楚看不见的那一块、能站到别人的位置想问题、能从三张图造出一座楼；我搭的每一个模块都真的留在了基地里。
- **基准**：纪念碑谷（正交等轴、精致低多边形、安静的高级感），Funexpected 的"积木视图"题（无字、操作即答案），乐高官方搭建说明（图→物的严格对应）。我们不抄任何一款：核心是"施工—检查—对接"的工程闭环，加上月面科学细节（1/6 重力、没有空气的尘土）。

### 1.2 立意
1. **像真正的航天工程师那样做事**：读图、预判、核对、对接。失败只是"检查发现了差异"，不是"错"。
2. **科学是真的**：月面有重力（约地球的 1/6），悬空的积木会越落越快地掉下，只是比地球慢；月面没有空气，扬起的尘土走抛物线直直落回，不会飘成云；天宫里才是失重。开场有一张"天宫 / 月面 / 地球"对比卡，专门防止"月亮上东西会飘"的误解。
3. **文化**：基地叫广寒基地，月宫是"嫦娥住的地方"的现代版本；知识卡讲嫦娥工程、玉兔、鹊桥。
4. **爸爸参与**：每个世界一张实物挑战卡（用家里的积木），M9 有"出题给爸爸"。实物操作比纯屏幕训练的迁移更好（Hawes 等 2022），所以这是设计的一部分，但**永远不卡进度**。

## 3. 核心循环与规则（穷举、无歧义）

### 3.1 世界模型
- **网格**：n×n 个格（n ∈ {3,4,5}；自由建造 5），每格一根"柱子"。坐标与玉兔编程一致：`x` 西→东，`z` 北→南（z=0 是北边，离默认相机最远），`y` 向上。体素 (x,y,z) 占 [x,x+1]×[y,y+1]×[z,z+1]。
- **列高模型**：每格是一串颜色（从下到上）。**永远没有悬空的块**；"悬空"只作为下落动画的起点出现。最高层 `maxH`（1–4）由关卡给定。
- **颜色**：5 色，每色有符号（色弱友好，颜色从来不是唯一信号）：`w` 月白○、`g` 金★、`b` 蓝●、`c` 青◆、`o` 朱▲（`COLORS = 'wgbco'`，色值与色弱实测见 §6.2）。只看形状的关（`colored:false`）所有块都是月白，颜色托盘隐藏。固定关与施工单只用 w / g / b；托盘在这些关只显示本关用到的颜色；自由建造与 M9-06 显示全部 5 色。
- **序列化**（关卡数据、存档、测试共用）：行用 `/` 分隔（北边一行在前），格用 `,` 分隔（西边在前），格内是从下到上的颜色字母，`.` 为空。例：`".,gw,gw/.,.,w/.,.,."`。只看形状的简写：每格一个数字，例 `"012/001/000"`。
- **平台**：棋盘格两种灰（读格子用；校验器的"地面奇偶"与此一致），北边中点立一面红色"北"字小旗，平台东南角地面贴指南针。

### 3.2 相机
- 正交相机，俯角固定 **30°**（`ISO_PHI`，校验器同值），方位只有 4 档：`yawStep` 0–3 = SE、NE、NW、SW（方位角 = 45° + 90°·k，从南向东量）。**没有自由旋转、缩放、平移。**
- ↻ = `yawStep+1`（看起来模型顺时针转），↺ = `yawStep−1`。补间 360 ms easeInOutCubic；补间中忽略放块点击；连按最多排队 1 次。
- 每关开始 `yawStep=0`（SE）。M2/M3 设计图的拍摄角在数据里（`pictureYaw`），施工视角不强制对齐。
- 特殊机位（只用于演示，结束后回到当前档）：拍照机位（S/E/N/W 侧，俯角 20°，`PHOTO_PHI`）、视图机位（正面：方位 0° 俯角 0°；左面：方位 270° 俯角 0°；上面：俯角 90°、北朝上）、缩略图机位（SE，30°）。
- 取景：平台包围盒（n×n×(maxH+0.3)）投影后放进自由区，留 6% 边距；方向变化 / 窗口变化时重新取景（不打断动画）。

### 3.3 输入
| 手势 | 规则 |
|---|---|
| 按下 | 只认第一根手指（kit PrimaryPointer）。对画布做 DDA 拾取（§8.5）。若命中有效放块目标 → 立即显示**预览块**（半透明 + 青色描边，80 ms 淡入；若会下落，预览画在落点，并在原高度画一个虚线幽灵和向下箭头） |
| 拖动 | 移动 >10 px → 进入"瞄准"：预览跟随手指下的目标；目标变化时 `ui-tick`；取消长按计时 |
| 松开 | 预览目标有效 → 放块；无效 → 软"咚"（`bump`），不弹任何文字 |
| 长按 | 不动按住 ≥150 ms 在**可拿走的块**上：手指周围出现环形进度；到 500 ms **立即**拿走这块（不等松手），上面的块按月面重力落下 1 格。拿走之后到松手前不再触发任何动作。M8 镜像关给定的一半是锁定块，不可拿；M1-03 的起始杂块是普通块，可以拿（这正是那关要教的） |
| 横扫 | 按下点不在任何可放目标上（天空 / 平台外），水平移动 ≥80 px 且 ≤600 ms → 转一档（向右扫 = ↺，模型正面跟着手指走） |
| 颜色托盘 | 点色块选中（金环 + `ui-select`）。默认色 = 目标里出现最多的颜色（并列取 `COLORS` 顺序靠前者）。托盘第一次出现时（无论哪一关）：幽灵手点一个色块 + `moon.color.intro`（`flags.colorTaught`） |
| ↶ 撤销 | 撤回最近一次搭建操作（放 / 拿 / 清空），不限次数；不能撤回"检查"。栈空时置灰 |
| 清空 | **长按 ↶ 800 ms** → 弹窗（✓ / ✗ 两个图标按钮）→ 清空本关（M8 只清建造侧；起始块恢复）。可撤销 |
| 💡 提示 | 见 §5.1 |
| 对接检查 | 见 §3.5。没有任何改动（与上次检查后相同，或 0 块）时置灰 |

### 3.4 放块规则（DDA 拾取结果 → 放到哪一格）
| 命中 | 目标列 | 落点 | 无效条件（无预览，松手软"咚"） |
|---|---|---|---|
| 平台地面格 (x,z)（只可能是空列） | (x,z) | y=0 | 该列锁定 |
| 块 (x,y,z) 的**顶面** | (x,z) | y = 列高 h | h = maxH（该列顶部闪一下"封顶环"，`mb-cap`）；列锁定 |
| 块 (x,y,z) 的**侧面**，法线 (dx,0,dz) | (x+dx, z+dz) | y' = 该列当前高度（y' ≤ y 恒成立；y' < y 时从 y 高度**下落**） | 目标格出界；y' = maxH；列锁定 |
| 天空 / 平台外 | — | — | 总是无效（可触发横扫旋转） |

- 新块颜色 = 当前托盘色（无色关为 `w`）。
- **下落**（月面重力，物理真实）：1 块高 = 0.5 m，g = 1.62 m/s² ⇒ 以"块/秒²"计 g_s = 3.24；位移 Δy 的下落时间 t = √(2Δy/g_s)：1 块 0.79 s、2 块 1.11 s、3 块 1.36 s。y(t) = y₀ − ½g_s t²（越落越快）。**逻辑上立即落位**（模型、拾取、检查都用落点）；动画只是表现。
- 同一列在动画中又被操作：先把该列动画瞬间完成再执行新操作。撤销、检查、旋转、离开页面前：所有动画瞬间完成。
- 拿走 (x,y,z)：该列在 y 之上的块各降 1 格（下落动画 0.79 s）。
- 封顶：任何列高 ≤ maxH；块总数 ≤ n·n·maxH。
- M1-01（`ghostsOnly`）：只有幽灵所在格可放，其余点击 = 软"咚" + 最近的幽灵脉动 1 次。
- M8 镜像关：给定一侧（轴 X：x≤1；轴 Z：z≤1）**整侧锁定**（含空格）；锁定块的侧面可以作为"朝建造侧放块"的命中面。
- 可搭性已由机器人证明：只有 4 档视角、按真实自由区（竖屏 810×508、横屏 736×598，取两者较差者，6% 边距）取景、点选面积 ≥ 44×44 px（苹果 HIG）的条件下，70 关 + 432 单全部可搭，且"一根一根随机顺序搭"也从不出现够不着的格子（R14/R15）。自由建造 5×5×4 抽样 22 个结构：全部可搭；随机塔序在 2/22 个结构上会卡（可转视角 / 撤销解决，沙盒不做要求）。

### 3.5 对接检查（判定与反馈）
**判定**（`src/rules/check.ts` + `@engines/voxel/model` 的 `diff`、`views`；与原型 `mbcore.mjs` 的 `diff`、`views`、委托判定逐条一致，`golden.test.ts` 锁定）：
| 模式 | 通过条件 | 平移容忍 |
|---|---|---|
| holo、picture、count、memory、rotate、photo 的搭建阶段 | 搭的结构 = 目标（`colored` 时颜色也要一致） | **允许整体平移**：在所有不出界的平移 (dx,dz) 中取差异最小者；并列时取 (0,0)，再取 |dx|+|dz| 最小。只看形状，不惩罚"搭在了别的格子" |
| mirror | 建造侧 = 目标的建造侧 | 不允许（以镜子墙为准） |
| views（M6/M7/M9-03） | 搭的结构的正面 / 左面 / 上面图 = 给定的图（给哪几张比哪几张）。**任何满足的搭法都算对** | 不允许（视图带位置） |
| commission | 见 §3.6.9 各委托判定 | 不允许 |

**反馈**（失败时；任何编辑都会清掉叠加）：
1. 扫描：一张青色扫描平面从下到上扫过（700 ms，`mb-scan`）。
2. 差异叠加（in-place 3D）：**缺的** = 琥珀色（`--xg-try-500`）虚线框 + 12% 填充；**多的** = 块变半透明（α 0.45，保持原色）+ 顶面中央一个琥珀圆底白 ✕ 角标（始终朝向相机的精灵）+ 轻摆（±4°，2 Hz，1.2 s 后静止）——不给块本身染色，否则金色块看不出区别；**颜色不对** = 块上方浮一个应有颜色的小色块（带符号）+ 弯箭头。从不出现红色、不出现"错"字。平移容忍时叠加画在"最佳平移"对齐后的位置（§3.5 判定表）。
3. 伙伴：`moon.check.missing` / `.extra` / `.recolor` / `.mixed` 中按情况选一句；检查次数 +1（同一结构不重复计数）。有生以来第一次出现"多的"块时，↶ 脉动 + `moon.undo.intro`。
4. 视图模式：每张视图卡上不一致的格子画琥珀色描边，3D 里对应的列 / 排 / 格竖起一道淡光柱（2 s）。
5. 委托：见 §3.6.9。

**通过**：扫描 → 所有块按 20 ms 间隔依次闪白（120 ms）→ `correct-big` → 进入对接（S4）。过程性表扬按发生了什么来选（只选一句）：本关转过视角且 `needRotate` → `pass.4`；有藏块的图 → `pass.5`；之前检查失败过 → `pass.3`；一次通过 → `pass.1`/`pass.2` 交替；★3 时追加 `moon.star3`。M3 先播数数动画（§3.6.3），M5 先进入提问（§3.6.5）。

### 3.6 各模式流程
#### 3.6.1 holo 全息照搭（M1、复习关、施工单）
设计图卡里是目标的**3D 全息模型**（自带小平台和北旗），与主相机**同步转动**（同一 `yawStep`）。孩子在主平台上照着搭，检查 → 对接。`needRotate:true` 的关，至少有一个顶块从起始视角看不清（已由校验器证明），必须转过去看。
- 首次教学：M1-02 开局 ↺↻ 旋入 + `moon.rotate.intro`；M1-03 开局平台上已经按 `start` 摆好 3 块：目标少 1 块、另有 1 块多余的放在不挨着目标的空格上。幽灵手先在多余块上演示长按 0.5 s（只首次）+ `moon.delete.intro`。块数相等且没有任何平移能"只加不拿"地完成（R16 已证明），所以这关**必须**拿走一块才能过——正是这关要教的。

#### 3.6.2 picture 定视角图（M2、复习关、施工单）
设计图卡是一张**固定角度的蓝图**（`pictureYaw`，俯角 30°，蓝底白线技术图风格，带平台格子和北旗），**不随主相机转动**。校验器保证：图中每根柱子的顶都清楚可见（≥30%）、每格"再加一块"也会被看见 ⇒ 这张图唯一确定了每根柱子的高度；`hidden` = 必须靠"高处的块下面一定有块"推出来的支撑块数（≥1）；任意改动 1–2 根柱子都会让图至少变化 3%（实测最小 6.2%）。
- M2-01 开场演示（只首次，6 s，可跳过）：一块积木从 2 格高处放出，按月面重力越落越快地落下；接着弹出"天宫 / 月面 / 地球"三格对比卡（§4.5）。

#### 3.6.3 count 先猜后搭（M3、复习关、施工单）
1. 猜：设计图卡放大，`moon.m3.intro` "先猜一猜：一共要几块？"，数字键盘输入 1–40，✓ 提交。**不判对错**，猜数钉成一张便签贴在设计图卡角上（`moon.m3.noted`）。
2. 搭：同 picture（或 holo，当 `blueprint:'holo'`）。
3. 检查通过后数数：从下到上、从北到南、从西到东逐块点亮并弹出数字（每块 180 ms，数字语音 `moon.num.N`，N=1…30；clip 缺失时 kit 用 speechSynthesis 念数字，再缺就用五声音阶递升）。最后与便签比较：相等 → `moon.m3.right` + 便签盖金章；不等 → `moon.m3.diff`，所有"藏着的块"脉动 2 次。都不算失败。

#### 3.6.4 memory 看一眼就搭（M4、复习关、施工单）
1. 展示：全息卡放大，平台变暗不可点；环形计时（无数字）走 `showMs`（≥5000 ms）。展示期间**可以转视角**。
2. 隐藏："关灯"快门合上（`mb-holo-off`，280 ms），平台亮起，`moon.m4.hide`。
3. 搭：设计图卡显示一个合着的"记忆舱"和 👁 "再看一眼"按钮（64px）。点 👁：舱打开 `peekMs`=3000 ms，**期间平台不可搭**（可转视角），关上后计数 +1。不限次数。
4. 检查 / 对接同 holo。★3 需要"再看"≤1 次（§5.3）。
- 中途离开：若在展示阶段离开，回来重新展示且不计次；在搭建阶段离开，恢复搭建进度和"再看"次数。

#### 3.6.5 photo 换个角度（M5）
1. 搭建阶段：`build:'robot'` → 平台边的小吊车 2 s 内逐块装好目标（每块 150 ms，`mb-crane`），孩子看；`build:'holo'|'picture'` → 孩子先按 holo/picture 规则搭好并通过检查（复习关）。
2. 锁定视角：相机回到 SE 档，↺↻ 隐藏（问答期间不能转——这正是要练的）。
3. 每题（共 3 题）：玉兔沿平台外圈开到 `side`（N/E/S/W，2 单位/秒，`mb-rover-drive`），升起桅杆，闪光 + `mb-shutter`。
   - `pickPhoto`：出现 3 或 4 张照片卡（离屏渲染：只拍积木、不拍平台和北旗，浅色渐变底，白边"拍立得"相框，每张固定 ±2° 倾斜）。选项种类按数据：`correct`、`mirror`（正确照片水平翻转）、`ego`（从南边看到的，也就是"我自己看到的"）、`other`（另一侧）。显示顺序按 `hashString(levelId+side)` 洗牌（确定性）。
   - `whereStood`：出现一张照片，平台四边出现 4 个玉兔站位按钮，选"玉兔站在哪"。
   - 点选后：**对**——卡片青色发光，相机飞到玉兔的机位（800 ms）让孩子看到"真的长这样"，停 1.2 s，飞回（700 ms）。**不对**——卡片轻摇（±6 px，300 ms），相机同样飞过去看，正确卡发光；孩子再点正确卡才继续（只为闭环，不计入首答）。飞行中选项不可点。
4. 3 题答完 → 对接。★3 需 3 题全部首答正确。
- 数据保证（R6）：每张照片里看得见的块，孩子从 SE 视角都看得清（或是支撑块）；正确照片不是左右对称的；任意两选项差异 ≥12%；必有镜像干扰项；"站在哪"题四张侧面照两两不同，且对面两张不是镜像双胞胎。

#### 3.6.6 views 视图（M6、M7、M9-03、复习关、施工单）
设计图卡是 2–3 张视图卡（`given`：`FT`、`FLT`、`FL`）。画法：**正面图** = 站在南边看，列 x 从左到右；**左面图** = 站在西边看，从左到右是北→南；**上面图** = 从上往下看，北在上。每列 / 每格画实心方格（`--xg-moon` #8170DB 填、`--xg-moon-deep` 描边），卡头有"眼睛 + 站位"小图标和 2 字标签。
- **按住**某张视图卡：主相机飞到对应视图机位（500 ms）并保持，松手飞回。这是脚手架，不扣星。
- 检查：比较视图；任何满足给定视图的搭法都算对（多解时伙伴说 `moon.m6.anyok` "你的搭法也对！"）。
- `challengeMin:true` 的关：底栏显示"用了 N 块"；★3 要求块数 = `minBlocks`（已校验 min < max，即"把能填的都填满"的直觉搭法不是最省的）。
- M7-06（只给正面 + 左面）：275 种搭法都算过关，★3 = 最少 6 块。

#### 3.6.7 mirror 镜子墙（M8-01–03）

#### 3.6.8 rotate 转台（M8-05–07）

### 3.7 边界情况（必须实现并测试）
1. 横竖屏切换发生在任意动画中：重新取景，动画继续，不丢状态。
2. 切到后台（shell `pause`）：取消长按、所有动画瞬间完成、立即存档进行中的关；回来 `invalidate()`。
3. 第二根手指 / 手掌：忽略（kit）。
4. 极快连点：每次点击独立拾取，逻辑立即生效；同列动画按 §3.4 处理。
5. 检查按钮在动画中按下：先完成动画再判定。
6. 补间旋转中点平台：忽略；点 ↺↻：排队 1 次。
7. M4 展示中点 👁 或检查：不可用（隐藏）。
8. M5 飞行中点选项：不可用；返回键在提问中可用（进度：已答的题保存）。
9. 撤销栈跨越"检查"：撤销只回退搭建操作，检查次数不回退。
10. 中途离开再回来：恢复结构、检查次数、提示等级、再看次数、M3 猜数、M5 已答题；`yawStep` 回到 0。
11. 存档损坏或版本未知：kit `createStore` 回到默认值；不崩溃。
12. WebGL 上下文丢失：S11 覆盖层；恢复后画面与丢失前一致（§8.5）。
13. 选中颜色在只看形状的关：托盘隐藏，用 `w`。
14. 块数达到上限 n·n·maxH：所有放块无效（不会发生在关卡解里）。
15. 自由建造作品与关卡目标完全一样：允许。
16. 静音 / 关声音：全部可玩（字幕 + 图标 + 动画）。
17. 低电量模式（rAF 30 Hz）：性能指标看 `renderer.render` CPU 用时，不看帧间隔。
18. 有 `start` 的关（M1-03、M8）：撤销到底 = 起始状态（不是空平台）；清空 = 回到起始状态；M1-03 的起始块是普通块可以拿，M8 的锁定半边永远拿不走、点它的侧面可以朝建造侧放块。
19. `orders.json` 动态加载失败（例如首次离线且未缓存）：订单板显示"施工单在路上"的纸条、隐藏卡片，不影响关卡；下次进入重试。
20. 同一个施工单在 `inProgress` 里（中途离开）：回来时订单板上它排第一个、带"继续"角标；档位规则只在完成时结算。
21. 世界内"后 2 关可玩"与跳关：跳过的关在关卡条上保持"开放"，世界完成判定只看 ★≥1 的关数（6/8），所以跳 2 关也能完成世界。

**算法**（每单，`orders.mjs` 的 `make()`）：
1. 种子 = FNV-1a(`"<type>:<tier>:<k>"`) → xorshift32；在档位参数里取块数 b、拍摄角、侧面顺序、镜墙方向、转向。
2. `randomStructure(R, n, maxH, b, {connected, colors})`：先长出一块连通（或按档位概率散开的）占地，再随机加高到 b 块，逐块随机上色。
3. 按类型过拒收规则（与固定关**同一套函数**，§9.1）：
   - holo / memory：所有顶块至少在一个视角清楚可见（R3）；`needRotate` 与档位要求一致（memory 一律不需转）；连通块数在允许范围；b≥4 时不能"一样高且只有一块"；memory 再过 R5（单色 ≤4 块、总 ≤5 块、估计搭建 ≤20 s）。
   - picture / count：R4 可读（顶块与"再加一块"都 ≥30% 可见）；藏块数在档位区间；局部唯一（改 1–2 根柱子图像差 ≥3%）**且 R4g 全局唯一**；b≥5 时至少两种高度。
   - photo：R6 全套（照片里的块孩子看得见、正确照片不对称、选项两两差 ≥12%、必有镜像项；"站在哪"四侧两两 ≥12% 且对面不是镜像双胞胎）。
   - views2 / views3：解数在档位区间；多解时存最少块解；`challengeMin` 时最少 < 最多；去掉任一张图解数都变多（R7）。
   - mirror：给定半边连通、贴着镜线、不越线；镜像 ≠ 平移复制（R8）。rotate：结果 ≠ 原样 / 镜像 / 反方向 / （半圈时）四分之一圈（R9），至少两种高度。
4. 去重（R2）：按"玩法家族"（picture 与 count 同族；views 按给定图分族；mirror 按镜墙方向分族；rotate 按转向分族；photo 含侧面顺序）+ 旋转 / 镜像 / 平移规范形，与全部固定关和已生成的单都不重复。
5. 拒收后重试，单张最多 4000 次；生成失败即构建失败。实测接受率与耗时见附录 C。

**投放与自适应**（`src/rules/orders.ts`，纯函数，`stair.mjs` 有同规则的模拟）：
- 订单板同时 3 张：从已开放类型里选"最久没做的 3 类"（并列按世界顺序）；每类有自己的 `tier`、`streak`、`next[tier]`（下一张序号）。
- 起始档：该世界固定关首检通过率 ≥70% → 2 档，否则 1 档。
- **结果分类**：A = 第一次检查就通过且没用 H2/H3；其余都不是 A。
- **升档**：同类连续 3 单 A → +1（最高 4），伙伴说 `moon.orders.up`。**降档**：任何一单不是 A → −1（最低 1），**静默**，卡面不显示档位。这是 Levitt "3 升 1 降"阶梯，长期首检通过率收敛到约 79%；模拟（R17）：超前 / 典型 / 吃力 / 均匀四种画像分别 80.5% / 76.8% / 67.9% / 79.7%，都在 65–88% 带内。v1.0 的"2 次 ★3 升、严重失败才降"在典型画像下掉到 58%，已否决。比方案"连错 2 次降一档"更灵敏，但孩子看不到，所以不构成惩罚。
- 每档 12 单，用完从该档第 1 单循环（循环时伙伴不提"重做"，卡面照常）。完成一单：基地"仓库区"多一个货箱（可视增长，最多显示 60 个，超出的堆成"满仓"徽记），不发货币、不计入世界星数。
- "今天"建议条：每次进入基地，若有已开放类型，放 1 张施工单作为热身（排在新关前面）。
- 施工单的星级规则与固定关相同（§5.3），只记在 `orders.done` 里，不显示 n/24。

## 6. 美术（商业品质、不用图像生成器）

### 6.1 风格一句话
**"正交等轴的精致低多边形 + 暖光冷影的月面"**：纪念碑谷式的安静与精确；倒角积木、哑光材质、一盏暖色主光、冷紫色阴影；天空是星港夜空的蓝紫（从不纯黑），挂着半亮的地球。不用卡通表情、不用描边漫画风、不用渐变塑料感。所有东西由代码生成（Three.js 几何 / Canvas / SVG），可选 Kenney Space Kit（CC0）只做基地远景装饰。参考原型：`research/proto/lowpoly.html`（绿色浮岛，评 A-）——月宫沿用它的光照参数思路，换成月面配色。

### 6.3 场景与光照
- **施工场景 = 悬在星空里的"月面圆台"（diorama）**。为什么：正交相机俯角 30°、只框住 3–5 格的平台时，画面上缘只看到平台后方约 8 格的地面——无限大的月面上永远看不到天空和地球。所以做成纪念碑谷 / 原型浮岛那样的切片：一块半径 7.5 的月壤圆台，顶面是顶点色噪声月壤 + 2 个小陨坑 + 散石，台缘一圈不规则低多边形断面露出三层地层色带（#A9A196 / #847C72 / #5A5878，下沿碎成几块小石头），施工平台压在台面中央。圆台后面是**屏幕空间全景背景**（一个 Canvas 2048×512 程序纹理，启动时画一次）：天空渐变（night 950 → 700 → 500，从不纯黑）、600 颗星（确定性种子）、远山剪影（#3D3F63）、地平线暖辉（#FFD9A0 α .35）、半亮的地球（海 #3F7BE6、陆 #6DB35A / #D9C38A、云 α .8、晨昏线）。全景作为第一个 pass 的全屏四边形（不写深度）；`yaw` 每转一档，全景水平平移 1/4 宽，与相机补间同步（360 ms），转动时"看到另一边的天"；默认 SE 档地球在自由区左上 1/3 处。**不加雾**（月球没有大气）。
- 圆台 / 平台 / 积木的世界尺寸固定（1 = 积木边长），切换 3×3 / 4×4 / 5×5 时圆台不变、平台换尺寸，正交 `fit` 只框平台 + 0.3 高余量（§3.2），所以圆台边缘在大平台时会稍微出画——这是允许的。
- **光**：环境（月面、远山、散石、地球、区域建筑）用世界固定的太阳：主光暖 #FFE3B5，强度 2.2，方位 300°（从南向东量：南 0°、东 90°、北 180°、西 270°，所以 300° 是西南偏西；默认 SE 视角下南面受光、东面背光，地平线低角度长影符合南极）、仰角 35°；半球光（天 #B7C1EC / 地 #6D6A66，1.1）；轮廓光 #9FB4FF 0.6。**积木不用世界光**，用"视空间三色调"材质（`engines/voxel/view/blocks.ts` 的 `ToneMaterial`，`MeshBasicMaterial.onBeforeCompile` 打补丁）：按视空间法线把面分成顶 / 左 / 右三类（`n.y > 0.5` → 顶；否则 `n.x < 0` → 左；否则右），颜色 = 底色 × {1.00, 0.78, 0.58}（线性空间；w 块三档 L* ≈ 94 / 86 / 76，b 块 ≈ 40 / 35 / 30）× 底部一圈顶点 AO 0.85。这样四个视角里永远是"顶最亮、左次之、右最暗"，和纪念碑谷一样稳定好读，旋转时不会因为背光突然变暗（世界光方案在 4 个方位里有 2 个是背光）。**不开阴影贴图**。ACES 色调映射只作用于环境材质（积木 `toneMapped:false`，颜色所见即所得，色弱校验才有意义），sRGB 输出。
- **阴影**：每根非空柱子一个 blob（径向渐变 64² 贴图的四边形，y=0.01，α = 0.35 + 0.08·高度，向光的反方向偏移 0.15·高度，尺寸 1.25 + 0.1·高度），一个 InstancedMesh。积木底部一圈顶点乘 0.85 做接触暗角。
- **基地总览**：同一套全景背景，圆台换成半径 20 的大圆台（中央陨坑 + 坑沿环路，§6.4 基地布局）；主光仰角降到 18°（长影，呼应"南极太阳贴着地平线"），blob 拉长 1.8 倍。

### 8.2 VoxelKit API（README 合同的超集；已并入玉兔编程 §8.6 的接口请求）
**方位约定**（两款游戏共用）：`yawDeg` = 相机所在方位角，从 +z（南）向 +x（东）量；`yawDeg = 0` 时相机在南边向北看、北朝上（玉兔编程 C1–C2 的锁定镜头）；月宫的 4 档 = `MOON_YAWS = [45, 135, 225, 315]`（SE、NE、NW、SW），俯角 30°。网格坐标 x 西→东、z 北→南、y 向上，体素 (x,y,z) 占 [x,x+1]×[y,y+1]×[z,z+1]。

### 8.4 状态机
**应用**：`boot → gate →`（首次：`introDescent → level(M1-01)`；否则 `base`）；`base ⇄ district`；`district → level`；`level → dock → result → (level(next) | district | wrap)`；`base → orders → level(order)`；`base → free`；`base → cards`；`print` 是独立页面；任意状态 `→ contextLost →` 原状态（覆盖层，不卸载下层）。
**关卡**：
```
enter → intro（旁白 + 设计图揭示；第二次起可点击跳过）
  → [count] guess → [memory] show → hide
  → [photo, build:'robot'] assemble
  → build ⇄ { rotating | peek(memory) | viewHold(views) | hint(H1–H3) }
  → checking → fail → build
             → pass → [count] counting → [photo] lockCamera → question×3 { drive → snap → choose → fly → (ok ? next : waitCorrect) }
  → docking → result → exit
```
**关卡会话（事件溯源）**：`ops: Op[]`，`Op = place{x,z,c} | remove{x,y,z} | clear | undo | check{ok, missing, extra, recolor} | hint{level} | peek | guess{n} | answer{q, choice, ok} | rotate{yaw}`；状态 = 折叠 ops；撤销栈只含搭建操作（上限 200）。进行中存档 `inProgress = { levelId, stacks, undo, checks, hintMax, peeks, guess, answers, phase }`，每次 op 后 400 ms 防抖写入，`pause`/`beforeleave` 时立即写入。

### 8.5 渲染方案
- 一个 `WebGLRenderer`（`antialias:true`——Apple TBDR GPU 上 MSAA 很便宜；`alpha:false`；`powerPreference:'default'`；`outputColorSpace = SRGBColorSpace`），一个全屏画布（`position:fixed; inset:0`，DOM 覆盖层在上面）。
- **按需渲染**：`requestRender()` 只排一个 rAF；有 `onFrame` 回调（动画）时保持循环，全部结束后停；空闲时帧数为 0（测试见 §9.3）。DOM 动画（扫描线、脉动、环）用 CSS，不触发 WebGL。shell `pause` → `view.pause()`（取消 rAF、完成所有补间），`resume` → `requestRender()`。
- **DPR**：平台硬上限 1.5（GAME_AUTHORING §7、VoxelKit README），默认 `min(devicePixelRatio, 1.5)` + MSAA。`renderer.render` 的 CPU 用时（`performance.now()` 前后差）在最近 30 个渲染帧的 p95 >8 ms → 降到 1.25 并写入 `settings.dpr`（本次会话不回升）。方案 §3.2 原写"默认 2"，与平台预算冲突，以平台为准；若 iPad 实测施工屏 p95 ≤3 ms，可向平台申请本游戏放宽到 2（积木边缘更锐利），在那之前不改。
- **实例化**：每色一个 InstancedMesh（容量 n·n·maxH ≤100），只更新变化的实例矩阵（`instanceMatrix.addUpdateRange`）；基地里所有孩子作品共享一套每色 InstancedMesh（简化块，容量 1700）。区域建筑与装饰各合并为 1 个网格（`mergeGeometries`，顶点色）。
- **内嵌视口**（设计图卡里的全息 / 蓝图 / 转台）：主场景渲染后开启剪裁，按卡片 DOM 矩形（CSS px × DPR，Y 翻转）设置 viewport/scissor，清深度，渲染内嵌场景。卡片 DOM 只画边框和 CSS 扫描线。
- **拾取**：模型空间 DDA（Amanatides–Woo）沿正交相机前向，逐格检查列高；先命中块则返回块面，否则返回地面格；零分配。命中容差：主射线没命中可放目标时，再试以按下点为中心、半径 8 px 的 8 条偏移射线，取离按下点最近的有效目标（手指比像素粗）。与原型 `bot.mjs` 的命中规则逐条一致（单测用随机 1 万条射线与暴力 `firstHit` 比对）。
- **离屏渲染**：一个复用的 `WebGLRenderTarget(384,384)` → `readRenderTargetPixels` → `putImageData`（翻转 Y）→ Canvas；用于照片、缩略图、知识卡以外的所有截图类 UI。
- **上下文丢失**：`webglcontextlost` → `preventDefault()`、暂停调度、显示 S11；`webglcontextrestored` → 所有纹理 / 渲染目标 `needsUpdate`、Canvas 贴图重画、`invalidate()`。3 s 内没有恢复 → 销毁渲染器、替换 `<canvas>`、按模型重建场景（全部程序生成，无需重新下载）。
- **three 引入**：只 `three` 核心（具名 import，可摇树）+ `three/addons/utils/BufferGeometryUtils.js`；`GLTFLoader` 仅在存在 `moon-props.glb` 时动态 import。
