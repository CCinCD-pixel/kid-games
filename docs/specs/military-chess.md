### 0.3 术语

- **红方 / 蓝方**：人机对战与学堂里孩子永远执红、坐在下方（竖屏）或左侧（横屏）。翻翻棋里颜色由第一次翻子决定（R6.2）。
- **格 / 站**：棋盘上 60 个可停的点。坐标写成 `c4`：列 a–e（红方从左到右），行 1–12（红方底线为 1，蓝方底线为 12）。孩子看不到坐标。
- **一步（ply）/ 一手**：一方走一次（或翻一次）。"回合"不用。
- **碰子**：走到对方子所在的站。结果由裁判判定：攻胜 `A`、守胜 `D`、同归 `B`、夺旗 `F`。
- **下场**：子被拿下棋盘（界面上不说"死"）。
- **安静步数（quiet）**：自上次碰子（翻翻棋：或翻子）以来的连续步数，用于和棋判定。
- **par**：求解器算出的最少步数（只数红方的步）。
- **残局**：明棋局面，蓝方按"最强防守"应对，目标是 N 步内扛旗。
- **图标记号**：本文中的 🏠 💡 ⋯ ↶ ⟲ 🎲 👣 ⚔ 🛡 等符号只是指代设计系统的 SVG 图标（`icon('hint')` 等）或本游戏 `view/icons.ts` 的代码绘制图标；产品里不出现任何表情符号字符（GAME_AUTHORING §6）。
- **参谋**：对局中的提醒与提示（伙伴机器人"领航员"兼任）。**裁判**：暗棋里判定碰子结果的电脑（同一个领航员，戴裁判帽）。

## 1. 定位、玩家幻想、立意、能力目标、课标锚点、证据等级

### 1.1 一句话

和家里那副实体军棋**同一套规矩**的陆战棋：先在学堂里一课一课学会军衔、铁路、工兵、地雷炸弹和守旗，再和机器人、和爸爸下真正的暗棋——看不见对方的子，也能从裁判的结果里把它们猜出来。

### 1.2 玩家幻想

"我是小司令。"小步步在星港的**演习场**里指挥自己的红军：摆一个自己的阵，派工兵沿铁路绕到对面挖雷，用炸弹换掉对方的司令，最后扛回军旗。打赢守营地的机器人军官，他的肩章一级一级往上升，直到司令。周末拿出实体棋，iPad 当裁判，和爸爸下一盘"真的"。

### 1.3 立意

1. **看不见的，也能想明白**：暗棋是大厅里唯一的不完全信息游戏。裁判只说"谁赢了"，不说"它是谁"；孩子从"它没动过""它赢了我的旅长""它拐了弯"里推出答案。这是推理，不是运气。
2. **一支队伍守一面旗**：每个子都有用——最小的工兵能挖雷、能扛旗；最大的司令也怕炸弹和地雷。不存在"没用的子"。
3. **规矩面前人人一样**：不偷看、不悔棋（暗棋）、裁判公正、输赢都握手。和爸爸下的时候，规则和电脑里一模一样。
4. **演习，不是战争**：棋子"下场"不"死"；炸弹是纸屑礼花式的闪光，没有血、没有真实军徽和国旗；敌人是"蓝方"，是机器人教官和爸爸。

### 1.6 证据等级（诚实版，家长面板照抄）

- **规则理解与序数比较：C/D。** 游戏里直接练、直接测；没有专门研究军棋的对照实验。
- **不完全信息推理：C。** 有"练什么长什么"的近迁移可能；远迁移（"变聪明"）**没有证据**。国际象棋的元分析（Sala & Gobet 2016、2017）显示远迁移小或不可靠，本游戏不宣传益智。
- **家庭对弈的社交与文化价值：D（价值判断）。** 军棋是很多家庭都会下的国民棋；这是爸爸要它的主要理由。
- 家长面板文案："陆战棋：标准规则，和家里实体棋一样。练规则、路线规划和'看不见时的推理'；定位是好玩和家庭对弈，不宣传益智。"

**情报板（按玩法）**
- 翻翻棋：两行小瓦片（红一行、蓝一行），每种子一格，显示"还没翻开的数量"（例：蓝 炸弹 ×2）。数量为 0 的格变灰。上方一行状态："扛蓝旗还要挖 2 颗雷 · 你能挖雷的：工兵 1 炸弹 1"。
- 暗棋：对方 25 子名单（12 种 × 数量，排两列），**只有确定下场的**才划掉（推断见 §3.9）；下面一行"对方已下场 N 个"。棋盘上对方的暗子挂"参谋笔记"小角标（§3.9 表）——参谋笔记开关在 ⋯ 菜单，L1–L2 对手默认开。

## 3. 核心循环与规则（穷举；参考实现 `military-chess-tools/core.mjs`）

规则来源与取舍：棋盘、子数、布阵、走法、碰子以中文维基"陆军棋"条目、英文维基 Luzhanqi 条目和常见实体棋规则说明为准；和棋步数、来回走限制参照 QQ 游戏/各大棋牌平台的通行做法（QQ 四国军棋连续 70 步不碰子判和、其他平台 50 步；翻翻棋 80 步；"扛旗前须挖光地雷"是翻翻棋通行规则）。下面每一条都是**本游戏的唯一解释**，实现与测试以此为准。

### 3.1 核心循环

- **学堂**：看 3 秒幽灵手示范 → 自己做 3–5 道小题（棋盘题/卡片题）→ 课末收尾卡（一句"讲给爸爸听"）→ 回地图。约 8–12 分钟一课。
- **对局**（天梯或家庭）：选对手/玩法 → 布阵（暗棋、明棋；翻翻棋跳过）→ 轮流走子，碰子由裁判判定 → 夺旗 / 无子可走 / 和棋 → 结果卡 + 三个关键时刻 + 全盘揭晓复盘 → 回营地（不自动开下一局）。翻翻棋约 8–12 分钟，暗棋约 10–15 分钟（§9.4 实测步数）。
- **残局**：读目标 → 走 → 蓝方最强防守应对 → N 步内扛旗 → 星级 → 回残局图。每道 1–3 分钟。

### 3.2 棋盘（R1）

- 60 个站：`x ∈ 0..4`（列 a–e），`y ∈ 0..11`（y=0 蓝方底线 = 第 12 行；y=11 红方底线 = 第 1 行）；`index = y·5 + x`；记谱 `"abcde"[x] + (12 − y)`。
- 每方 30 站：**大本营 2**（红 b1、d1；蓝 b12、d12）、**行营 5**（红 b3、d3、c4、b5、d5；蓝 b8、d8、c9、b10、d10，呈"×"形）、**兵站 23**。
- **铁路站 32 个**：第 2、6、7、11 行的全部 5 站，以及 a、e 两列第 2–11 行。
- **连线（全部画出来的线，共 133 条）**：
  1. 同一半场内上下左右相邻的两站都相连（每半场 24 条横线 + 25 条竖线）；
  2. 两半场之间只有 a、c、e 三列相连（a6–a7、c6–c7、e6–e7，**三条过界通道都是铁路**）；b、d 两列之间是**山界**，不通；
  3. 每个行营与它斜对角的 4 个站相连（同一半场内；共 32 条斜线，c4/c9 与四周行营之间的斜线也算），斜线只连接行营——两个普通兵站之间没有斜线。
- **铁路边 35 条** = 上面第 1、2 类连线中两端都是铁路站、且同在一条铁路直线上的边：第 2/6/7/11 行的横向边（16）、a/e 列第 2–11 行的竖向边（18，含 a6–a7、e6–e7）、c6–c7（1）。
- **铁路直线**（非工兵只能沿其中一条走一步）：第 2、6、7、11 行（各 a–e）；a 列、e 列（各第 2–11 行，穿过山界）；c 列只有 c6–c7 一段。

### 3.4 布阵（R3，明棋与暗棋）

1. 每方把 25 枚子放满本方的 23 个兵站 + 2 个大本营；**5 个行营开局必须空着**。
2. **军旗**必须在本方两个大本营之一。
3. **地雷**只能放在本方最后两排（己方视角第 5、6 排 = 红方第 2、1 行，蓝方第 11、12 行；含大本营）。
4. **炸弹**不能放在本方第一排（红方第 6 行，蓝方第 7 行）。
5. 其他子可以放任何兵站或大本营；放进大本营的子整局不能动（R5.7）——布阵界面对此给一次提示（"大本营里的子不能动"），不禁止。
6. **布阵串**（存档与模板的统一格式）：25 个字符，按"己方视角从第 1 排到第 6 排、每排从己方左手到右手、跳过行营"的槽位顺序（`SLOTS`）。同一个串放到红方或蓝方都合法（蓝方 = 红方旋转 180°）。槽位表：第 1 排 c1–c5、第 2 排 c1/c3/c5、第 3 排 c1/c2/c4/c5、第 4 排 c1/c3/c5、第 5 排 c1–c5、第 6 排 c1–c5（c2、c4 为大本营）。
7. **让子**（只在"和爸爸下"与 AI 连败后的让子局）：被让掉的子在布阵串里写成 `.`（空槽），其余规则不变；让掉司令**不**触发亮旗（本游戏的明确约定，因为它不是"下场"）。
8. 校验函数 `validateLayout(layout, handicap?)` 返回错误码列表：`length`、`bad-code`、`count-<名>-<n>`、`flag-not-in-hq`、`mine-row-<r>`、`bomb-front-row`。布阵界面用同一函数实时拦截。

### 3.5 走子（R4、R5）

- **先后手**：人机对战第 1 局孩子先走，之后每局交换；家庭对局在设置里选（默认小步步先）；翻翻棋由先手方先翻。
- 每一手必须且只能做一件事：走一枚子（明/暗/翻），或翻开一枚暗子（只有翻翻棋）。不能"过"（谜题里的静态蓝方除外，R9）。

**R5.1 能动的子**：己方、在场、类型能动（不是地雷、军旗）、**不在任何大本营里**（己方或对方的大本营都算；R5.7）；翻翻棋里还必须已经翻开。

**R5.2 公路步**：沿任意一条连线走到相邻站（上下左右、过界通道、行营斜线都算一步）。

**R5.3 铁路直行（非工兵）**：起点在铁路站时，可沿四个方向之一、只走铁路边、方向不变地连续前进，经过的站必须都空；可以停在途中任何一个空站；遇到的第一个子若是对方的、且可被攻击（R6.1），可以碰它（停在那里），然后停止；遇到己方子立即停止（不能停在它上面）。不能拐弯，不能跳子。

**R5.4 工兵**：起点在铁路站时，可沿任意由铁路边组成、途经站全部为空的路径移动，拐弯次数不限；终点可以是路径能到的任何空铁路站，或与路径末端以铁路边相邻的对方子（碰子）。工兵的公路步与其他子相同。

**R5.5 一步只能二选一**：要么一个公路步，要么一次铁路移动；不能"先走一格公路再上铁路"。

**R5.6 目标站**：空站 → 移动；己方子 → 非法；对方子 → 碰子（若可攻击）；**对方在行营里的子不能被碰**（R6.1）。

**R5.7 大本营**：任何子进入任何大本营（包括对方空着的大本营）之后永远不能再动；大本营不是安全区，里面的子可以被碰。

**R5.8 来回走限制（防磨棋）**：同一方连续用**同一枚子**在**同两个站**之间来回，最多 4 次；第 5 次来回被禁止（该着法不出现在合法着法里）。实现：每方记录 `{pid, from, to, n}`；新着法若 `pid` 相同且 `from = 上次的 to`、`to = 上次的 from` 则 `n+1`，否则 `n = 1`；当 `n ≥ 4` 时，继续来回的那一步非法。翻子（翻翻棋）清零翻子方的记录。界面上：被禁止的目标站不亮；孩子点它时领航员说"来回走太多次了，换一步吧"。

### 3.6 碰子（R6）

**R6.1 可攻击**：目标是对方子，且不在行营里。翻翻棋另加：目标必须已翻开；目标若是军旗，其所属方的 3 颗地雷必须**全部**已经不在场（R8.3）。

**R6.2 判定**（攻方 A 碰守方 D）：

| 情况 | 结果 | 落子 |
|---|---|---|
| D 是军旗 | **夺旗**（`F`），攻方立即获胜（攻方是工兵、炸弹也一样） | A 进入该站 |
| A 或 D 是炸弹 | **同归**（`B`） | 两枚都下场，该站变空 |
| D 是地雷，A 是工兵 | **攻胜**（`A`） | 地雷下场，工兵进入 |
| D 是地雷，A 是其他子 | **守胜**（`D`） | A 下场，地雷留在原地 |
| 两个有军衔的子 | 等级大者胜；相等同归 | 攻胜：D 下场、A 进入；守胜：A 下场 |

地雷、军旗、大本营里的子永远不会成为攻方。全部 10×12 组合由 `test-core.mjs` 的矩阵测试覆盖。

**R6.3 碰子结束这一手**；碰子后安静步数清零。

**R6.4 吃子不连续**：一手只碰一次。

**R6.5 司令下场 → 亮军旗**：任何原因（被吃、同归、撞雷、被炸）使某方司令下场，该方军旗**立即**对对方公开：暗棋里军旗瓦片对对方翻成正面并保持；翻翻棋里若军旗还是暗的，立即自动翻开（不占手）；明棋里军旗上加一个"亮"徽记。双方司令同时同归时两面军旗同时亮出。暗棋的推理含义：这次碰子中下场的那枚对方子就是司令（R11）。

### 3.7 胜负与和棋（R7），每一手之后按顺序检查

1. **夺旗**：走子方获胜（`flag`）。
2. **无子可走**：轮到走的一方没有任何合法着法（翻翻棋：也没有可翻的暗子）→ 若另一方同样没有任何合法着法 → **和棋**（`both-immobile`）；否则轮到走的一方**负**（`no-moves`）。"没有合法着法"包括"能动的子都被堵死"和"只剩地雷、军旗、大本营里的子"。
3. **安静和棋**：安静步数达到上限 → 和棋（`quiet`）。上限：明棋、暗棋 **80**（每方 40 手不碰子）；翻翻棋 **40**（翻子也清零）。在第 70/32 步时回合条下出现一行提示"再过 10 步不交手就和棋"（不是倒计时动画，只是一行字）。
4. **步数上限**：600 手 → 和棋（`ply-cap`，安全网；自对弈 3 000 局中从未触发）。
5. **求和**（只在家庭对局）：任一方点"求和" → 另一方看到"要和棋吗？"→ 两人都点"同意"成立（`agreed`）。人机对局不能求和、不能认输；"离开"即存档，回来可续局。

### 3.8 三种玩法（R8）

**R8.1 明棋**：布阵完成后双方所有子正面朝上。人机明棋允许悔棋（退回到孩子上一手之前，包括 AI 的应手），次数不限，但结果卡会如实写"悔棋 N 次"；家庭明棋悔棋需对方点"同意"。

**R8.2 暗棋（电脑裁判）**：
- 双方只看得见自己的子；对方的子显示为背面（只看得到颜色和位置）。
- 碰子时，裁判只宣布结果：`进攻的赢了` / `防守的赢了` / `一起下场` / `扛到军旗了`，**不宣布任何一方的身份**。地雷、炸弹的特效只在"看的人自己的子"是地雷/炸弹时才播放（例如孩子的炸弹去碰 → 爆炸；对方的炸弹碰孩子的军长 → 只播"一起下场"的通用烟团）。人机对局以孩子的视角决定特效；家庭暗棋一律只播通用特效。
- 司令下场亮旗（R6.5）；比赛结束后全盘揭晓（复盘）。
- 不能悔棋（悔棋会泄露信息）。
- 参谋笔记（R11.2）是对方暗子上的推理角标，开关在菜单。

**R8.3 翻翻棋**：
- 不布阵。50 枚子用种子 `createRng('mc:fan:<matchId>')` 洗牌（Fisher–Yates，逐个取 `rng()`），背面朝上放满两边的 50 个非行营站（双方的子混在一起，大本营里也有）；10 个行营空着。
- 先手方第一手只能翻子；**翻开的是什么颜色，他就是那一方**，然后轮到另一方（另一种颜色）。修掉旧版"首翻后连走两步"的问题。
- 之后每一手：翻开任意一枚暗子（不论颜色），或走一枚己方已翻开的子。
- 暗子是障碍：不能碰，铁路上也挡路（对双方都一样）。
- 军旗锁：某方的军旗只有在该方 3 颗地雷**全部下场**之后才能被碰（不论地雷是否已翻开）。情报板一直显示"扛蓝旗还要挖 N 颗雷"。
- 大本营规则照旧（随机落进大本营的子不能动）。
- 司令下场：该方军旗自动翻开（R6.5）。
- 安静和棋上限 40（翻子、碰子都清零）。
- 翻翻棋没有悔棋。

### 3.9 谜题模式（R9，学堂棋盘题、残局、每日残局）

- 局面由题目数据给出（只放必要的子），红方先走；**红方必须走**，不能过。
- `blue_moves: "static"`：蓝方每一手都"原地不动"（教学简化，讲解里说"蓝方先不动"）。`"best"`：蓝方按 `blueBestReply` 应对：选让红方剩余最少步数**最大**的应手（红方已无法完成目标的应手最优先）；同分时保留更多蓝方子力；再同分时选真实着法而非不动；再同分时选 `from·60 + to` 最小者。页面与校验器调用同一个函数，保证孩子看到的应手就是求解器假设的应手。
- 红方的"无子可走"照常判负；`best` 题里红方走完一手后蓝方没有任何合法着法 → 按标准规则红方胜（`flag` 目标视为完成，结果卡写"对方没棋可走了"）；`static` 题不检查蓝方（蓝方本来就"不动"）。安静和棋、步数上限关闭。
- 目标类型：`capture`（指定蓝子全部下场）、`reach`（任一红子/指定红子停在目标站）、`flag`（夺蓝旗）、`survive`（走一手后，经蓝方任意应手，指定红子仍在场 / 红旗仍在）、`nomoves`（红方走完后蓝方无合法着法）、`order`/`compare`/`infer`/`deploy`（卡片题，§4.1）。
- 一次失败（被守住、被吃掉关键子、超过 `par + 4` 步仍未完成）→ 领航员说原因（`mc.why.*`），自动退一步到失败前一手，并把提示阶梯升一级（§5.1）。

### 3.10 回合与输入的完整性（R10，旧版缺陷的根治）

1. **输入锁**：`Match` 控制器只有一个 `lockDepth` 计数；AI 思考、任何走子/碰子动画、裁判揭晓、交接遮罩、弹窗期间 `lockDepth > 0`，棋盘忽略所有点击和拖拽（被忽略的点击记入 `deadTaps` 日志，不给反馈声）。只有"当前走子方是人"且 `lockDepth = 0` 时才接受输入。
2. **请求代号**：每次向 Worker 请求 AI 着法都带 `{matchId, ply}`；回来的结果若与当前 `matchId/ply` 不符一律丢弃。重新开始/离开时 `worker.terminate()` 并新建。
3. **计时器袋**：所有 `setTimeout`/动画 Promise 都登记在 `disposables`；重开、离开、页面隐藏时统一取消。
4. **一手提交即锁**：点击目标站的那一刻状态机进入 `ANIMATING`，同帧内的第二次点击被丢弃（80–450 ms 双击回归测试，§9.6）。
5. **首翻交回合**：翻翻棋首翻后 `turn = 另一种颜色`（R8.3）。
6. **AI 无着可走**：按 R7.2 判负，不会"永远在想"。
7. **输了不庆祝**：失败与和棋只用 `jingle-round-over`（柔和下行），没有纸屑、没有奖杯。

### 3.11 信息模型与推理（R11，暗棋）

**R11.1 每一方能看到的东西**：己方全部身份；对方每枚子的位置；对方每一手的起点、终点（从而知道它"走过"，以及是否"拐了弯"——起终点既不相邻、也不在同一条畅通的铁路直线上，只能是工兵，`needsEngineer()`）；每次碰子的结果；对方的亮旗。下场的对方子身份不会公开。

**R11.2 约束推理**（孩子的参谋笔记与 AI 的信念用同一个模块 `core/belief.ts`）。每枚对方子维护一个"可能身份集合"（12 位掩码），初值按布阵规则：不在大本营的不可能是军旗；开局不在后两排的不可能是地雷；开局在第一排的不可能是炸弹。事件更新：

| 事件 | 推出 | 参谋笔记角标 |
|---|---|---|
| 它走过 | 不是地雷、军旗 | 👣 小脚印 |
| 它一步拐了弯 | 是工兵 | "工" |
| 我的 r 级子碰它，我赢 | 比 r 小的军衔（我是工兵 → 它是地雷） | "<r"（工兵赢 → "雷"） |
| 我的 r 级子碰它，我输 | 比 r 大的军衔，或地雷（我是工兵 → 只能是更大的军衔） | ">r 或 雷" / ">1" |
| 我的 r 级子碰它，同归 | 等级 r，或炸弹 | "=r 或 炸" |
| 它碰我的 r 级子，它赢 | 比 r 大 | ">r" |
| 它碰我的 r 级子，同归 | 等级 r 或炸弹 | "=r 或 炸" |
| 它碰我的 r 级子，它输 | 比 r 小（不是炸弹） | "<r" |
| 它碰我的地雷：它赢 / 同归 / 它输 | 工兵 / 炸弹 / 工兵以外的军衔 | "工" / "炸" / ">1" |
| 我的炸弹参与的碰子 | 无信息 | — |
| 对方亮旗 | 军旗身份确定；这次碰子里下场的对方子是司令 | 旗标常亮 |

- 角标规则：集合只剩一种身份 → 显示该身份的字（"工""雷""旗"）；否则按表显示最强的那条约束；没有约束、也没走过 → 不显示。
- 情报板"确定下场"：下场的对方子若集合只剩一种身份，名单上划掉一枚该身份。
- 一致性：自对弈 300 局、每一手检查"所有约束都包含真实身份"，违规 0（§9.3）。
- **侦察便签**（孩子手动）：长按对方暗子 → 径向菜单 5 个便签：大官（≥7）、小兵（≤3）、炸弹、地雷、军旗；可改可撤。赛后揭晓时每张便签按真实身份打 ✓/✗，结果卡写"你猜对了 N 个暗子"（不扣分，只统计）。

### 3.12 实体棋裁判（S12）的判定

- 步骤：① 进攻方颜色（红/蓝两个大按钮，记住上次）→ ② 进攻方悄悄点自己的子（12 宫格，地雷、军旗灰掉不能点）→ 屏幕盖上"交给防守方"（长按 600 ms）→ ③ 防守方点自己的子 → ④ 领航员吹哨（`mc.whistle`）+ 鼓点揭晓（`mc.reveal`），大字显示"把**进攻方**的子拿下来"/"把**防守方**的子拿下来"/"两个子都拿下来"/"扛到军旗了，进攻方赢！"；若司令下场，加一行"**红方**司令下场了，亮出军旗吧"。**不显示任何一方的身份**。
- 判定函数就是 `resolve()`；12×12 全部组合单测。
- 只是辅助工具：不记录棋盘、不判胜负（夺旗除外），不进天梯；记入家庭战绩的"实体棋局数"（家长手动 +1）。

### 4.1 军棋学堂（8 课 36 题，规范数据 `content/lessons.json`）

**题型与交互**

| type | 画面 | 交互 | 判定 |
|---|---|---|---|

**生成算法**（`site/military-chess/tools/gen-endgames.mjs`，与原型同名脚本逐行对应）
1. 种子 `hashSeed("mc-endgame:<tier>:<seed>")` → mulberry32。

### 5.1 提示阶梯

**卡片题**：H1 点亮一个正确位置/正确按钮；H2 播放一次相关的 VS/规则小动画 + `mc.why.*`；H3 直接展示答案，再给孪生题。

**布阵题**：H1 选中的子可放的槽全部发绿光；H2 自动替他放好一枚；H3 自动完成，再请他交换任意两个子（交换后仍合法才过）。

**对局里的参谋（💡）**：只有两级，不自动走子。
- 一级"看这里"：若孩子的军旗下一手可被扛走（明棋/翻翻棋精确；暗棋按"对方任一能动的子一步能碰到军旗"），高亮威胁子与军旗；否则若存在"确定能赢的碰子"，高亮那个对方子；否则高亮 AI 推荐着法的那枚己方子。
- 二级"走这里"：画出推荐着法的箭头。推荐着法 = 以孩子的视角调用 3 档 AI（暗棋用孩子的信念做推测世界）。
- 每次使用记入 `match-end` 日志 `hints`；不影响胜负记录，不影响星级（对局没有星级）。

**参谋提醒（对局中主动弹出，可在菜单关；1–2 档对手默认开，3–4 档默认关；每局最多 3 次）**

| C2 | 明棋/翻翻棋：这一手走到的站会被对方一个确定更大的子（或炸弹）吃掉，且该子等级 ≥5，并且这一手没有吃到等值以上的子 | `mc.coach.hang` | 同上 |

### 5.2 失败处理

- **学堂与残局**：没有生命值、没有计时、没有"游戏结束"。失败（关键子下场、守旗失败、蓝方守住、超过 `par + 4` 步）→ 领航员用一句 `mc.why.*` 说明原因（并在棋盘上演示：例如被吃掉的子重新出现、VS 牌再翻一次）→ 自动退回失败前一手 → 提示阶梯升一级。`↶ 退一步`、`⟲ 重来` 一直可用。
- **同一题连续失败 2 次**：H2 按钮自动发光（不自动播放）。连续失败 4 次：领航员主动问"看我走一遍？"（H3，可以拒绝）。
- **对局失败**：结果卡用 `jingle-round-over`，没有纸屑、没有奖杯；标题"这局对方扛到了军旗"（或"我们没棋可走了"）；接着是战报（§5.6），然后三个按钮：再来一局 / 换个对手 / 回营地。连输 2 局，"换个对手"按钮上提示上一档；连输 3 局给让子（§4.4）。
- **界面上从不出现"错"字**；所有失败文案都是"发生了什么 + 为什么"（语气 lint 已检查 229 句台词）。

### 5.3 星级与掌握

| 内容 | 3★ | 2★ | 1★ | 解锁 |
|---|---|---|---|---|
| 学堂棋盘题、残局、每日残局 | 步数 ≤ par，且没用 H3 | 步数 ≤ par + 2，或用了 H3（孪生题） | 完成 | 每课：前一课 ≥(题数 − 1) 题 ≥1★；残局档：上一档 ≥6/8 题 ≥1★ |
| 卡片题 | 全部首次就对 | ≤2 处改正 | 完成 | 同上 |
| 布阵题 | 首次放置全部合法 | 有 ≤2 次被拦截 | 完成 | 同上 |

- 进度永远不卡在 3★ 上；不出现"再来一次拿 3 星"之类的文案。重做一题只在星数更高时更新记录。
- **掌握**（家长面板，不影响解锁）：某课的全部题目最近一次都是 ≥2★ 且没用 H2/H3 → 该概念"掌握"。天梯：某玩法某档最近 5 局得分率 ≥0.6 → "稳定战胜"。

## 6. 美术（商业品质，不用图像生成器）

### 6.1 风格总则

**"一副好木头军棋，放在星港演习场的桌上。"** 棋盘与棋子追求**实体棋的质感**（木框、印刷的绿色战场、黑白相间的铁路、漆面棋子、阴刻金字），界面外框与营地用设计系统的剪纸夜空。参照：Royal Match 的按钮与弹窗手感、Monument Valley 的安静层次、实体棋的"刻字漆片"。

- 操作区（棋盘）内没有任何装饰动画；所有动画都是反馈（选中、移动、碰子、揭晓）。
- 全部美术由代码绘制（SVG）或离线脚本程序化生成（木纹纹理），**无第三方图片素材、无表情符号字符**；许可台账只需登记"自制"条目。
- `prefers-reduced-motion`：所有位移动画降为 1 ms 直接切换，揭晓改为 150 ms 淡入；震屏关闭。
- 颜色语义沿用设计系统："还没成功"用琥珀（`--xg-try-*`）而不是红色；红色只用在红方棋子上。

### 6.3 棋盘（`view/board-svg.ts`，按当前布局一次性生成 SVG，缓存为 `<svg>` 元素，方向改变时重建）

1. **木框**：圆角矩形（r 18），三层：外沿 `--mc-wood-deep` → 斜面渐变 `--mc-wood-hi→--mc-wood`（宽 12）→ 内沿暗线 2 px；`<pattern>` 引用 `wood-512.webp` 平铺。
2. **战场**：两个半场矩形（`--mc-field`、`--mc-field-2`），叠设计系统 `grain-overlay.webp`（8%，multiply）；四周 3 px 内阴影营造"印刷纸面"。
3. **公路线**：按 133 条连线逐条画（斜线 2 px、虚线 4/4 以区别于直线）；每个站一个 6 px 圆点（行营、大本营除外）。
4. **铁路**：按 35 条铁路边画黑白相间粗线（`stroke-dasharray: 10 10` 黑线上再叠一条 7 px 的浅色虚线，偏移 10），拐角处画 1/4 圆弧使轨道连贯。
5. **行营**：圆（半径 = 0.34 × min(行距, 列距)），纸色底 + 双环 + 中心淡淡的"营"字（13 px，`--mc-wood-deep` 35%，装饰，不需要读）。
6. **大本营**：圆角矩形 0.82 × 0.74 格，按所属方着边框色，顶上一个小屋檐形（三角 + 横线），中心淡"本"字（装饰）。
7. **山界带**：深绿色带；b、d 两列位置各画一座水墨山（2 个三角山峰 + 1 条留白山脊，路径固定，宽 70）；a、c、e 三处画铁路桥（两道桥栏 + 枕木），桥两端与铁路相接。
8. **方位标识**（只在横屏）：红方一侧木框上烫金"红"小圆章，蓝方一侧"蓝"小圆章（形状不同：红为方章、蓝为圆章）。
9. **目标与高亮层**（单独的 `<g>`，在棋子层之下）：可走站圆环、可碰双剑、铁路路径预览（金色 5 px 圆头线，沿真实路径，出现 160 ms）、上一手箭头、参谋高亮（琥珀脉冲环 1.2 s 循环 2 次后停止）。

### 6.4 棋子（`view/pieces-svg.ts`：12 种 × 正/背 × 宽瓦/竖瓦 的 `<symbol>`，颜色走 CSS 变量）

- **形体**：宽瓦 92×50 / 竖瓦 52×88，圆角 9；**红方四角各切一个 4 px 小倒角（八角形轮廓），蓝方是标准圆角**——不靠颜色也能分清红蓝。漆面：主色线性渐变（上 `-hi` → 下 主色）+ 顶部 30% 高的高光带（白 22% → 0）+ 底边 3 px 暗沿（`-deep`，厚度感）。投影：偏移 (0, 3) 模糊 4 的 `--mc-felt-shadow`（用一个偏移的深色副本绘制，不用 SVG filter，A13 上更省）。
- **正面文字**：军衔名（2 字；"军旗""地雷""炸弹"同样 2 字），`--xg-font-ui` 600、24 px，阴刻效果（§6.2 `--mc-engrave` 三层文字）。宽瓦横排居中偏左，右端是等级数字；竖瓦竖排，底部是等级数字。
- **等级数字**：直径 20 的圆形徽，`--xg-font-num` 700、15 px，金色底 `--xg-gold-300` + 深色字；炸弹、地雷、军旗不显示数字，改显示 18 px 图标（§6.5）。家长面板可关掉数字（实体棋手感），关掉时图标仍保留。
- **背面**（暗棋、翻翻棋）：同形漆面，中心一枚压花徽：红方 = 带四个小角的方形印章纹，蓝方 = 同心圆纹（同样是形状区分），压花用上下 1 px 明暗线。
- **状态**：选中 → 上浮（y −6、投影放大）+ 金色 2 px 外框；亮旗 → 军旗瓦片常亮一圈金色细边；冻结（大本营里）→ 右下角小锁 12 px（只在孩子点它时出现 1.2 s）；参谋笔记角标 → 左上角 22×22 白底小签（"工""雷""<5"等，`--xg-font-num`）；侦察便签 → 右上角彩色小旗（5 色 5 形）。
- **翻翻棋**里双方暗子混在一起：背面徽记依然按真实颜色显示？**不**——翻翻棋的背面统一为中性木色（`--mc-wood`）+ 星港徽，不泄露颜色；暗棋的背面才按颜色显示（暗棋里颜色本来就公开）。

### 6.6 角色

- **裁判领航员**：设计系统伙伴机器人（`@kit/companion`），本游戏通过 `accessory` 钩子加：黑白条纹袖标 + 胸前银色哨子（SVG 覆盖层，跟随机身 bob）。表情只用设计系统的 7 种；判定揭晓时 `surprised`，孩子赢时 `celebrating`，孩子输时 `encouraging`（从不难过）。
- **4+1 位机器人对手**：用同一个参数化机器人（`mount(el, { shell, led, antenna, variant: 'head' })`）换外壳色和帽子：豆豆（草绿外壳 `#9bb36a`、小钢盔）、铁蛋（灰蓝外壳、斜戴贝雷帽）、雷达（深橄榄、大檐帽 + 天线换成雷达碟）、老将（深灰 + 金色饰边、大檐帽 + 麦穗）、钢铁司令（钢灰 + 金星帽）。帽子是 4 个 SVG 路径组（`view/hats.ts`，每个 ≤1.5 KB）。对手只在 S9 卡片、回合条小头像（40 px）和结果卡里出现；他们的气泡不配音，只有 `blip-*`。
- **小步步的肩章**（9 级，`view/insignia.ts`）：橄榄色肩章底 + 金边；工兵 = 铁锹，排/连/营 = 1/2/3 道金杠，团/旅/师/军 = 1/2/3/4 颗金星，司令 = 金色麦穗环绕一颗大星。**抽象设计，不复制任何真实军衔标志。**

### 8.3 状态机

**路由**：S0 → (S0b) → S1 ⇄ {S2→S3/S4, S9→S5→S6→S8, S10→S3, S11→S5/S6/S12, S13, S14, S15}。不进浏览器历史；🏠 在 S1 以外 = 返回上一层（先存档）。

**对局控制器**（`ctrl/match.ts`；纯 reducer + 副作用列表，副作用由 `screens/match.ts` 执行）

```
SETUP ──(明/暗)──> DEPLOY(side) ──(家庭暗棋)──> HANDOFF ──> DEPLOY(other) ──> HANDOFF ──> TURN_START
SETUP ──(翻)──> TURN_START
TURN_START: result? → END
            当前方是 AI → AI_THINK（lock+1，发 think{id=matchId:ply}）
            家庭暗棋 → HANDOFF（遮罩，长按放行）→ HUMAN_IDLE
            否则 → HUMAN_IDLE（lock = 0）
HUMAN_IDLE ──点己方能动子──> SELECTED（显示目的地）──点合法目的地──> COACH_CHECK
SELECTED ──点别处/同一子──> HUMAN_IDLE ；──点另一枚己方子──> SELECTED(新)
COACH_CHECK ──无提醒──> COMMIT ；──有提醒──> COACH_PROMPT ──还是走──> COMMIT ／──再想想──> HUMAN_IDLE
AI_THINK ──worker 'move'(id 匹配)──> COMMIT ；id 不匹配 → 丢弃
COMMIT: apply()（纯）→ 追加记谱 → 存档 → ANIMATE（lock+1）→ [REFEREE 揭晓] → lock−1 → TURN_START
END ──> 暗棋揭晓动画 → RESULT(S8)
```
- 任何状态下收到 `restart/leave`：`disposables.dispose()`、`aiClient.reset()`（terminate + 新建）、`lockDepth = 0`、状态回 SETUP 或离开。
- `pause`（页面隐藏）：动画立即跳到终点、存档；`resume`：若在 AI_THINK 且结果已到，从 COMMIT 继续。
- reducer 单测：80–450 ms 双击、AI 思考中点击、思考中重开、首翻后立刻点击、遮罩期间点击——都不能产生第二个 COMMIT。

**谜题控制器**：`READY → (RED_IDLE ⇄ SELECTED) → COMMIT → [BLUE_REPLY（static: 跳过；best: blueBestReply，380 ms 后播放）] → CHECK(goal|fail|continue) → DONE/FAIL(→ 讲解 → 退一步 → RED_IDLE)`。

### 8.4 渲染与输入

- 一个根容器：底层 `<svg>` 棋盘（静态，按方向生成并缓存）→ 高亮层 `<svg>` → 棋子层（50 个绝对定位 `<div class="mc-piece">`，内含 `<svg><use href="#mc-p-<side>-<type>-<shape>"/></svg>`，位置用 `transform: translate3d()`）→ 特效 canvas（kit particles，覆盖全屏，空闲时不跑 rAF）→ HUD/面板（HTML）。
- 动画全部用 WAAPI（`el.animate`），只动 `transform`/`opacity`；路径动画 = 按路径关键帧逐站 translate。**不跑常驻 rAF 循环**；只在有动画时由 WAAPI 驱动。
- 输入：`PrimaryPointer` 只认第一个手指；点选：`onTap(stationHit)`，站命中区 = 整个站距矩形（124×62 / 60×128）；拖拽：`makeDraggable` 按住棋子 >8 px 移动开始拖，松手吸附到最近的合法站（60 px 内），否则弹回；拖和点都有效。
- 方向切换（`onLayout`）：取消正在进行的拖拽，所有动画跳到终点，棋盘 SVG 重建，棋子按新坐标瞬移（无动画），状态不变。
- 存档时机：每次 COMMIT 后、离开前（`onBeforeLeave` ≤400 ms）、`pause` 时。

### 8.5 AI 设计（`ai/*`，跑在 Web Worker；原型 `ai.mjs` + `selfplay.mjs` 已验证可行）

**评估函数**（对走子方；终局 ±10 000 ∓ 步数）
- 子力值 `VAL = [旗 0, 雷 10, 炸 30, 工兵 14, 排 6, 连 9, 营 13, 团 18, 旅 25, 师 35, 军 50, 司令 70]`；工兵另加 `k·(对方剩余雷数)/(己方工兵数)`，k = 3（翻翻棋 8）；翻翻棋暗子按 0.8 倍计。
- 推进：能动子每在对方半场 +1.5。
- 扛旗牵引：能动子 +`flagPull/(1+d)`，d = 到对方军旗的连线距离（BFS，忽略阻挡）；翻翻棋里对方军旗被雷锁住或还没翻开时不牵引。
- 守旗危险：对每个己方军旗，Σ 对方能动子 `1/(d+1)²` × `flagGuard`（扣分）。
- 猎杀（明棋、翻翻棋，暗棋不用）：每个能动子对"它能确定吃掉的最近对方子"加 `hunt·(1+max(0, 子力领先)/40)/(1+d)`。
- 翻翻棋地雷：每颗已挖掉的对方地雷 +`minesFan`；对方地雷挖光 +3·`minesFan`（己方对称扣分）。
- 求和厌恶（只给 AI）：`−contempt·(quiet/quietLimit)²`。

**搜索**：negamax α-β；着法排序：夺旗 > 赢的碰子（按 MVV-LVA）> 同归 > 普通着法 > 输的碰子；叶子上做"只走碰子"的静态搜索（深度 `qdepth`）；迭代加深直到节点预算用完（返回最后一层完整结果）；置换表 2^16 项，Zobrist（两个 32 位，`core/zobrist.ts`）。

**暗棋（PIMC）**：从 `belief.sampleAssignment`（Kuhn 匹配可行性 + 布阵先验权重：地雷后排 ×1.4–2、炸弹第 2–3 排 ×1.6、大官在边路或前两排 ×1.4、未动的子当雷/旗 ×1.3）采样 `samples` 个"推测世界"，每个世界做完美信息搜索，按着法平均根分。

**翻翻棋**：翻子是机会节点：按剩余暗子多重集（含颜色）对每种可能身份求期望；2 档起考虑对手一手碰子应对；全部翻开之后改用明棋搜索，4 档在能动子 ≤10 时加深到 3 层。

**选着**：以 `randomMove` 概率随机走一个合法着法；否则对根分做 softmax（温度 `temp`）。AI 最少"思考" 450 ms 再走（显示用）。

**档位旋钮**（`ai/levels.ts` 的规范数值；原型校准结果见 §9.4，实现后必须重跑校准并允许 ±30% 内调参）

**Worker 协议**

```ts
// 主线程 → worker
{ t: 'think', id: string, mode, state: EncodedState, knowledge?: EncodedKnowledge, level: 1|2|3|4|5, side: Side, seed: string, budget: { nodes: number; ms: number } }
{ t: 'hint',  id: string, …同上，level 固定 3，side = 孩子 }
{ t: 'cancel', id: string }
// worker → 主线程
{ t: 'move', id, action: string /* 记谱 */, stats: { nodes, ms, samples, depth } }
{ t: 'error', id, message }
```
- `new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })`（写在 `ai/client.ts` 里）；预算：节点数为主（结果可复现），`ms` 为安全上限（到点返回已完成的最深一层）。默认预算：1 档 2 千、2 档 1 万、3 档 3 万、4 档 8 万、5 档 40 万节点；`ms` 上限 1 500（5 档 2 500）。
- `client.ts`：一个 Worker 常驻；超时 4 s 未回复 → terminate + 重建 + 用 1 档规则就地选一手（日志 `ai-timeout`，测试要求 0 次）。
